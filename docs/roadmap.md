## 1. 产品终局

一个自己掌控数据的钱包式个人财务工具：账本以**加密文件**躺在用户自己的网盘 / NAS 上，手机和电脑都能记账、都能看数，两端最终一致，没有账号、没有服务器、没有云厂商。

| # | 承诺 | 对架构的强制要求 |
|---|---|---|
| 1 | 数据在用户手上 | 任何时候能用标准工具读出全量账目；导出格式长期稳定，加密容器格式公开可解 |
| 2 | 密钥在用户手上 | 恢复码由系统生成（≥128 位熵）、用户抄写保管，不由用户自选；换设备只靠恢复码；泄露后可更换（重加密全部容器） |
| 3 | 两端数字一致 | 同步必须可重放验证 |
| 4 | 不依赖服务存活 | 离线优先；同步是后台增强，失败可见但绝不阻塞记账 |

**质量优先级**：数据不丢 > 数字可信 > 可解释 > 结构清晰 > 交互顺手 > 好看。上一层没收口，不开下一层。

**产品顺序**：地基可信 → 界面可用 → 同步契约 → 跨设备可用 → 自动同步 → 自动记账 → 第二语言。注意「产品顺序」不等于「实现顺序」：同步契约（纯 PC 工作）必须排在移动端之前，否则手机会先写出一套不兼容的数据。

## 2. 硬依赖（错了两端一起返工）

- **L1–L3 → H**：手机复用已重建的 feature 层与文案目录；目录未建就开 H，手机会一边写一边等前端结构。
- **F → H**：手机从第一天就按同一套同步契约（`rev` / `vv` / `deletedAt`）写。
- **容器格式与实体集合解耦**：周期交易、标签、多账本（K1–K3）决定可同步实体集合，但它们被推迟。每条记录自带 `entityType`，合并算法不认识具体实体类型；K 批落地是增量工作，不改容器格式。
- **同步先于自动记账**：自动记账产生的数据也必须能被同步。
- **V2/V3 → H-A、V4 → I-A**：spike 通过后再承诺对应主线。

## 4. 同步架构（长期不可动）

同步是三层，每层独立交付、独立验证：

| 层 | 负责什么 | 交付物 |
|---|---|---|
| 数据层 | 哪些实体可同步、每条记录带什么版本信息 | `rev` + 版本向量 `vv` + `deletedAt` 墓碑（已落地） |
| 传输层 | 字节怎么离开设备、怎么加密 | 加密容器 + 介质适配器（容器已落地，适配待 G-B） |
| 合并层 | 两份状态怎么合成一份 | 记录级合并，幂等、顺序无关（已落地） |

- **合并与传输解耦**：目录 / WebDAV / NAS / GitHub 只是搬字节的管道，合并逻辑不需要知道文件从哪来，到达顺序不影响结果。
- **用版本向量判定先后，不用时间戳**（设备时钟会骗人），也不用 `baseRev`（快照式同步拿不到它）。同 `id` 两条记录：vv 逐维可比 → 取后继；不可比 → 真并发，两版都进 `sync_conflicts` 且可见；vv 相同内容相同 → 幂等丢弃。解决冲突只写一条新记录，其 vv 逐维取最大，同时支配两个旧版本。
- **记录自带 `entityType`**：新增可同步实体 = 加一条类型标签 + 一种负载格式，不改容器结构、不改合并算法。未知 `entityType` 只跳过该条并警告，不丢弃整批；未知 `formatVersion` / 头部非法才整批拒绝。
- 密文出端：同步文件与备份文件中没有明文账务数据，密钥 / 恢复码不进入任何上传文件；明文只存在于设备本地 SQLite。备份与同步共用同一份加密容器实现。
- 格式细节见 [sync-container-format.md](sync-container-format.md)；落地规则见 [dev-guide.md](dev-guide.md) §3.3–3.4。

| 13 | `packages/domain` 唯一允许的第三方 runtime 依赖是 `xirr`（XIRR 求解）：依赖与类型声明归 Domain，封装在 `investment/` 内，不向外暴露第三方类型，API 不直接调用 | 更换收益率求解器时重议；除此之外 Domain 保持零外部依赖 |
| 14 | **转账金额语义统一**：`amount` = X、`fee` = f、`coupon` = c，`转出 = X + f`、`转入 = X + c`、`净变化 = c − f`；唯一依据在 `ledger/rules.ts` 的 `postingsOf`，余额 / 现金流 / 桑基按展示粒度消费。**导出坚持此语义，不随外部软件改字段含义**；外部导入在适配层归一：明确给 fee / coupon 就直接映射，只给转出与到账金额时结合本金字段或导入规则推断，无法确定则保留原始值并提示用户，**禁止用差额反推 fee 或 coupon**（差额也可能来自账单缺失、汇率、平台补贴）。内核口径固定，不设版本系统 | 不可推翻「内部模型统一表达经济事实、不随外部软件变」；复审触发：出现无法用 X/f/c 表达的经济事实 |

**已评估但不采用**（保留结论，避免反复讨论）：物化 `postings` 表、Fastify / tRPC / Drizzle 替换现有栈、TanStack Router / Table / React Hook Form、Biome、Turborepo、FSD / 六边形整体重构、游标分页、CRDT / 协同编辑引擎、自建同步服务器、厂商 API 直连作主同步通道、React Native / 全原生重写移动端。共同理由：收益尚未出现，迁移成本或复杂度大于收益；触发条件见上表与对应决策。

## 6. 明确不做（非目标）

自建服务器、账号体系、厂商托管的云同步；多人共享账本与实时协作；多币种与汇率；微服务 / 消息队列 / 独立数据库；容器化部署 / K8s / CI-CD 流水线；第三方账单抓取与 OCR；投资实时行情接入；为「将来可能」提前抽象（模型预留 ≠ UI 提前做）。
