# UI 设计与交互规范

> 本文是**界面视觉、交互与「未来报表」口径的唯一来源**：写新页面、改 token、判断某个交互该怎么表现、核对推演数字时看这里。
> 账务口径见 [requirements.md](requirements.md)，代码结构见 [architecture.md](architecture.md)，编码规则见 [dev-guide.md](dev-guide.md)，待办见 [roadmap.md](roadmap.md)。
> 本文只写**规则与理由**，不复述已完成的实现过程；历史在 git 里。文档与代码不一致时，先确认哪个是错的，当场改齐。

## 1. 信息架构

| 平台 | 导航 | 说明 |
|---|---|---|
| PC | 侧栏 5 项：总览 · 流水 · 报表 · 预算 · 设置 | 账户归属并入总览，不独立成页；≥768px 显示完整侧栏，768–1023px 收窄为 64px 图标轨 |
| 移动 | 底部 5 项 + 悬浮「＋」 | 账户从总览的账户入口进入设置；<768px 走独立组件树 |

- **设置 8 分区**（以 `features/settings/settingsModel.ts` 为准）：配置中心 3 项（账户分类 / 收支分类 / 现金流分类）+ 通用 5 项（外观主题 / 自动备份 / 列表显示 / 数据与备份 / 回收站）。投资资产类型配置已删除——后端无更新载体。
- **报表共享一个全局期间**，切换报表不改变期间；同类配置只有一个权威入口，报表页不内嵌配置弹窗，只保留跳转。
- **新功能放哪**：按「这笔钱/这个数字属于哪个象限」判断——Flow 流水、Stock 总览、Plan 预算、Insight 报表；跨页面复用的组件进 `features/shared`，不新建 `pages/`、`queries/`、`ui/`、`hooks/` 目录。
- 页面层级最多三层：页面 → 分区（SectionBlock）→ 卡片 / 设置行。禁止弹窗套弹窗。

## 2. 视觉

### 2.1 token 只有一个来源

| 类别 | 定义处 | 规则 |
|---|---|---|
| 结构（间距 / 字号 / 行高 / 圆角 / 尺寸 / z-index） | `styles/theme/variables.css` | 只用 `--mb-*`；引用即定义，CSS 引用未定义变量不报错、会静默回退 |
| 颜色 / 阴影 | `styles/theme/hf-theme.ts` 的 `cssVariablesResolver` | 随 Mantine colorScheme 注入 `:root`；业务 CSS/TSX 不得手写色值 |
| 主题状态 | Mantine `createTheme` + `localStorageColorSchemeManager` | `light / dark / auto` 三档，存储键 `moneybrain-theme-mode`；不自建 Context 或第二套 token 表 |

- `--mantine-*` 是库内部变量，业务代码不得覆盖；只用 Mantine 公开 API。`--ant-*` 已随 AntD 移除，引用数必须为 0。
- **字体单栈**：正文 / 标题 / 数字同族（`"Inter", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`），数字靠 `body` 的 `tabular-nums` 对齐；字号只取 `--mb-fs-0…6` 七档（最小 12px），字重只取 400 / 500 / 600。不写 `font-family` 字面量，不用 10/11px。
- **颜色只表达方向**：收入绿、支出红、转账蓝、退款青、平账灰；分类色只用于图标与图表，不用于金额文字。金额一律带单位、右对齐、千分位、负号统一。
- 一屏一个主数字（hero），其余降级；暗色不是反色，需单独校验对比度与图表色板。

### 2.2 颜色语义（改色前先看这几条）

1. **accent 双档**：`accent` 只用于文字 / 图标 / 链接 / focus 环；`accent-fill` 只用于填充面。亮色下所有 `accent-fill` 面统一 1px 描边 `#356B0C`（填充对页面仅 1.39，形状必须由描边定义），填充上文字用 `on-accent-fill` `#0D1005`，禁止默认白字。
2. **支出色是硬要求**：`expense` / `expense-display` 必须与 `+` / `−` 符号、右对齐金额列同时出现——亮色 deutan 下支出与收入绿 ΔE 仅 3.2，颜色本身不可分。支出禁用橙色 / 正红。
3. **danger 只给破坏性动作**（删除 / 清空 / 覆盖 / 退出未保存），且必须「图标 + 动词文案 + 二次确认」；普通错误用 `text-primary` + ⚠。
4. **投资页正负色 = 全局正绿负红**：盈利 `income`、亏损 `expense`，图例写「收入/支出」「盈利/亏损」，禁用「涨/跌」。
5. **主卡随主题切换层级**：浅色 = `surface-raised` + `border` + `sh-1`，暗色 = 高一档底色 + 1px `hero-line` 高光边；不做浅色深底反白卡。
6. **图表只走 1:1 viewBox**：宽度按容器实测写入，高度只由 `features/shared/chartLayout.ts` 的 `CHART_HEIGHT` 提供；禁 `preserveAspectRatio="none"`，`padL` 按最长刻度文字宽度推算。

### 2.3 进度条（面 / 字分离）

条面颜色独立于文字色，**提高彩度而不是压暗**；这些 token **只用于条面，不用于任何文字**。轨道独立为 `--mb-progress-track`（浅 `#A4A8A2` / 暗 `#4A5257`），条高 6px、圆角、无描边。

**验收口径**（旧的「填充对轨道固定 3:1」已作废）：

1. 填充对卡片底色 ≥4.0；
2. 填充对轨道 **≥1.6 明度比且 ΔE00 ≥20**；
3. 状态必须同时有**文字承载**（剩余 / 接近上限 / 已达上限 / 超支 / 还差 / 已达成 / 不计入预算），色条是冗余编码，不能是唯一信息源。

原因：3:1 是给「只能靠颜色理解」的图形用的；我们的状态有文字，卡 3:1 反而逼出反主题的深色。

| Token | 浅色 | 暗色 | 含义 |
|---|---|---|---|
| `--mb-progress-normal` | `#2E8A57` | `#3FA572` | 良好：支出仍在计划内 / 收入已达成（不设第二个绿） |
| `--mb-progress-neutral` | `#425B70` | `#8EA8BF` | 进行中：收入未达成 |
| `--mb-progress-warning` | `#C26600` | `#C9822F` | 接近上限（支出 80–100%） |
| `--mb-progress-over` | `#CA4D40` | `#C9615F` | 超支（支出 >100%） |
| `--mb-progress-track` | `#A4A8A2` | `#4A5257` | 轨道（装饰，不承担状态） |

- **绿只出现两处**：支出仍在计划内、收入已达成。**neutral 有两种用法**：收入进行中画钢色条并保留 100% 刻度；转账 / 不计入预算不渲染条、不渲染刻度缺口（整条只有轨道）。
- **超支表现（0–130% 刻度）**：轨道统一 `--mb-progress-track`；100% 预算位在 76.9231%，画一条 2px 与轨道同色的竖缺口；`percent > 100` 时条面连续跨过缺口。宽度取 `max(真实宽度, calc(76.9231% + 8px))`（8px = 2px 缺口 + 6px 红段），超过 130% 钳在右端。
- 文字规则回到文字体系：名称恒 `primary`，`normal` / `neutral` 状态文字 `secondary`，只有 `warning` / `over` 用语义色并带图标。

### 2.4 双端与断点

PC 与移动是**两套独立结构**，不是同一棵树的响应式缩放：桌面是「浏览与洞察」，移动是「单手快速录入」，信息密度、导航、主动作位置本就不同。

| 阈值 | 行为 |
|---|---|
| `< 768px` | 设备切换：移动组件树 + 底部导航；`DesignApp.tsx` 的 `(max-width: 767px)` 是唯一设备判定 |
| `768–1023px` | 侧栏由 236px 收窄为 **64px 图标轨**（`--mb-sidebar-w-rail`），不是收起、不是单栏降级 |
| `≥ 1024px` | 完整侧栏 236px + 多栏内容 |

- 设备判定只有一个常量 + 一个 hook；CSS 媒体查询阈值不得各写各的裸数字（CSS 自定义属性在 `@media` 条件中不生效，需构建期解析或由单一选择器切换）。
- **浮层宿主：一份内容，两处外壳**——PC 用居中对话框 / Drawer，移动用底部 Sheet；内容组件不判断平台，外壳由宿主注入。
- 移动端：表单一律底部 Sheet，保存按钮吸底并避让安全区；触控目标 ≥44×44、列表行高 ≥56；每屏只保留 1 个主图，其余折叠为数字；时间选择全站同一交互（底部抽屉 + 预设 chip）。

### 2.5 骨架原语

四个原语 + 一个允许关系：`PageShell > (Head, ControlRow?, SectionBlock*)`；`SectionBlock > (SectionTitle, Card*, SettingRow*)`；`SettingRow` 是唯一承载「label 在左、控件在右」的行原语。

| 原语 | 职责 | 关键数值 |
|---|---|---|
| `PageShell` | 页面三段（页头 / 控件行 / 内容）的存在与段间距 | 内容左右内距 28（移动 26）、上内距 28（移动 8）、底部留白 28（移动 116）、最大宽 1120；段间距 16 |
| `ControlRow` | 页面级控件唯一容身处，紧跟页头 | 时间器 / 分段控件 / 筛选器；**页级动作（新增、设置、导出）只能在 Head 右侧** |
| `SettingRow` | label 左、控件右 | 行高与对齐以组件实现为准；侧栏信息块复用 `stack` 变体 |
| `SectionBlock` | 分区标题 + 卡片 / 设置行 | 标题字号、间距、卡片内距以组件实现为准 |

页面根节点不得自写 `padding-top` / `max-width` / `gap`；页头内不得放时间选择器、筛选器、分段控件；禁止负 margin 把后续块顶上来。实现见 `features/shared/skeleton/`。

## 3. 交互

### 3.1 记账与流水

- **3 步内记完一笔**：类型默认上次使用、金额自动聚焦、分类最近优先、账户默认上次、日期默认今天；手续费 / 优惠券 / 不计收支折叠进「更多」。支持连续录入（保存后回到金额输入）。
- **撤销优先**：单条删除不弹确认，改为「已删除 · 撤销」；批量删除、清空、覆盖导入才二次确认，且写明对象与数量。
- **退款**只能从原交易发起，自动带出原账户 / 分类 / 可退余额；原交易显示「已退 ¥50 / ¥120」。**转账**转出 / 转入并排，手续费独立并说明「手续费计入支出」。
- 搜索匹配备注、分类、账户、金额；筛选与搜索叠加生效；无结果 ≠ 冷启动，给出可操作的清空条件。「本月」笔数不含未来，未来分组自证。
- 批量操作（改分类 / 删除）必须先看到选中笔数与影响范围，结果可撤销。
- **流水行两段式**：主行是分类名 + 备注，副行是**交易类型 · 账户**（转账为 源账户 → 目的账户）。移动端与 PC 用同一个 `TxRow` 组件，只换排版密度，不换信息内容——移动端同样显示类别。
- **流水分批渲染**：一次只渲染前若干个日期分组，PC 点「查看更多」继续加载，移动端滚动到底自动追加；合计与笔数始终按完整筛选结果算，不随已渲染的分组变化。

### 3.1.1 配置列表（设置页 · 账户分类 / 收支分类 / 现金流分类）

- 三个分区的行结构一致：手柄 + 图标 + 名称 + 计数 + 行尾 `⋯` 菜单。**排序一律拖拽**，不提供上移 / 下移按钮；手柄即拖拽入口。
- 行内操作统一走 `RowMenu`（编辑 / 移动到… / 删除），删除带二次确认；账户分组、账户、收支分类、现金流分类共用同一个菜单组件。
- 相同语义的按钮视觉一致：分区工具栏里的「新增 X」是 primary + 加号图标，空态里的「新增 X」是 primary + 加号图标，页面级页头动作（显示 / 新增）走共享的 `HfHeadAction`。
- **图标选择器独立成抽屉**：编辑抽屉只留当前图标与「选择图标」入口，完整网格（分组 + 搜索）在独立抽屉里展开，避免图标变多后编辑表单被挤出屏幕。

### 3.2 报表

- 统一时间条：`day / week / month / year` 四粒度，四张报表共享同一期间；切换视图不改变期间。
- **日期选择器按粒度分档**：日看日历网格、周看周列表、月看 12 个月、年看年份窗口；日期显示只到该粒度（月粒度不显示日），快速选择只提供该粒度支持的预设（不支持的不出现，而不是置灰）。
- 明细表两组 + 二级项可折叠，列可排序；**下钻从报表 → 明细 → 流水**，条件（账户 + 期间 + 分类）全程带上，笔数与金额同源。
- **对账差以角标说明**，不常驻整行对账条：`经营净额 不含修正 ¥2.40`、`合计 · 手续费 ¥2.00 不计`。差额必须为 0，见 [requirements.md](requirements.md) §3.6。
- 构成图「其余」与下钻同口径；现金流桑基**守恒优先于好看**，流入必须等于流出 + 净额。
- 收支表父子行：子级角标「†」；资产构成环跟随资产负债的「分组口径」。
- 报表设置**只针对当前这张报表**：打开即是它的展示配置（draft + 确认，落 localStorage）与它唯一依赖的分类管理入口——资产负债→账户分类、收支明细→收支分类、现金流→现金流分类、投资分析→投资账户。设置页与报表页的分类管理是同一份组件与 controller，保存立即写库，不另建表格或表单。
- 报表页自带设置入口（PC 页头按钮 / 移动页头图标），应用级设置在底部导航里，不在页头重复。

### 3.3 预算

- 三类预算互不混用：**支出 = 限额**（超支告警）、**收入 = 目标**（低于目标才是告警方向）、**转账 = 计划跟踪**（不计入告警，标「不计入预算」，进度条保持在轨道不填充）。三类混在一个百分比里会互相稀释，这句话常驻预算页。
- 头部徽标**按单项优先**判定：有单项超支 →「N 项超支」并置顶超支行；无超支但有接近上限 →「N 项接近上限」；都没有才显示总比例「按计划」。
- 总量用环形进度（PC 156px / 移动 108px），中心是百分比，下方「已用 ¥x / ¥y」；分类列表每行三段：名称 / 进度条 / `已用 / 限额`，超支行加标记。
- 使用率返回真实百分比，>100 不截断；进度条宽度可封顶但文本必须显示真实值。调整限额只在单一预算条目内做，超支必须给一个决定（改限额 / 改分类 / 忽略）。

### 3.4 数据、键盘与三态

- 覆盖导入固定三步（选文件 → 预览新增/更新/跳过 → 二次确认），覆盖范围要说清楚；**还原前先再存一个回滚点**。
- 失败要说人话（发生了什么 + 为什么 + 怎么办），三段式；Toast 只承载成功与可撤销动作，字段校验内联，可恢复失败用 `ErrorPanel` + 重试（金额显示 `—` 不显示 `0`），系统级失败用顶部横幅。
- 键盘：Tab 顺序符合视觉顺序、Esc 关闭浮层、关闭后焦点回到触发元素、`:focus-visible` 恒可见；纯键盘能走通主流程。
- 加载 / 空 / 错三态齐全且一致；空态要告诉用户下一步做什么，不用「暂无数据」打发。
- 可访问性：自定义可交互元素有可访问名称与角色，装饰图标 `aria-hidden`，对比度 AA，颜色不是唯一信号，`prefers-reduced-motion` 关闭非必要动画。

## 4. 未来报表（唯一口径）

### 4.1 范围与时间轴

未来区间只覆盖三个视图，且复用已发生区间的同一套组件：资产负债 → `BalanceView`、收支 → `FlowView`、现金流 → `CashView`；投资分析**不做未来版本**，显示空态 +「回到已发生」入口，时间条不禁用。已删除 `Future*View` 简化面板，不再恢复。

| 状态 | 判定 | 含义 |
|---|---|---|
| 已发生 `past` | `to <= asOf` | 只取历史报表 / 真实余额 |
| 混合 `mixed` | 起点在 `asOf` 前、终点在 `asOf` 后 | 桶内分段展示 |
| 全未来 `future` | `from > asOf` | 只展示预测数据源 |

`asOf` 在真实账本里是今天，种子模式用冻结锚点。四粒度同一套参数 `asOf / from / to / granularity`：day 上限 3 个月、week 6 个月、month 12 个月、year 3 年；不传窗口参数时默认「月粒度、从 `asOf` 所在自然月起连续 12 个月」；超限返回 400 与可操作文案。`fromMonth / months` 已删除，不恢复。

### 4.2 三来源与互斥

未来数字一律由后端合成，前端不写 `actual + planned + committed`：

| 来源 | 定义 |
|---|---|
| `actual` | `date <= asOf` 的真实交易余额；未来日期真实交易不计入起点 |
| `committed` | `asOf < date <= 窗口末` 的真实交易累计增量 |
| `planned` | 同窗口预算展开累计增量，只来自 `generatePredictedOccurrences`，已剔除被覆盖点位 |
| `total` | `actual + committed + planned` |

- `planned: null` 表示**没有预算来源**，不得用 `0` 冒充，界面显示「—」，分类行标「无预算」（`hasBudget=false`）。
- `covered[]` 只作解释：被真实交易覆盖的计划点位已从 `planned` 剔除、金额只留 `committed`，前端不二次抵扣。
- **同一 occurrence 互斥**：类型相同 + 来源账户相同 + 转入账户相同 + **分类相同** + 真实交易日期落在同一预算周期 `[periodStart, periodEnd]`；一对一配对、**同日优先**、金额不参与匹配。未被匹配的两侧都保留并在明细可见。匹配在 `projection-events.ts`，前端不做抵扣。
- 资产口径只做预算展开 + 已排定交易，不做统计外推、不推定投资收益。现金流 `endCash = startCash + net` 恒成立；现金账户互转本金不计流入/流出、手续费计流出。

### 4.3 端点

| 端点 | 参数 | 返回要点 |
|---|---|---|
| `GET /api/analytics/asset-projection` | `asOf + from/to + granularity`，`includePlanned` / `includeCommitted`（默认 true） | `base{assets,liabilities,netWorth}`；`points[].{actual,planned,committed,total,covered,accounts[],categories[]}` |
| `GET /api/reports/income-expense-projection` | 同上，另支持 `includeExcluded` | `income / expense / balance` 三来源、`incomeCategoryDetails / expenseCategoryDetails`（`actual/committed/planned(null)/total/hasBudget`）、`points[]`、`predictionNote` |
| `GET /api/reports/cash-flow-projection` | 同上 | 窗口级 `cashInflow / cashOutflow / netCashFlow`、`byActivity` 三来源 item、窗口级 `sankey` 默认返回、逐桶 `points[]` |
| `GET /api/budgets/period-plan` | 同上 | 只供预算页使用；报表未来收支**不再**消费 |

- 投资账户：任何真实或已排定现金流事件都进入余额，只是不推演市值涨跌（`valuationNote='transfer_schedule_only'`）；**不为「非 transfer 事件打到投资账户」加过滤开关**，分红记为收入进余额是正确行为。
- 转账按类型默认不计收支、无开关；普通收入/支出/退款继续由 `excludeFromIncomeExpense` 逐笔控制。不新增 `incomeExpenseSide` 三态字段、不做规则 v2、不改 CSV 列或 DB schema。
- 预测编码统一由 `features/reports/prediction.tsx` 产出：含预测的行常驻「预测」文字标记、指标构成文案「已发生 … · 按预算计划 … · 已排定 … · 合计 …」四个数字全来自后端；不新增颜色、不靠透明度编码。
- 验证：`apps/api/tests/integration/projection.route.test.ts`（26 条）、`projection-detail.route.test.ts`（5 条）、`apps/web/tests/unit/future-reports.test.tsx`（15 条）。
