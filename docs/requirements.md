# MoneyBrain 产品需求与账务口径

> 本文回答**做什么**与**口径是什么**——它是产品与账务语义的权威定义。
> 怎么实现见 [architecture.md](architecture.md)，怎么写代码见 [dev-guide.md](dev-guide.md)，接下来改什么见 [rewrite-blueprint.md](rewrite-blueprint.md)。

## 1. 定位

个人记账软件，本地 SQLite、单用户、无鉴权。**当前形态数据完全不出本机**；
终局形态是手机与电脑双端可用、两端通过用户自己的网盘 / NAS / GitHub 加密同步
（详见 [rewrite-blueprint.md](rewrite-blueprint.md) §0.1 与 §3.10）。

参考「钱迹」类产品的功能范围，但账务口径由本项目自行定义并严格遵守。

设计前提：**用户不懂代码，全部开发由 AI 完成**。因此产品必须自解释——空状态要能告诉用户下一步做什么，错误要说明原因和怎么办。

## 2. 功能范围

**必须有**

1. 资产与负债分类、账户管理（含期初余额与期初日期）。
2. 收入 / 支出 / 转账 / 退款 / 平账 五类交易记录。
3. 预算：按账户 + 分类 + 周期设定额度，查看已用与剩余。
4. 报表：资产负债表、收入支出表、现金流量表、投资分析表。
5. 统计分析：首页汇总、收支趋势、分类占比、净资产变化。
6. 投资：资产类型配置、持仓快照、收益分析（累计 / 年化 / 时间加权）。
7. 数据：CSV 导入导出、完整备份导出与恢复、按范围覆盖导入。
8. 外观：浅色 / 深色主题，桌面 / 平板 / 移动端响应式。

**明确不做**

- 多用户账号体系、厂商托管的云同步、实时协作。
- 多币种（模型预留，但 UI 只做单一货币）。
- 自动抓取账单、OCR 票据。
- 投资实时行情接入。

> 终局形态还要做手机端、跨端加密同步、多语言与通知自动记账——
> 这些是**路线问题**，见 [rewrite-blueprint.md](rewrite-blueprint.md) §5 里程碑。

## 3. 账务口径（权威定义）

### 3.1 五类交易

| 类型 | `amount` 含义 | `fee` / `coupon` | 方向 |
|---|---|---|---|
| `income` | 净收入 | 冗余展示 | 账户 +amount |
| `expense` | 净支出 | 冗余展示 | 账户 −amount |
| `transfer` | **本金** | 独立参与转出计算 | 转出 −(本金+fee−coupon)，转入 +本金 |
| `refund` | 实际退回 / 退出的现金 | 冗余展示 | 由原交易类型决定：支出退款 +amount，收入退款 −amount |
| `adjustment` | 余额增量 | 无 | 账户 +amount（不计入收支） |

规则：

- **手续费只从转出账户扣一次**，转入账户只加本金。`Δ转出 + Δ转入 == −fee`。
- **退款必须关联原交易**，金额不得超过剩余可退金额；方向由原交易决定，调用方不需要额外传「原类型」。
- **已有退款的交易不能改类型**：改类型会反转退款的冲减方向（收入退款 ↔ 支出退款），余额与报表会同时错。
- **平账**只影响余额，不进入收入/支出统计。
- **不计收支**（`excludeFromIncomeExpense`）：不影响余额，但不参与收入/支出统计。
- **金额语义现状**：转账的 `amount` 是本金、手续费独立参与计算；收入/支出/退款的 `amount` 是**净额**，
  手续费字段虽然存着但能从净额反推（冗余），不参与任何金额计算。
  目标（蓝图 A4）是统一成「本金 + 手续费」——**数字不变**，只是 `amount` 的含义变统一、手续费可单独统计。
- **口径带版本**：每笔交易记录 `ruleVersion`（写入时的账务口径版本）。
  解释历史数字时按交易自己的版本取规则，因此改一次口径不会改写历史报表；
  未知版本直接失败，不回退到当前规则。口径的权威定义在 `packages/domain/src/ledger/rules.vN.ts`。

### 3.2 日期与期间

- 交易只存日期（`YYYY-MM-DD`），不存时分秒。
- 期间一律半开 `[start, endExclusive)`；「本月」= `[月初, 次月月初)`。
- **期初余额 = 期初日期当天开始前**的余额，当天交易照常计入。
- 查询日期早于期初日期时，账户尚未存在，余额为 0。
- 日期是**用户本地日历日**：系统不做任何 UTC 转换，用户换时区后历史日期不得改变；「今天」由客户端本地日期提供，服务端不推断。

### 3.3 分类

- 账户分类：资产 / 负债，决定净资产归属；支持「现金等价物」「投资账户」标记。
- 收支分类：收入 / 支出，支撑预算与报表下钻。
- 现金流量分类（`cashFlowType`）：经营 / 投资 / 筹资，用于现金流量表归类。
- **未分类是合法状态**：没有分类的交易进入「未分类」桶，永远可见，不允许从合计里消失。

### 3.4 预算

- 预算 = 账户 + 分类 + 周期（每日 / 每周 / 每月 / 每季 / 每年）+ 额度。
- 用量 = 该预算范围内、该分类子树、该账户的支出，**退款自动冲减**。
- 预算自身生效期与当前周期取交集。
- 「查看流水」下钻必须带上账户 + 期间 + 分类，下钻结果条数与用量一致。

补充口径（此前未定义，导致线上与领域层给出不同答案）：

- **账户侧**：转账预算绑定「转出账户 + 转入账户」，统计**这一对账户之间**的转账；
  来自其它账户转入同一目标账户、或从同一转出账户转往其它目标的转账，都不计入。一次转账只计一次。
- **期间归属**：退款计入**退款发生的那一期**，不冲减原支出那一期。
  因此跨期退款会让某一期的用量为负——此时用量取 0（预算「已用」下限为 0），
  剩余不得大于预算额度，百分比不得为负。
- **金额不外溢**：退款冲减后剩余不超过额度，超支只体现在「超出 ¥x」。

### 3.5 报表口径

| 报表 | 口径 |
|---|---|
| 资产负债表 | 时点余额；资产 = 资产类账户余额合计，负债 = 负债类账户余额合计，净资产 = 两者之差 |
| 收入支出表 | 期间内净收入 / 净支出，退款按原类型冲减；含未分类节点；期初/期末净资产与资产变动必须自洽 |
| 现金流量表 | 只统计现金账户；按对手方分类的 `cashFlowType` 归入经营 / 投资 / 筹资；手续费单列；未分类单列一组 |
| 投资分析 | 快照链按日期推导；收益率分累计收益、XIRR 年化、TWR 时间加权三层；外部现金流单列，手续费不混入本金 |

### 3.6 净资产恒等式（对账条）

收入支出表必须常驻一条对账式，让「收支口径」与「余额口径」是否自洽**可见**：

```
期初净资产 + 净收入 − 净支出 + 其他 = 期末净资产
```

- **其他** = 不进收支统计、但会改变余额的部分：
  - 不计收支交易（`excludeFromIncomeExpense`）的净影响；
  - 转账手续费（只扣转出账户）；
  - 平账（`adjustment`）的净影响；
  - 减去**早于账户开户日**的交易净额（它们进收支统计，但不进余额）。
- 差额（期末 − 等式右边）必须为 0；不为 0 时前端要显式提示「数字对不上」并给出差额。
- `npm run db:verify` 用同一套规则离线复核整本账，输出不一致项。

### 3.7 导入导出

- **CSV 导入幂等**：同一文件重复导入 → 0 新增（用稳定业务键去重）。
- **覆盖导入**：先清空所选范围再写入，必须二次确认，且清空范围与导入范围一致。
- **导出保真**：金额、日期、`不计收支` 标记、调整方向、稳定 ID 都要往返一致。
- **口径版本随行往返**：CSV 带「口径版本」列，导入时按该版本解释这笔交易；
  旧文件没有这一列时按当前版本写入。导出的历史交易始终带原版本号，
  这样文件往返一次不会改变任何历史数字。
- **文件里的金额是元**（人读、可丢进 Excel）：固定 2 位小数，表头写明「金额（元）」；
  导入按字符串解析成整数分，超过 2 位小数直接报错，不静默舍入。
  程序内部（DB / API / 前端）一律用整数分，元只活在文件和输入框里。
- 时间格式固定为可机器解析的格式，不使用本地化字符串。

## 4. 设计原则

1. **金额是主角**：等宽数字、右对齐、千分位、负号统一；金额一律带单位，不出现裸数字。
2. **色彩只表达方向**：收入绿、支出红、转账蓝、退款青、平账灰；分类颜色只用于图标与图表，不用于金额文字。
3. **一屏一个主数字**：每页只有一个 hero 指标，其余降级。
4. **失败要说人话**：错误文案三段式——发生了什么 + 为什么 + 怎么办。绝不用「加载失败」四个字打发。
5. **未分类不是错误**：显示为「未分类」，不写成「未知」。
6. **数字可解释**：关键数字能点开看口径与原始流水（目标态）。
7. **暗色不是反色**：单独校验对比度与图表色板。
8. **日期语义显式**：「截至 2026-10-20」「2026 年 10 月」「期初（10-01 开始时）」，不用模糊说法做报表口径。

## 5. 信息架构（目标）

| 象限 | 页面 | 回答的问题 |
|---|---|---|
| Flow | 流水 | 钱最近怎么进出的？ |
| Stock | 资产 | 我现在有多少？分布在哪？ |
| Plan | 预算 | 接下来能花多少？ |
| Insight | 报表 | 这个月发生了什么？为什么？ |

- 桌面：侧栏（首页 · 流水 · 预算 · 报表 · 资产 · 设置）。
- 移动：底部 5 项 + 悬浮「＋」；「资产」由首页净资产卡片进入。
- 设置按 **账户 / 分类 / 投资 / 数据 / 外观** 分组；报表页不再内嵌配置弹窗，只保留跳转链接。
- 报表共享**一个全局期间**，切换报表不改变期间。

> 当前实现仍是 5 个平级页面（首页 / 交易 / 预算 / 报表 / 设置），改造顺序见 [rewrite-blueprint.md](rewrite-blueprint.md) 批次 C/D。

## 6. 关键交互

- **快速记账**：3 秒内记完一笔。类型默认上次使用、金额自动聚焦、分类最近优先、账户默认上次、日期默认今天；手续费/优惠券/不计收支折叠进「更多」。
- **撤销优先**：单条删除不弹确认，改为「已删除 · 撤销」；批量删除、清空、覆盖导入才二次确认，且要写明将删除的对象与数量。
- **退款**：只能从原交易发起；自动带出原账户、原分类与可退余额，金额默认剩余全额；原交易显示「已退 ¥50 / ¥120」。
- **转账**：转出/转入并排，手续费独立字段并说明「手续费计入支出」。
- **报表**：常驻对账条 `期初净资产 + 净收入 − 净支出 = 期末净资产`，不等时提示差异；每个分类可下钻到带相同条件的流水。
- **预算**：卡片显示已用/总额、进度、剩余与按当前速度的月末预测；超支显示「超出 ¥x（预计 ¥y）」。
- **导入导出**：导入前给预览（将新增/更新/跳过多少条）；覆盖前生成回滚点。

## 7. 反馈层级

| 场景 | 形式 |
|---|---|
| 成功 | Toast（可撤销时附「撤销」） |
| 表单校验 | 字段内联错误，不用 toast |
| 可恢复失败 | 页面内错误面板 + 重试（金额显示 `—`，不显示 `0`） |
| 系统级失败 | 顶部横幅（离线 / 后端不可达） |
| 破坏性操作 | 二次确认（需明确对象与数量） |

**禁止**：用 toast 承载需要用户决策的信息；用弹窗承载可以内联的提示。

## 8. 移动端与可访问性

- 表单一律底部 Sheet，不用全屏弹窗；保存按钮吸底并避让安全区。
- 触控目标 ≥ 44×44；列表行高 ≥ 56。
- 时间选择全站同一交互（底部抽屉 + 预设 chip）。
- 移动端每屏只保留 1 个主图，其余折叠为数字。
- 键盘可达：Tab 顺序、Esc 关闭、焦点回到触发元素。
- 对比度 AA；颜色不是唯一信号（收入/支出同时有符号与文字）。
- `prefers-reduced-motion` 关闭非必要动画。
