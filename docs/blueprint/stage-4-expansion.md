# 阶段 4 · 候选池（M7 及以后）

> **目标**：把已经长成的产品扩展到更多场景。这一阶段要么是明确推迟的，要么都有触发条件——
> 条件不出现就不开工。阶段 1 只留 K8，K1–K7 全部推迟到这里（理由见 [rewrite §2](../rewrite-blueprint.md)）。
> 本文件不是「第四个开发阶段」，而是**候选池**：没有排期承诺，只有触发条件与验收。
>
> 什么时候看：想加一个「以后再说」的新功能、判断是否该开工、或做同步/桌面 spike 时。触发条件未出现就不动手。

## 差距清单

### 批次 K · PC 产品补全（从阶段 1 推迟）

**这一批决定「PC 端可用」到底是什么**，原本排在移动端之前。现在推迟到阶段 4，
理由与代价见下。

| # | 现状 | 目标 | 验收 | 触发条件 |
|---|---|---|---|---|
| K1 | 只能手动记单笔 | 周期交易（房租、订阅、工资）：按规则自动生成待确认交易 | 按规则生成、生成前可预览、金额可变、生成后成为普通交易可编辑 | 用户抱怨「每月都要重录」 |
| K2 | 只有分类，没有标签 | 标签（多对多）：一笔交易可打多个标签 | 标签可增删改、筛选按标签、标签随同步传播 | 需要「一笔钱多个维度」的归类 |
| K3 | 无账本概念 | 多账本（个人 / 家庭 / 公司各一本），每本独立 | 账本可切换、独立统计、账本 ID 写入同步容器 | 出现「个人与公司的钱要分开」的需求 |
| K4 | 只能通过账户余额看数 | 目标储蓄（攒钱目标）：进度条 + 还需每月存多少 | 目标可设金额与期限；进度按分类支出自动算 | 用户在用其它工具记攒钱目标 |
| K5 | 无票据 | 交易可附票据图片（拍照或选图），压缩后随记录同步 | 票据可看可删；不计入金额；单图大小有上限 | 票据留存成为真实需求 |
| K6 | 只能整本备份 | 按范围备份/导出（账户、分类、交易、附件） | 范围导出后可单独恢复，不影响其它数据 | 大账本导出耗时变长 |
| K7 | 无「下期应付」概念 | 待付款清单（已承诺未支付），从周期交易派生 | 待付款可标记已付，标记后生成正式交易 | 随 K1 一起来 |

**为什么推迟**：理由见 [rewrite §2](../rewrite-blueprint.md)「界面先于新功能」与 §3「关键依赖」（F 与实体集合解耦）。
补充两点：① 新增功能无论复用还是新增组件，都要求现有组件统一；② 「PC 端可用」真正卡住用户的是界面不可信，
不是少了周期交易——K8 + 界面治理收益大于 K1–K7。代价是真实的：手机端同步的不再是一个功能完整的 PC 产品，由 F11 契约兜住。

**什么时候必须回来做**：K1/K2/K3 决定可同步实体的集合——动其中任意一条前，先确认同步契约的扩展方式（见批次 F 验收），否则容器格式与两端代码都要返工。

## 候选功能池（还没立项，触发条件出现才做）

这些是「可能需要、但现在没有明确需求」的功能，**不是承诺**，是备选池；技术方案已明确的见批次 J。

| # | 功能 | 价值假设 | 触发条件 |
|---|---|---|---|
| P1 | 共享账本（多人一本账） | 家庭共同记账 | 单人模式被明确抱怨；需要权限模型 |
| P2 | 银行流水自动导入 | 免去手工导入 | 用户抱怨导入麻烦；需要银行适配与凭证处理 |
| P3 | 多币种估值 | 海外账户 | 出现真实外币账户（语言需求不算） |
| P4 | 桌面小部件 / 快捷键 | 记账频次高的用户 | 记账被高频使用（每周 >20 笔） |
| P5 | 发票 OCR | 自动填金额 | 票据功能被高频使用 |
| P6 | 复式记账（可配科目表） | 专业会计需求 | 出现明确的专业用户 |
| P7 | 现金流预测 | 提前知道够不够花 | 预算与报表被高频使用 |
| P8 | 订阅制支出聚合 | 看清订阅总花费 | 周期交易被高频使用 |
| P9 | **用户层面对账**（拿银行流水核对账本差异） | 数字可信，不只是自洽 | 用户抱怨「余额和银行对不上」；需要银行流水导入 |
| P10 | **分账**（AA 记账，一笔支出拆给多人） | 聚餐、团建等场景 | 出现多用户诉求但暂不共享账本 |

**P1/P6/P3 会推翻大量现有设计**，真要做时应当重新评估而不是直接开工。

## 先验证的 spike

在承诺对应里程碑之前先做，失败就换方案；每个 spike 结束写结论进本文或 ADR，不保留演示代码。
编号用 `V`（验证），与候选功能池的 `P` 区分开。

| # | 问题 | 时间盒 | 通过标准 | 失败就 |
|---|---|---|---|---|
| V1 | 桌面一键启动（Tauri）能包住现有 Express + Prisma 吗？ | 1–2 天 | 双击启动、可选开机自启、数据目录可迁移 | 回退到「启动脚本 + 浏览器」 |
| V2 | Capacitor + 现有 Vite 构建 + 组件库（Mantine 8）布局在目标 Android 真机可用吗？ | 1–2 天 | 记账表单、列表、首页可操作；冷启动 <2s | 按屏幕引入移动控件/原生页，不改领域层 |
| V3 | 手机 WebView 里 SQLite 插件 + 共享领域层能跑通吗？ | 1–2 天 | 5k 笔查询 <100ms；事务写入可用 | 换 SQLite 插件或原生仓储适配器 |
| V4 | 目标机型能稳定读到支付通知吗？ | 1 天 | 允许列表内能拿到金额/商户；可去重 | 降级为「分享到 MoneyBrain」+ 手动记账 |
| V5 | 加密容器 + 版本向量合并 + 两实例目录同步能收敛吗？ | 2–3 天 | 两实例一致；乱序/重复/半文件都不出错；KDF <2s | 换 KDF 或重设计协议，先不上传输 |

**排期（不再是候选）**：`V5` 已完成（`F-C` 之后，结论见下）；`V1` **待做**（`R1` 已完成，V1 是 K8 前置）；
`V2`–`V4` 在阶段 3 的 H / I 批开工前做。每个 spike 结束写一段结论进本文或 ADR，不保留演示代码。

### V5 结论（2026-11-05）：可冻结

复现：`npm run spike:v5`（两实例写同一临时目录，产物用后即删）；快速参数用例在
`packages/sync/tests/spike-v5-directory-sync.test.ts`（随 `npm run test:sync` 执行）。

实测（本机，`t=3 / m=65536 / p=1 / dkLen=32`，默认参数）：

- 3 轮目录同步 + 一轮复读：两实例均为 6 条记录，`identical=true`；
- 乱序读取（第 2 轮反向）、重复读取（收尾两次复读命中 24 条幂等分支）结果不变；
- 同一 `entityId` 并发写入：两实例各检出 1 次冲突，生效版本逐字段一致；
- 截断 64 字节的「半文件」与非容器文件：两实例都拒绝且状态不变，后续轮次照常收敛；
- 耗时：`sealContainer` 8 次平均 1499.6 ms，`openContainer` 24 次平均 1430.1 ms（验收线 2000 ms）。

结论：容器格式与「全量快照 + 记录级合并」的目录同步模型**可冻结**，S0 阶段不做增量日志。
余量只有约 500 ms，且本机是桌面 Node；手机 WebView（V2/V3）必须复测同一参数，
若超标再按「失败就」换 KDF 参数或重设计，不提前改格式。

Spike 产物保留在仓库并标注：`scripts/spike-v5-directory-sync.mts`、上述测试文件。

## 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 低端 Android 上 WebView + 组件库（Mantine）卡顿 | 记账体验不可用 | V2 真机实测；按屏幕降级，不整体重写 |
| 通知权限被厂商 ROM 限制 / Play 审核拒绝 | 自动记账不可用 | V4 验证；保留手动与分享回退；sideload 备选 |
| 手机/平板访问不到「已同步目录」 | 同步不可用 | WebDAV / NAS 适配器；仍不行才做厂商 API |
| 用户丢失恢复码 | 数据永久不可解 | 强制抄写 + 新设备恢复演练 + 界面明确说明无找回 |
| 冲突处理把两个版本都入账 | 重复计钱 | 不变量 8 + 专项测试；同一 `entityId` 只应用一个版本 |
| 设备时钟偏差导致覆盖错版本 | 数字被静默改掉 | 用版本向量而非时间戳排序（决策 #25；不变量 10 保证合并结果） |
| 桌面与手机各写一套规则 | 数字分叉 | 共享 `app`/`domain`；跨端测试向量；合并后 `db:verify` 恒过 |
| 容器损坏（截断/半写/网盘改写） | 数据分叉或同步不可用 | **整包 AEAD**（tag 失败即拒绝整批）+ `formatVersion` 校验 + 临时文件原子改名 |
| 容器体积无界增长 | 同步变慢 | S0/S1 接受（个人规模几 MB）；>50MB 才做增量日志（S2） |
| 用户以为「端到端加密」连本地也加密 | 安全预期错误 | 威胁模型写进设置页；本地明文是明确边界 |
| Tauri 包不住 Express + Prisma | PC 端装不起来 | V1 先验证；失败回退到启动脚本 + 浏览器，不硬凑 |
| **K 批次一直推迟，手机端同步到半个产品** | 移动端价值打折 | 同步契约与实体集合解耦（批次 F 验收）；手机端只同步当期存在的实体 |

每个里程碑结束都要能回答四个问题：**这笔钱在 5 个视图里是否一致？断网还能不能记账？
两台设备冲突时会不会重复计钱？换一台空设备能不能恢复出同样的余额？**
