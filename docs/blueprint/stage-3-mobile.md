# 阶段 3 · 移动端（M4–M6）

> **目标**：让手机成为一个**真正能每天用**的记账工具——单手能记、断网能记、
> 通知能自动识别，且手机记的账最终能在电脑上看得到。
>
> 手机端「功能看起来少」是刻意的，不是缺陷。

## 前置

- 阶段 2 的批次 F 完成：同步契约先于移动端（见 [rewrite §3 关键依赖](../rewrite-blueprint.md)）。
- 阶段 1 的 UX3 平台差异规范完成（见 [stage-1](stage-1-experience.md)）。
- Spike 先行：**V2**（Capacitor + Mantine 8 真机布局）与 **V3**（WebView 内 SQLite + 共享领域层）
  在 H 批开工前完成；**V4**（目标机型通知可达）在 I 批开工前完成。失败即换方案，
  不把风险带进主线（见 [stage-4](stage-4-expansion.md)「先验证的 spike」）。

## 差距清单

### 批次 H · Android 移动端（先记账闭环）

| # | 覆盖 | 现状 → 目标 | 验收 |
|---|---|---|---|
| H-A | H1、H2、H4、H7 | 只有 Web、服务端依赖 Express/Prisma → Capacitor 壳 + 现有 Vite 构建 + SQLite 仓储 + 共享 `app` 用例；手机不跑 Express；从第一天写同一套同步契约（`rev`/`vv`/`deletedAt`） | 真机安装启动；桌面功能不回归；同一笔交易两端同一套校验与规则、数字一致；手机记录能被桌面合并；5k 笔下列表与首页可用（冷启动 <2s、滚动不卡，以真机为准） |
| H-B | H3、H5、E5 | 手机上记一笔要好几步、移动布局不统一 → 记账闭环（快速记一笔、列表、编辑、删除撤销、首页、预算）+ 底部 Sheet、数字键盘、安全区、44×44 触控 + 时间选择统一底部抽屉与预设 chip | 断网完整可用；3 步内记完一笔；单手可完成记账；所有时间入口手感一致 |
| H-C | H6 | 备份只在桌面 → 手机可导出/导入加密账本容器 | 手机容器能在桌面恢复；与桌面用同一格式 |

**H8（v1 不做）**：四张报表全量对等、投资快照编辑、批量导入——范围写死，避免移动端拖住主线。

### 批次 I · 通知自动记账（Android）

| # | 覆盖 | 现状 → 目标 | 验收 |
|---|---|---|---|
| I-A | I1、I2、I5、I6 | 无原生模块、无候选、通知文本敏感、无权限即不可用 → Kotlin `NotificationListenerService` + 权限引导；本地解析金额/商户/时间 + 候选收件箱；原文只在本地保留 ≤7 天、只同步解析字段；「分享到 MoneyBrain」与手动快速记账回退 | 目标机型稳定收到允许列表内通知；解析失败也进收件箱并显示原因；同步/备份/日志中无通知原文；无权限时记账闭环不受影响 |
| I-B | I3、I4 | 无去重、无入账边界 → `importKey` + 近邻匹配 + 人工确认；v1 不自动入账，学习规则默认关闭 | 同一笔通知不重复；与手动记录不重复；未确认的候选不影响余额与报表 |

## 验收基线

- 断网可记账；手机从第一天就写同一套同步契约。
- 同一笔交易在两端走同一套校验与规则，数字一致。
- 单手可完成记账；真机冷启动 <2s、列表滚动不卡。
- 手机可导出/导入加密账本容器，桌面能读。
- 通知候选可解析、可确认、可去重；失败可见；通知原文不出设备。
- 无通知权限时，手动与分享回退不受影响。
