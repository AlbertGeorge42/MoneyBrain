# 核心交互模型（UX2）

> 这份文档回答：**用户怎么操作这个产品**。
> 覆盖记账、搜索与筛选、交易详情与编辑、批量操作、报表浏览、预算、数据（导入/回滚/导出）七组交互，
> 外加键盘、三态、触屏三条通用约束。
> 段三实现时按本文档落地；原型见 [prototype/index.html](prototype/index.html)。
> 双端承载差异见 [platform-design.md](platform-design.md)。

---

## 1. 记账：为什么不该是通用表单

通用的 CRUD 表单是：选账户 → 选分类 → 填金额 → 填备注 → 保存，
手续费/优惠券常驻可见。问题不在字段本身，而在**它假设每次记账都是一次独立任务**。

实际场景是**连续、成组、有状态**的：
今天中午记了午餐，下午又记了咖啡，同一个账户、同一个分类、几乎同一个金额。
让人每次都重新选一遍账户和分类，是把系统的结构复杂度转嫁给用户。

记账交互因此按三条原则重做：

1. **金额是唯一焦点** —— 打开即聚焦金额，输入即唯一大字。
   其余字段全部是「确认或跳过」的角色。
2. **重复项可省略** —— 账户与分类记住上次，默认已选，不用每次确认。
3. **不中断** —— 保存后可以直接记下一笔，不回到列表再打开。

## 2. 记账流程

### 2.1 常规路径：3 步

```text
打开（N / FAB / 侧栏按钮）
  ↓  焦点已在金额输入框
输金额
  ↓  ⏎
选分类（点分类格，或按 1–9）
  ↓  ⏎
保存并再记（表单保持在打开状态，只清金额）
```

**3 步内完成**的验收口径与 E2 一致。

- 账户**默认选中上次用的账户**，不再需要选。
- 分类默认选中上次用的分类——但分类格始终可见且高亮，按 1–9 可直接改。
- 手续费 / 优惠券 / 日期 / 备注**折叠进「更多」**，默认收起。常规路径零干扰（承接 E2）。

### 2.2 连续录入

保存后表单**不关闭**：清空金额，保留账户与分类，焦点回到金额框。
用户可以连续敲 10 笔而不用重新打开表单。

「已连记 N 笔」常驻在弹层顶部，给出连续性的反馈。

### 2.3 放弃与保存的撤销语义

- <kbd>Esc</kbd> 或点击遮罩 → 放弃当前这笔，弹层关闭；**不提供撤销**——
  放弃的是一份还没落账的草稿，没有可恢复的账本记录。
- **保存后 6 秒内提供撤销**：toast「已保存 · 账面已同步」+ **撤销**按钮，
  点撤销即删除刚写入的那条记录并回滚余额（复用记录级 6 秒撤销机制）。
- 删除 / 批量删除的 toast 同样提供撤销，把交易放回原位置。

> 撤销是**操作的一部分**，不是补救措施。toast 必须 `position: fixed` 贴在视口内
> （PC 贴底居中、移动端贴视口底部安全区），不随页面滚动漂走。
> 渲染位置是 **body 级 portal**（宿主带 `.mb-hf-portal` token 作用域）：预览画布 /
> 手机框的 `transform` 会成为 fixed 的包含块，留在子树里会退化为相对祖先定位
> （实测滚动 400px 后 top 从 760 变 360）。验收：滚动任意距离后 toast 相对视口
> 的 `top` 不变（实测 843 → 843，Δ0）。
> 撤销按钮必须有文字标签，不能只用图标。

### 2.4 账户切换

账户是**常驻单行横向 chips**（两端同构）：最近使用 + 当前选中（前 5 个），
点击即切换、不展开面板——切换前后抽屉高度 / 滚动状态零变化（第十轮）。
行尾「全部账户 ›」打开**固定高度二级抽屉**（搜索 + 按分类分组 + 内部滚动，
选完回原位置；第十一轮分级兜底，账户多时外层不变）。
选中的账户成为新的「上次」。

转账类型额外提供「转入账户」一行 chips，与「转出账户」各自独立选择。

### 2.5 退款分类：能选到原支出分类

退款仍按**收入**计（增加账户余额），但分类维度要保留：分类格列出通用
「退款」+ 全部支出根分类（与支出分类同一套，最多 9 格、`1–9` 编号仍可用）。
选中某个支出分类表示这笔退款冲减该类别，报表「收入构成」按该分类归集，
只是不改退款按收入计的口径；不选支出分类时落在通用「退款」。

## 3. 搜索与筛选（承接 E3）

### 3.1 搜索匹配什么

搜索框的占位符写「搜索备注、账户、分类…」——**它就必须匹配这些**。
匹配的是**用户看得见的文本**，不是内部 ID：

| 匹配 | 示例 |
|---|---|
| 备注 | 「山姆」→ 命中「山姆会员商店」 |
| 账户**名称** | 「招商」→ 命中招商储蓄卡下的交易 |
| 分类**名称** | 「餐饮」→ 命中餐饮分类 |
| 类型 | 「收入」 |
| 金额 | 「328.6」 |

> 曾经按账户 ID（如 `cmb`）匹配，用户永远搜不出来——这是接口泄漏到界面的典型错误。

### 3.2 筛选与搜索叠加

类型筛选（全部 / 支出 / 收入 / 转账 / 退款 / 调整）与搜索框**同时生效**，
取交集。「全部」是「未设类型筛选」的状态，不是永远高亮的装饰。

**高级筛选**（账户 / 分类 / 金额区间 / 日期区间）与前两者同样叠加，
但承载方式分端：PC 是工具栏下方的**内联面板**（高密度工作流不必来回弹层），
移动端是**底部抽屉**（与时间选择同一手势）。

生效后的条件必须在列表上方**显式可见**：chip 显示条件本身（可读文字，不是
「筛选(2)」这种数字），每条可单独清除，另有「清除条件」清全部。
「重置」= 恢复未筛选态（清高级筛选条件与类型筛选——第十六轮起类型筛选在
移动端也并入筛选面板，同一面板里的条件一起重置才符合直觉）。

**筛选状态写进 URL query**（键：`txQ / txType / txAccount / txCategory /
txRoots / txFrom / txTo / txAmin / txAmax`，只覆盖本页键，保留预览壳的
`page / device / state`）：从报表下钻跳到流水、再返回总览／报表，重新进入流水时
条件原样还原、chip 仍在。无法还原的条件（分类已删、日期非法等）不得静默清空：
页面顶部提示「部分筛选条件未能还原：…」，其余合法条件照常生效。

### 3.3 无结果 ≠ 冷启动

两种「空」必须区分：

| 场景 | 文案 | 动作 |
|---|---|---|
| 库里真的没有数据 | 「从第一笔开始」+ 三步引导清单 | 建账户 → 记第一笔 → 看报表 |
| 有数据但没匹配上 | 「没有匹配的记录」 | **清空筛选** |

把第二种显示成第一种，是最常见的空态错误：用户搜了个不存在的词，
系统却告诉他「账本是空白的」，他会把账本误当成空的。

### 3.4 笔数口径：本月不含未来，未来分组自证

页头「共 N 笔」、页脚「共 N 笔」、筛选结果与无障碍播报**统一用本月口径**
（`date > 今天` 的未来记录不计入），N 在各处必须相等。

未来记录**不进本月合计，也不再加附注句**：列表末尾的「未来」分组（带年份）
自身已表达归属，笔数与合计按本月口径直接可读，不得把未来金额静默并入合计。
分组头右侧直接并列「N 笔 · 小计 −¥x」，用数字自证该组不在本月合计内
（页头 / 页脚仍是本月口径的 13 笔，未来组单独 1 笔，两处可对上）。
总览「本月支出 / 结余」与流水同口径，同样排除未来记录。

批量条「已选 N 笔」是**操作集合口径**（实际选中行数，含未来记录），
不参与本月合计；选中数即删除 / 改分类的作用范围，不再加「含未来 M 笔」后缀。

## 3A. 交易详情与编辑

流水行的详情（PC 右侧面板 / 移动底部抽屉）按**读 → 改 → 删**三段排列：

```text
金额大字 + 分类图标 + 账户 · 日期   ← 一眼读完
─────────────────────────────
日期 / 分类 / 账户 / 类型 / 手续费 / 备注   ← 键值列表
─────────────────────────────
[编辑]                      [删除]
```

编辑态复用同一个浮层，内容换成表单（金额 / 分类 / 账户 / 日期 / 备注），
底部换成「取消 / 保存」。转账多一项「转入账户」。

编辑中的值写在**草稿**里（不直接改交易），点保存才写回；点取消或关闭
浮层即丢弃草稿。改账户或改金额会影响余额，保存时要先回滚旧影响再按新值重算。

**金额输入容错**：解析前统一归一化——全角数字 / 小数点 / 负号转半角，
剥离 `¥` / `￥` / `$`、千分位逗号与前后空白（`¥1,234.56` → `1234.56`，
`１２３４` → `1234`）；失焦后按千分位格式化显示；解析失败时字段标红。
**错误态保存按钮禁用**，但必须给出可执行的出口：负数支出 →「改为退款」一次点击
同时切类型并把金额转正（−28 → +28），字段不再报红、保存立即可用；
不存在「字段有错但主按钮还能点」的状态。

**支出不能靠负数表达方向**：支出金额改为 ≤ 0 时，错误文案同时给出出口
「金额需大于 0。退款请改用退款类型，冲正请用调整」，并在错误块内提供
「改为退款」「改为调整」两个快捷切换（切换后自动选中对应类型的分类），
不允许只报一句「需大于 0」把用户困住。

删除在浮层底部，但删除后 toast 提供**撤销**，把交易放回原位置并回滚余额。

## 3B. 设置：被引用分类的删除

分类行上的引用数**含子分类交易**（行 meta「N 笔 · M 个子分类」与删除弹窗
使用同一个计数），不得出现「行上 2 笔、弹窗 1 笔」的双口径。

- 有子分类时删除项置灰，并显示可见说明「有子分类，先处理子分类」。
- 有交易引用、无子分类时，删除弹窗直接提供「把这 N 笔转到…」分类选择器
  （同类型、排除自身子树）；选目标后一步完成「转移 + 删除」，toast 报告
  转移笔数与目标分类，并提供 **6 秒撤销**（与批量删除一致）：撤销恢复原分类
  对象与每笔流水的原分类归属，而不是只恢复分类名。
- 无引用、无子分类时保留二次确认删除。

## 4. 批量操作

- 流水页「批量」（PC 工具栏）/「批量」（移动端搜索框下方的筛选操作区）进入批量模式。
- 进入后每行左侧出现复选框（真按钮，`role="checkbox"`，带 `aria-checked`）。
- 底部浮出操作条：「已选 N 笔」+ 改分类 + 删除 + 退出。
  操作条在 PC 挂视口、在移动端**挂机身内**——飘在手机壳外会压住底栏。
- **批量改分类仅支持单一收支方向**：混选时「改分类」置灰，但必须**指出异类**——
  操作条列出「已排除：工资（收入）、账户互转」这类具体记录与原因，
  并提供「仅选支出」快捷筛选，而不是只给一句概括理由。
- **删除有明确确认**，确认文案含数量。
- <kbd>Esc</kbd> 退出批量模式。
- 批量删除后 toast 提供**撤销**，一次恢复全部。
- **PC 批量条固定高度 56px**，文案变长不得顶高：计数 + **单行摘要**（`white-space: nowrap` + 省略号），
  异类超过两项折叠成「+N」。类别名与类型名重复时只留一次（`退款（退款）`→`退款`、
  `账户互转（转账）`→`账户互转`）。
- **移动端 390 宽用两行**：第一行是「已选 N 笔 + 排除项 / 禁用原因」的可见文字，
  第二行是动作（混选时含「仅选支出」，与改分类 / 删除 / 退出四颗等分；三颗主按钮一律
  44px 高）。排除原因**不得只挂在 `title` 或 sr-only**——触屏没有 hover，等于不可达。
  批量条挂机身内、底栏之上，不随列表滚动；两行高度仍不压列表末行（滚动内距 ≥ 批量条高 + 底栏）。
- **PC 流水底部槽位（自下而上）**：合计条（38px，`bottom:0`）→ 批量条（56px，距合计条
  6px）→ 撤销 toast（再上 16px）；侧栏「记一笔」固定在左下 805–843 区，横向不与三者
  重叠。四者同时出现时实测两两相交面积为 0。

**批量改分类只改分类**：金额、账户、日期不动，因为「批量」的价值在于
一次性纠正归集口径（报表分组与预算占用），不是批量改账。改完提示改了
几笔、是什么分类，并逐笔仍可在流水里撤销。

## 5. 报表浏览

### 5.1 统一时间条

四个报表视图共用同一条时间条（结构固定，两端同构）：

```text
‹   2026 年 10 月  ▾   ›        [日][月][年]
```

- **‹ › 逐期步进**：按当前粒度 ± 1 桶（日 ± 1 天 / 月 ± 1 月 / 年 ± 1 年），即改即生效、
  不打开面板；时点语义（资产负债）步进后仍锚月末 / 年末。
- **▾ 任意跳转**：点标签弹面板（PC 浮层 / 移动抽屉，同一渲染函数）——预设 chips
  （不兼容者置灰）+ 日历 + 取消 / 应用；日历只展示「当前粒度及以下」的层级
  （年 = 年步进 + 年网格、月 = 年步进 + 月网格、日 = 年步进 + 月网格 + 日网格）。
- **粒度切换在时间条上**（第十五轮维度 9「粒度归属」）：分段常驻、即改即生效，
  不打开面板；按新粒度重锚定当前值，失效预设吸附一次并 toast。
  四张报表（含资产负债）都支持全部三档粒度——资产负债是**点时态**（快照），
  粒度 = 锚点精度（月 = 该月末、年 = 该年 12-31）。

时间状态**切报表保持**（C1 语义，评审轮）：从一个报表切到另一个，已选期间
原样带过去——用户通常是在「同一时段」下对照看几张报表，各自记时间会把
对照打断。

**三个 tab 共用同一套期间措辞**（由时间条统一渲染，不在各 tab 里各写一套）：

- 期间（收支 / 现金流）：「2026 年 10 月 · 截至 10-28」；
- 时点（资产负债）：「2026 年 10 月 · 截至 10-28」并另注「月末估值」；
- **时点不得晚于数据截止日 `asOf`**：选月末锚点（10-31）时按 `asOf`（10-28）截断，
  界面不出现晚于数据截止日的估值日。

### 5.2 一致的骨架

```text
时间条 → 指标 → 图 → 明细表
```

四视图都是这个骨架，只是内容不同。这样用户学会一次，四处都能用。

- **指标**：**1 个主指标 + 3 个数字**（指标条 1+3，第一轮定稿）——
  主指标更宽更大，其余三格平铺。洞察型第五格已随 Q7「一句话结论移除」删除：
  结论是模板拼接，信息量与指标重复且容易过期，改由「指标 + 表格 + 表尾合计」自己读出来。
  表达形式按端分：PC 是**一条指标带**（单一容器 + 发丝分隔线）；
  移动端是**卡片**（主指标占满行，其余 2×2）。
- **图表**：主图（趋势）+ 副图（构成），PC 端横跨整行全宽。
  副图在 PC 用两侧各自标尺的横条（收入构成 / 支出构成），
  在窄屏只画支出构成（收入侧只有两类，完整数字在明细表里）。
- **明细表**：父行是一级分类，`└` 缩进是二级类别，与分类树同构。

### 5.3 明细表：两组表 + 二级项可折叠

四张报表的明细表都是**两组表**，每组一张：

| 报表 | 表一 | 表二 | 移动端分段按钮 |
|---|---|---|---|
| 收支 | 收入表 | 支出表 | 收入 / 支出 |
| 现金流 | 流入表 | 流出表 | 流入 / 流出 |
| 资产负债 | 资产表 | 负债与权益 | 资产 / 负债与权益 |
| 投资分析 | 持仓明细（单表，含二级持仓） | — | 无（只有一张表） |

PC 端两组**并排**（对照是核心动作）。所有**报表数据表**（并排表与普通单表）统一遵守以下规则（HF 与 R2b 表格原语的验收依据）：

1. **行高固定**：所有报表数据表单行高度 = `--mb-tbl-row-h`（见 [design-tokens §5](design-tokens.md)），不因内容多被拉伸；超长内容在单元格内截断，但不改变行高。
2. **合计行底部对齐**：两表并排时，`<tfoot>` 合计行必须落在同一水平线，这是唯一对齐锚点；不得用「等高拉伸」把行拉长来凑高度。
3. **短侧静默占位**：行数少的一侧用空白占位行补齐到同侧行数；占位区**无斑马纹、无边框、无 hover**，不得被误读为空数据行。
4. **列宽按语义**：表格用 `table-layout: fixed`，列宽由 `colgroup` 按权重折算（首列名称 / 分类最宽，日期、中列、数字列依次收窄；权重见 [design-tokens §5](design-tokens.md)），使 `ellipsis` 真正生效。禁止每张表各写一套固定 px 列宽。
5. **超长内容展开**：**悬停 tooltip 显示全文 + 点击行进入详情**（行语义沿用所在页面：报表行=下钻，审计行=详情/编辑）；**不做行内展开**——行内展开会重新撑高行，与固定行高冲突。可访问性要求：tooltip 须能被键盘聚焦触发（截断单元格进入 tab 序列，非截断单元格不进入）；tooltip 默认在单元格上方展开，**不得遮挡同表 `<tfoot>` 合计行**。
6. **流水列表不再表格化（HF 修复定稿）**：~~PC 流水行固定 `--mb-tbl-row-h`，列宽按「分类 2.0 / 备注 1.9 / 账户 1.8 / 金额 1.1」折算；流水表允许保留表头，账户列单行显示「账户 · 类型」~~ **已作废**。原型流水是 **54px 两段式行**：主行「26px 分类图标 + 分类名 `primary/600` + `·` + 备注 `primary/600`」，副行「账户 · 类型」（12px `tertiary`），转账行金额下方补「→ 转入账户」12px `tertiary` 子行，行尾右对齐金额，行间 `1px dashed border`，**无表头**。表格化（4 列 + 表头 + 29px 单行）与原型结构不同，观感无法一致，因此撤回 `--mb-tbl-row-h` 对流水列表的约束——29px 只约束报表数据表（见 [design-tokens §5](design-tokens.md)）；总览最近交易同样改用 54px 两段式行（见下一条）。
7. **总览最近交易与流水同源（推翻上一轮的表格保留）**：总览的「最近交易」不再使用 4 列表格 + 表头 + 29px 行，改为与流水页共用 `features/shared/TxRow` 的两段式行——主行「图标 + 分类名 `primary/600` · 备注 `primary/600`」、副行「账户 · 类型 `tertiary/12px`」，无表头，行高 `--mb-tx-row-h`（54px）、图标 26px、内边距 `8px 12px`、行间 `1px dashed` 全部同源；两页差异只允许通过组件 props（如 `showNote` / `showAccount`）表达，不得各写一套行样式。`--mb-tbl-row-h`（29px）退回只约束报表数据表，不再约束总览最近交易。

**合计收进各表表尾**（`<tfoot>` 合计行，第三轮定稿）：数值右对齐、用底色与上边框区分合计语义。
卡片底部的跨栏**对照条已删除**（第三轮）：指标条已给结余、表尾已给合计，
对照条是第三处冗余。
移动端**分段按钮 一次只显示一张表**（窄屏并排读不了，上下堆叠又太长）。

**二级子项可折叠**：

- 父行左侧有折叠箭头（`aria-expanded` 标注状态），点击只收起该父项的子行。
- **父行的合计金额始终可见** —— 折叠的是明细，不是数字。
- 折叠状态按「报表:表名:父项」存放，切换报表互不干扰。
- 全局「展开全部 / 折叠全部」控件不设——折叠是逐项的阅读动作，
  常态读表不需要批量开关（原型现状）。

### 5.4 可排序的表

投资分析的表头可点，按市值 / 成本 / 收益 / 收益率排序，再次点击反向。
表头带 `↑` `↓` 指示当前排序。

### 5.5 下钻：报表 → 明细 → 流水

点分类行（父行）打开下钻浮层（PC 右侧面板 / 移动底部抽屉）：

```text
本期支出                     −314.00
─────────────────────────────
二级类别
  └ 外出就餐                 −258.00
  └ 公司食堂                  −56.00
─────────────────────────────
相关流水 · 近 2 笔
  2026-10-28 · 午餐·公司食堂   −28.00
  2026-10-18 · 周末火锅        −286.00
─────────────────────────────
[关闭]              [在流水中查看]
```

- **下钻只展开当期口径**。完整流水与原始交易在「流水」页，不在浮层里重复一遍。
- **金额符号按交易方向**，不按数值正负——支出 28 元是 −28，收入 28 元是 +28。
- **没有对应流水就不给出口**：持仓明细来自净值快照，与收支流水不是同一口径，
  所以持仓下钻不提供「在流水中查看」（给一个假的出口比不给更糟）。
- 「在流水中查看」跳到流水页并**带上筛选条件**：分类（或合并「其他」的多个根分类）
  与当前期间写入 URL（见 §3.2），回到列表顶部，条件以可单独清除的 chip 显式可见
  （移除分类或期间后立即重算），不再只弹一句占位文案。

### 5.6 三处口径对账（现金流 vs 收支明细）

现金流与收支明细的「本月支出 / 结余」按各自定义计算，差异必须在报表内可见，
不得让用户自己猜。当前口径（待用户拍板后可调整，改口径须先改本节）：

| 项 | 收支明细 | 现金流 |
|---|---|---|
| 支出 | 支出 + 负向调整（对账修正算支出） | 流出只含支出 + 转账，**不含调整** |
| 结余 / 经营净额 | 收入 − 支出 | 流入 − 流出，**不扣转账手续费** |
| 转账手续费 | 不计入支出 | 不计入流出，单独列出 |

口径差异由计算层保证（差异 = 经营净额 − 收支结余，金额可直接对上）。
界面不显示「口径与对账」区块或段落（2026-11-05 文案精简），但差异必须有一个
**紧贴数字的极短角标**，不得让用户自己猜：

- 「经营净额」标签后缀 `不含修正 ¥2.40`（tertiary 小字，不新增行）——这就是两个数的差额来源；
- 「流出」表说明位写 `合计 ¥12,501.70 · 手续费 ¥2.00 不计`（挂在已有说明位，不新增块）。

### 5.7 构成图「其他」与下钻同口径

构成图超过 6 个一级分类时，尾部合并为**「其余 N 类」**（不叫「其他」，避免与根分类
「其他 ¥2.40」重名被读成同一桶）。**合并行与下钻使用同一组根分类**，
点进下钻的金额与被点的那一行完全一致；卡片行不列构成说明，不做「卡片合并 5 类、
下钻只算 1 类」的两套聚合。
**每一行都是可点按钮**（含「其余 N 类」行），点击即以该行节点打开下钻；
验收：点「其余 3 类 ¥54.90」进入的下钻合计必须是 −¥54.90。

两侧柱长**各自以本侧最大值为满格**，不可跨侧比较：每侧标题后缀标 `满格 ¥x`
（tertiary 小字），替代原「两侧各自标尺 · 按一级分类」整句。

### 5.7a 收支表父子行：子级角标「†」

父级金额已含其子分类，展开后可见行相加会大于表尾合计（差 = 所有子级之和）。
**不改结构、不恢复表下说明**：子级行在分类名后挂「†」，含义写在已有合计说明位
（`合计 ¥x · † 子级已计入父级`），不新增行。父级行不加标记，折叠与展开都不改变合计。
1024 下四列表首列仅 101px（子级再让 48px 缩进），五字标记会把分类名挤成 0 宽，
故用单字角标 + 图例，不把全句塞进行内。

## 6. 预算

### 6.1 三类预算（评审轮拍板）

预算条目支持**支出 / 收入 / 转账**三类，各自语义互不混用：
**支出 = 限额**（超支告警，环形与「超支条目」提示只统计支出类）；
**收入 = 目标**（达成率，低于目标才是告警方向）；**转账 = 计划跟踪**（只记录流量，
不计入预算告警；行内标「不计入预算」，进度条保持在轨道、不填充）。
预算条目 = 名称 + 类型 + 金额 + 周期 + 分类 + 账户（不再是「每个分类一个月度额度」）。
三类混在一个百分比里会互相稀释、告警失去含义——这句话常驻在预算页
（预算类型说明），用户第一次看到「转账不占超支」时一定会怀疑自己理解错了。

### 6.2 布局：先看总量，再看分类

头部徽标**按单项优先**判定，不与「需要关注」列表打架：

- 有单项超支 → 「N 项超支」（语义色 + 警示图标），并把超支行置顶；
- 无超支但有接近上限 → 「N 项接近上限」；
- 两者都没有 → 才显示总比例判断「按计划」。

```text
PC                                   移动
┌──────────────────────────┐         ┌──────────────┐
│ 预算   2026 年 10 月     │         │ 预算  10月 ＋新增│
├──────────────────────────┤         ├──────────────┤
│   ◕ 78%                  │         │   环形进度    │
│   总预算 / 已使用 / 剩余 │         │     78%      │
│   ⚠ 购物已超支 ¥128.60   │         │  已用 ¥… / ¥… │
├──────────────────────────┤         ├──────────────┤
│  餐饮  ▓▓▓▓▓░░ 814/1500 │         │ 分类进度列表  │
│  居住  ▓▓▓▓▓▓▓ 5600/5600 │         │  居住 …       │
│  购物  ▓▓▓▓▓▓▓▓ 928/800  │         │  购物 … 超支  │
└──────────────────────────┘         └──────────────┘
```

- **总量用环形进度**（PC 直径大、移动端 108px）：一眼看出「这个月还剩多少」。
- 环形中心是**百分比**，下方是「已用 ¥x / ¥y」——百分比用于快读，金额用于决策。
- **分类列表**每行三段：名称 / 进度条 / `已用 / 限额`，超支行加「超支」标记。
- **条面与文字解耦**（用户拍板）：「文字这套颜色不适合作为进度条」——填充不再引用
  `accent` / `expense` 等文字色，改用填充专用 token `--mb-progress-normal / -warning /
  -over / -achieved`（降饱和压暗，对轨道 ≥3:1，见 design-tokens §2.6）；条高 **6px**、
  圆角、**无描边**，轨道取 `--mb-color-border-strong`。
- **文字回到文字体系**：分类名恒为 `primary`；`normal`（含 `achieved`、`neutral`）行的
  百分比与状态文字用 `secondary`；只有 `warning` / `over` 行的状态文字用语义色并带
  `TriangleAlert` 图标。不再让整列百分比一片绿黄红。
- **超支必须看得见**：轨道按 **0–130% 刻度**铺满，100% 预算位在 **76.92%**，右侧 30%
  为溢出区（track 末端一段 `surface-sunken`）。`percent > 100` 时 0–100 段照常填充，
  **第二段由 100% 处向右长出**（`--mb-progress-over`）。因此恰好 100% 的行停在预算刻度，
  超支行越过刻度进入溢出区——两者一眼可分。溢出段超过 30% 时钳在轨道右端，溢出量由
  行内百分比与「超支 ¥x」文字继续表达。
- **100% 口径按类型区分**：支出类满格 = `warning`「已达上限」（如居住 5,600/5,600）；
  转账类不参与预算告警，即使占用 100% 也不显示满格绿，只显示中性「不计入预算」，
  轨道可见、无填充。
- 总量卡上常驻一条**超支提示**：写明哪个分类超了多少（`购物已超支 ¥128.60`），
  而不是只把那一行标红。超支是需要在总量层面被看见的事件。

### 6.3 调整限额：只在单一预算条目内做

点击某个预算条目 → **条目详情面板**（PC 右侧抽屉 / 移动底部抽屉）：

```text
预算    餐饮 · 支出预算
──────────────────────────────
已用 286.00 / 1,500.00    ▓▓░░░░░░
类型 支出 · 周期 每月 · 分类 餐饮 · 账户 不限
──────────────────────────────
调整该条目额度      [ 1500 ]  [保存]
未超支，剩余 ¥1,214.00
──────────────────────────────
该分类流水（…）
[删除条目]
```

- **不设「调整所有预算条目」的统一入口**（第十七轮移除 PC 页头「调整预算」与移动页头
  「调整」）：全局调整表把「改哪一条」和「改多少」拆成两步，三类预算的语义差异
  在批量表里也看不出来。
- 每行只有**该条目**的三段：分类名 / 已用 / 限额输入；已用只读，改限额时立刻能算出剩余。
- 输入值写在草稿（`budOne`），点「保存」写回；关闭面板即丢弃。
- 保存后**面板保持打开**，进度条与反馈文字按新额度就地重算——反馈按类型分：
  支出「未超支，剩余 / 已超支」、收入「距目标还差 / 已达成」、转账「不计入预算」。
  双端输入框与保存键移动端均为 44px 触控高。
- 面板里的进度条与列表/总览预算卡共用同一组件（6px、无描边、0–130% 刻度、超支第二段），
  不另写一套。

### 6.4 超支必须给一个决定

超支行不是一句提醒，而是**一个待决事项**。条目详情面板里，超支的支出类条目下方
出现一个决定区，给三个出口：

| 出口 | 动作 | 语义 |
|---|---|---|
| **按实际调整** | 限额直接提到已用值 | 「就这样，我认了」 |
| **维持限额** | 不改限额，本期仍标记超支 | 「这是已知告警，别再提醒我」 |
| **查看流水** | 跳到流水页并按该分类筛选 | 「我先看看钱花在哪」 |

三条都必须是显式动作，不能靠「什么都不做」默认处理——默认选项会把用户的
真实意图（没看见 / 看见了接受 / 还没想）压成同一种结果。

「维持限额」要回一句明确的话（`维持原限额 —— 本期仍标记为超支，作为已知告警`），
让用户知道自己选了什么，而不是点了没反应。

### 6.5 生效时机

**调整立即按新额度重算该条目的用量与超支反馈（第十七轮改写，取代原「下一期生效」）。**

理由：条目内调整是「这一条现在改」，反馈必须当场可见——保存后面板不关，
进度条、剩余/超支、收入达成、转账阈值四种反馈就地更新。预算是判断基线，
不追溯已发生的交易金额；若真实实现需要「下期生效」，应在条目面板显示**生效期字段**，
而不是静默延后并让反馈与输入值矛盾。本轮原型即改即生效。

## 7. 数据：覆盖导入、回滚与导出

入口在**设置 → 数据**。这一组是低频但高风险的操作，布局原则是：
**每一步都可回看，每一步都先说清楚影响范围**。

### 7.1 覆盖导入：固定三步

```text
1 选择文件  →  2 预览  →  3 建回滚点  →  完成
```

向导是**三步固定流程**，不是可跳步的自由表单：

| 步 | 内容 | 关键约束 |
|---|---|---|
| 1 选择文件 | 拖放区 + 「选择文件」按钮；说明支持 CSV 与 OFX、列顺序与中文表头自动识别 | 进入时就讲清「导入是覆盖式的」 |
| 2 预览 | 解析结果表（日期 / 分类 / 备注 / 账户 / 金额），只展示前 5 行 | 同时给出**覆盖范围**与新增/覆盖笔数 |
| 3 建回滚点 | 清单式确认（回滚点 / 覆盖范围 / 保留项） | 「确认覆盖导入」是唯一主动作 |

- 第 2 步的预览表**必须标明是预览**（`仅预览前 5 行`），不能让人误以为这就是全部。
- 第 2 步要给数字：识别到多少笔、其中多少覆盖现有流水、多少是新增、
  覆盖哪个月份（`识别到 96 笔将覆盖 2026 年 10 月的现有流水，32 笔为新增；其余月份不受影响`）。
- 第 3 步是**清单而非表单**——只列「回滚点 / 覆盖范围 / 保留」，让用户核对而不是填写。
- 底部主动作文案必须带「覆盖」二字（`确认覆盖导入`），不能是笼统的「确定」。

### 7.2 覆盖范围要说清楚

导入只覆盖**文件声明的期间**；其余月份、账户余额、预算与设置**全部保留**。

这条在第 1 步、第 2 步、第 3 步各说一次（文案不同、事实相同）：
覆盖式操作最怕用户以为「全量替换」，所以影响范围要在**每一步**都露出来，
而不是只在最后一步才补充说明。

### 7.3 回滚点：还原前先再存一个

- 导入完成时**自动创建**一个回滚点，toast 明确告知（`导入完成 · 已创建回滚点`）。
- 回滚点列表在「设置 → 数据 → 回滚点」，每条含时间、类型（自动 / 手动）、大小。
- **还原前自动再存一个回滚点**——还原本身也是一次数据变更，
  必须同样可撤回。确认文案要写明这一点（`当前状态会先自动存为新回滚点`）。
- 还原是**全量**的：交易、账户余额与预算一起回到该时点。说明文字要写全，
  否则用户会以为只回滚流水。

### 7.4 导出

CSV 全量导出，格式长期稳定（下游脚本依赖它）。
导出是只读操作，不走向导，一个按钮 + 一次 toast 即可。

- 打开记账 → 焦点进入弹层的金额输入框。
- 弹层内 <kbd>Tab</kbd> 循环，不跑到弹层外。
- 关闭弹层 → **焦点回到打开它的那个元素**。记账是「随手翻开」的动作，
  关闭后焦点必须回到来处。

## 9. 三态

加载 / 空 / 错误三态在**每个**页面都存在，且表达统一（UX5b）：

| 态 | 表达 |
|---|---|
| 加载 | Skeleton（不用裸文本「加载中...」）；`role="status"` + `aria-busy`，屏幕阅读器读「正在加载数据…」 |
| 空 | 图标 + 标题 + 说明 + 引导动作（区分冷启动与无结果，§3.3） |
| 错误 | `role="alert"` + 说明「数据没取出来」+ 重试按钮 + 错误码 |

错误文案必须说明**数据是否安全**：「本地数据库响应超时。你的数据没有丢失——
这是展示层的问题。」——这一句是信任的载体。

- **页面级三态优先**：组件级 `loading` 可自吞，`error` 必须冒泡到页面级；
  单报表错误只替换报表区域，不整页失败。

## 10. 触屏

- 可点击元素 ≥ **44×44**（U6）。
- 主要动作（记账 FAB）落在拇指可达区：底部导航正中。
- 触屏上 `:hover` 永不触发，因此**不能把唯一入口藏在 hover 里**——
  行内操作按钮在触屏设备上常驻显示。

**44px 的落点**（不是「所有东西都 44px」，而是「容易点错的必须是 44px」）：

| 元素 | 处理 |
|---|---|
| 行内操作（编辑 / 删除） | 移动端**常驻**在行尾，触控目标 ≥ 44×44 |
| 批量复选框 | 移动端常驻在行首，与行内操作对称 |
| 流水行整行 | 行高不必到 44px，但点击区（整行）不得小于 44px |
| 图表 / 表格里的次要数据点 | 不作 44px 要求——它们不是主操作 |

**常驻不等于变挤**：移动端行内操作常驻后，行内留白靠**收紧图标间距**解决，
不靠缩小图标。若行内操作与金额数字产生竞争，优先把操作收到行尾一列，
不把金额缩小——金额是这一行最该被读到的信息。
