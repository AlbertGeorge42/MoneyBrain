# 核心交互模型（UX2）

> 这份文档回答：**用户怎么操作这个产品**。
> 覆盖记账、搜索与筛选、交易详情与编辑、批量操作、报表浏览、预算、数据（导入/回滚/导出）七组交互，
> 外加键盘、三态、触屏三条通用约束。
> 段三实现时按本文档落地；原型见 [prototype/index.html](prototype/index.html)。
> 双端承载差异见 [platform-design.md](platform-design.md)。

---

## 1. 记账：为什么不该是通用表单

通用的 CRUD 表单是：选账户 → 选分类 → 填金额 → 填备注 → 保存，
手续费/优惠券常驻可见。问题不在字段本身，而在**它假设每次记账都是一次独立任务**。

实际场景是**连续、成组、有状态**的：
今天中午记了午餐，下午又记了咖啡，同一个账户、同一个分类、几乎同一个金额。
让人每次都重新选一遍账户和分类，是把系统的结构复杂度转嫁给用户。

记账交互因此按三条原则重做：

1. **金额是唯一焦点** —— 打开即聚焦金额，输入即唯一大字。
   其余字段全部是「确认或跳过」的角色。
2. **重复项可省略** —— 账户与分类记住上次，默认已选，不用每次确认。
3. **不中断** —— 保存后可以直接记下一笔，不回到列表再打开。

## 2. 记账流程

### 2.1 常规路径：3 步

```text
打开（N / FAB / 侧栏按钮）
  ↓  焦点已在金额输入框
输金额
  ↓  ⏎
选分类（点分类格，或按 1–9）
  ↓  ⏎
保存并再记（表单保持在打开状态，只清金额）
```

**3 步内完成**的验收口径与 E2 一致。

- 账户**默认选中上次用的账户**，不再需要选。
- 分类默认选中上次用的分类——但分类格始终可见且高亮，按 1–9 可直接改。
- 手续费 / 优惠券 / 日期 / 备注**折叠进「更多」**，默认收起。常规路径零干扰（承接 E2）。

### 2.2 连续录入

保存后表单**不关闭**：清空金额，保留账户与分类，焦点回到金额框。
用户可以连续敲 10 笔而不用重新打开表单。

「已连记 N 笔」常驻在弹层顶部，给出连续性的反馈。

### 2.3 退出手势可撤销

- <kbd>Esc</kbd> 或点击遮罩 → 放弃当前这笔，弹层关闭。
- 立刻弹出 toast「已放弃这笔（¥xx）」+ **撤销** 按钮。
- 点撤销 → 弹层重新打开，**金额原样恢复**。

删除同理：删除后 toast 提供撤销，把交易放回原位置。
批量删除同样可撤销。

> 撤销是**操作的一部分**，不是补救措施。因此 toast 必须停留足够长（原型取 4.2 秒），
> 且撤销按钮要有明确的文字标签，不能只用图标。

### 2.4 账户切换

账户是**常驻单行横向 chips**（两端同构）：最近使用 + 当前选中（前 5 个），
点击即切换、不展开面板——切换前后抽屉高度 / 滚动状态零变化（第十轮）。
行尾「全部账户 ›」打开**固定高度二级抽屉**（搜索 + 按分类分组 + 内部滚动，
选完回原位置；第十一轮分级兜底，账户多时外层不变）。
选中的账户成为新的「上次」。

转账类型额外提供「转入账户」一行 chips，与「转出账户」各自独立选择。

## 3. 搜索与筛选（承接 E3）

### 3.1 搜索匹配什么

搜索框的占位符写「搜索备注、账户、分类…」——**它就必须匹配这些**。
匹配的是**用户看得见的文本**，不是内部 ID：

| 匹配 | 示例 |
|---|---|
| 备注 | 「山姆」→ 命中「山姆会员商店」 |
| 账户**名称** | 「招商」→ 命中招商储蓄卡下的交易 |
| 分类**名称** | 「餐饮」→ 命中餐饮分类 |
| 类型 | 「收入」 |
| 金额 | 「328.6」 |

> 曾经按账户 ID（如 `cmb`）匹配，用户永远搜不出来——这是接口泄漏到界面的典型错误。

### 3.2 筛选与搜索叠加

类型筛选（全部 / 支出 / 收入 / 转账 / 退款 / 调整）与搜索框**同时生效**，
取交集。「全部」是「未设类型筛选」的状态，不是永远高亮的装饰。

**高级筛选**（账户 / 分类 / 金额区间 / 日期区间）与前两者同样叠加，
但承载方式分端：PC 是工具栏下方的**内联面板**（高密度工作流不必来回弹层），
移动端是**底部抽屉**（与时间选择同一手势）。

生效后的条件必须在列表上方**显式可见**：chip 显示条件本身（可读文字，不是
「筛选(2)」这种数字），每条可单独清除，另有「清除条件」清全部。
「重置」= 恢复未筛选态（清高级筛选条件与类型筛选——第十六轮起类型筛选在
移动端也并入筛选面板，同一面板里的条件一起重置才符合直觉）。

### 3.3 无结果 ≠ 冷启动

两种「空」必须区分：

| 场景 | 文案 | 动作 |
|---|---|---|
| 库里真的没有数据 | 「从第一笔开始」+ 三步引导清单 | 建账户 → 记第一笔 → 看报表 |
| 有数据但没匹配上 | 「没有匹配的记录」 | **清空筛选** |

把第二种显示成第一种，是最常见的空态错误：用户搜了个不存在的词，
系统却告诉他「账本是空白的」，他会把账本误当成空的。

## 3A. 交易详情与编辑

流水行的详情（PC 右侧面板 / 移动底部抽屉）按**读 → 改 → 删**三段排列：

```text
金额大字 + 分类图标 + 账户 · 日期   ← 一眼读完
─────────────────────────────
日期 / 分类 / 账户 / 类型 / 手续费 / 备注   ← 键值列表
─────────────────────────────
[编辑]                      [删除]
```

编辑态复用同一个浮层，内容换成表单（金额 / 分类 / 账户 / 日期 / 备注），
底部换成「取消 / 保存」。转账多一项「转入账户」。

编辑中的值写在**草稿**里（不直接改交易），点保存才写回；点取消或关闭
浮层即丢弃草稿。改账户或改金额会影响余额，保存时要先回滚旧影响再按新值重算。

删除在浮层底部，但删除后 toast 提供**撤销**，把交易放回原位置并回滚余额。

## 4. 批量操作

- 流水页「批量」（PC 工具栏）/「批量」（移动端搜索框下方的筛选操作区）进入批量模式。
- 进入后每行左侧出现复选框（真按钮，`role="checkbox"`，带 `aria-checked`）。
- 底部浮出操作条：「已选 N 笔」+ 改分类 + 删除 + 退出。
  操作条在 PC 挂视口、在移动端**挂机身内**——飘在手机壳外会压住底栏。
- **删除有明确确认**，确认文案含数量。
- <kbd>Esc</kbd> 退出批量模式。
- 批量删除后 toast 提供**撤销**，一次恢复全部。

**批量改分类只改分类**：金额、账户、日期不动，因为「批量」的价值在于
一次性纠正归集口径（报表分组与预算占用），不是批量改账。改完提示改了
几笔、是什么分类，并逐笔仍可在流水里撤销。

## 5. 报表浏览

### 5.1 统一时间条

四个报表视图共用同一条时间条（结构固定，两端同构）：

```text
‹   2026 年 10 月  ▾   ›        [日][月][年]
```

- **‹ › 逐期步进**：按当前粒度 ± 1 桶（日 ± 1 天 / 月 ± 1 月 / 年 ± 1 年），即改即生效、
  不打开面板；时点语义（资产负债）步进后仍锚月末 / 年末。
- **▾ 任意跳转**：点标签弹面板（PC 浮层 / 移动抽屉，同一渲染函数）——预设 chips
  （不兼容者置灰）+ 日历 + 取消 / 应用；日历只展示「当前粒度及以下」的层级
  （年 = 年步进 + 年网格、月 = 年步进 + 月网格、日 = 年步进 + 月网格 + 日网格）。
- **粒度切换在时间条上**（第十五轮维度 9「粒度归属」）：分段常驻、即改即生效，
  不打开面板；按新粒度重锚定当前值，失效预设吸附一次并 toast。
  四张报表（含资产负债）都支持全部三档粒度——资产负债是**点时态**（快照），
  粒度 = 锚点精度（月 = 该月末、年 = 该年 12-31）。

时间状态**切报表保持**（C1 语义，评审轮）：从一个报表切到另一个，已选期间
原样带过去——用户通常是在「同一时段」下对照看几张报表，各自记时间会把
对照打断。

### 5.2 一致的骨架

```text
时间条 → 指标 → 图 → 明细表
```

四视图都是这个骨架，只是内容不同。这样用户学会一次，四处都能用。

- **指标**：**1 个主指标 + 3 个数字**（指标条 1+3，第一轮定稿）——
  主指标更宽更大，其余三格平铺。洞察型第五格已随 Q7「一句话结论移除」删除：
  结论是模板拼接，信息量与指标重复且容易过期，改由「指标 + 表格 + 表尾合计」自己读出来。
  表达形式按端分：PC 是**一条指标带**（单一容器 + 发丝分隔线）；
  移动端是**卡片**（主指标占满行，其余 2×2）。
- **图表**：主图（趋势）+ 副图（构成），PC 端横跨整行全宽。
  副图在 PC 用两侧各自标尺的横条（收入构成 / 支出构成），
  在窄屏只画支出构成（收入侧只有两类，完整数字在明细表里）。
- **明细表**：父行是一级分类，`└` 缩进是二级类别，与分类树同构。

### 5.3 明细表：两组表 + 二级项可折叠

四张报表的明细表都是**两组表**，每组一张：

| 报表 | 表一 | 表二 | 移动端分段按钮 |
|---|---|---|---|
| 收支 | 收入表 | 支出表 | 收入 / 支出 |
| 现金流 | 流入表 | 流出表 | 流入 / 流出 |
| 资产负债 | 资产表 | 负债表 | 总资产 / 总负债 |
| 投资分析 | 持仓明细（单表，含二级持仓） | — | 无（只有一张表） |

PC 端两组**并排**（对照是核心动作），且必须是**等高面板**——
两栏表项数量不同时，底部不能各挂一个悬空的合计。
**合计收进各表表尾**（`<tfoot>` 合计行，第三轮定稿）：与各列底部对齐、数值右对齐、
用底色与上边框区分合计语义；两栏并排时通过等高拉伸把两表合计行对齐到较长表格的底部。
卡片底部的跨栏**对照条已删除**（第三轮）：指标条已给结余、表尾已给合计，
对照条是第三处冗余。
移动端**分段按钮 一次只显示一张表**（窄屏并排读不了，上下堆叠又太长）。

**二级子项可折叠**：

- 父行左侧有折叠箭头（`aria-expanded` 标注状态），点击只收起该父项的子行。
- **父行的合计金额始终可见** —— 折叠的是明细，不是数字。
- 折叠状态按「报表:表名:父项」存放，切换报表互不干扰。
- 全局「展开全部 / 折叠全部」控件不设——折叠是逐项的阅读动作，
  常态读表不需要批量开关（原型现状）。

### 5.4 可排序的表

投资分析的表头可点，按市值 / 成本 / 收益 / 收益率排序，再次点击反向。
表头带 `↑` `↓` 指示当前排序。

### 5.5 下钻：报表 → 明细 → 流水

点分类行（父行）打开下钻浮层（PC 右侧面板 / 移动底部抽屉）：

```text
本期支出                     −314.00
─────────────────────────────
二级类别
  └ 外出就餐                 −258.00
  └ 公司食堂                  −56.00
─────────────────────────────
相关流水 · 近 2 笔
  2026-10-28 · 午餐·公司食堂   −28.00
  2026-10-18 · 周末火锅        −286.00
─────────────────────────────
[关闭]              [在流水中查看]
```

- **下钻只展开当期口径**。完整流水与原始交易在「流水」页，不在浮层里重复一遍。
- **金额符号按交易方向**，不按数值正负——支出 28 元是 −28，收入 28 元是 +28。
- **没有对应流水就不给出口**：持仓明细来自净值快照，与收支流水不是同一口径，
  所以持仓下钻不提供「在流水中查看」（给一个假的出口比不给更糟）。
- 「在流水中查看」跳到流水页并**带上筛选条件**（分类名映射到分类码，
  科目名映射到账户），跳转后筛选条件以 chip 显式可见（见 §3.2）。

## 6. 预算

### 6.1 三类预算（评审轮拍板）

预算条目支持**支出 / 收入 / 转账**三类，各自语义互不混用：
**支出 = 限额**（超支告警，环形与「超支条目」提示只统计支出类）；
**收入 = 目标**（达成率，低于目标才是告警方向）；**转账 = 计划跟踪**（流量提示）。
预算条目 = 名称 + 类型 + 金额 + 周期 + 分类 + 账户（不再是「每个分类一个月度额度」）。
三类混在一个百分比里会互相稀释、告警失去含义——这句话常驻在预算页
（预算类型说明），用户第一次看到「转账不占超支」时一定会怀疑自己理解错了。

### 6.2 布局：先看总量，再看分类

```text
PC                                   移动
┌──────────────────────────┐         ┌──────────────┐
│ 预算   2026 年 10 月     │         │ 预算  10月 ＋新增│
├──────────────────────────┤         ├──────────────┤
│   ◕ 78%                  │         │   环形进度    │
│   总预算 / 已使用 / 剩余 │         │     78%      │
│   ⚠ 购物已超支 ¥128.60   │         │  已用 ¥… / ¥… │
├──────────────────────────┤         ├──────────────┤
│  餐饮  ▓▓▓▓▓░░ 814/1500 │         │ 分类进度列表  │
│  居住  ▓▓▓▓▓▓▓ 5600/5600 │         │  居住 …       │
│  购物  ▓▓▓▓▓▓▓▓ 928/800  │         │  购物 … 超支  │
└──────────────────────────┘         └──────────────┘
```

- **总量用环形进度**（PC 直径大、移动端 150px）：一眼看出「这个月还剩多少」。
- 环形中心是**百分比**，下方是「已用 ¥x / ¥y」——百分比用于快读，金额用于决策。
- **分类列表**每行三段：名称 / 进度条 / `已用 / 限额`，超支行加「超支」标记。
- 进度条颜色按占用率分档：< 80% 品牌绿，≥ 80% 琥珀，**超支用支出红**。
  超支行的进度条填满 100%，不再画溢出段——溢出量用右侧金额与标记表达。
- 总量卡上常驻一条**超支提示**：写明哪个分类超了多少（`购物已超支 ¥128.60`），
  而不是只把那一行标红。超支是需要在总量层面被看见的事件。

### 6.3 调整限额：只在单一预算条目内做

点击某个预算条目 → **条目详情面板**（PC 右侧抽屉 / 移动底部抽屉）：

```text
预算    餐饮 · 支出预算
──────────────────────────────
已用 286.00 / 1,500.00    ▓▓░░░░░░
类型 支出 · 周期 每月 · 分类 餐饮 · 账户 不限
──────────────────────────────
调整该条目额度      [ 1500 ]  [保存]
未超支，剩余 ¥1,214.00
──────────────────────────────
该分类流水（…）
[删除条目]
```

- **不设「调整所有预算条目」的统一入口**（第十七轮移除 PC 页头「调整预算」与移动页头
  「调整」）：全局调整表把「改哪一条」和「改多少」拆成两步，三类预算的语义差异
  在批量表里也看不出来。
- 每行只有**该条目**的三段：分类名 / 已用 / 限额输入；已用只读，改限额时立刻能算出剩余。
- 输入值写在草稿（`budOne`），点「保存」写回；关闭面板即丢弃。
- 保存后**面板保持打开**，进度条与反馈文字按新额度就地重算——反馈按类型分：
  支出「未超支，剩余 / 已超支」、收入「距目标还差 / 已达成」、转账「阈值内 / 超阈值」。
  双端输入框与保存键移动端均为 44px 触控高。

### 6.4 超支必须给一个决定

超支行不是一句提醒，而是**一个待决事项**。条目详情面板里，超支的支出类条目下方
出现一个决定区，给三个出口：

| 出口 | 动作 | 语义 |
|---|---|---|
| **按实际调整** | 限额直接提到已用值 | 「就这样，我认了」 |
| **维持限额** | 不改限额，本期仍标记超支 | 「这是已知告警，别再提醒我」 |
| **查看流水** | 跳到流水页并按该分类筛选 | 「我先看看钱花在哪」 |

三条都必须是显式动作，不能靠「什么都不做」默认处理——默认选项会把用户的
真实意图（没看见 / 看见了接受 / 还没想）压成同一种结果。

「维持限额」要回一句明确的话（`维持原限额 —— 本期仍标记为超支，作为已知告警`），
让用户知道自己选了什么，而不是点了没反应。

### 6.5 生效时机

**调整立即按新额度重算该条目的用量与超支反馈（第十七轮改写，取代原「下一期生效」）。**

理由：条目内调整是「这一条现在改」，反馈必须当场可见——保存后面板不关，
进度条、剩余/超支、收入达成、转账阈值四种反馈就地更新。预算是判断基线，
不追溯已发生的交易金额；若真实实现需要「下期生效」，应在条目面板显示**生效期字段**，
而不是静默延后并让反馈与输入值矛盾。本轮原型即改即生效。

## 7. 数据：覆盖导入、回滚与导出

入口在**设置 → 数据**。这一组是低频但高风险的操作，布局原则是：
**每一步都可回看，每一步都先说清楚影响范围**。

### 7.1 覆盖导入：固定三步

```text
1 选择文件  →  2 预览  →  3 建回滚点  →  完成
```

向导是**三步固定流程**，不是可跳步的自由表单：

| 步 | 内容 | 关键约束 |
|---|---|---|
| 1 选择文件 | 拖放区 + 「选择文件」按钮；说明支持 CSV 与 OFX、列顺序与中文表头自动识别 | 进入时就讲清「导入是覆盖式的」 |
| 2 预览 | 解析结果表（日期 / 分类 / 备注 / 账户 / 金额），只展示前 5 行 | 同时给出**覆盖范围**与新增/覆盖笔数 |
| 3 建回滚点 | 清单式确认（回滚点 / 覆盖范围 / 保留项） | 「确认覆盖导入」是唯一主动作 |

- 第 2 步的预览表**必须标明是预览**（`仅预览前 5 行`），不能让人误以为这就是全部。
- 第 2 步要给数字：识别到多少笔、其中多少覆盖现有流水、多少是新增、
  覆盖哪个月份（`识别到 96 笔将覆盖 2026 年 10 月的现有流水，32 笔为新增；其余月份不受影响`）。
- 第 3 步是**清单而非表单**——只列「回滚点 / 覆盖范围 / 保留」，让用户核对而不是填写。
- 底部主动作文案必须带「覆盖」二字（`确认覆盖导入`），不能是笼统的「确定」。

### 7.2 覆盖范围要说清楚

导入只覆盖**文件声明的期间**；其余月份、账户余额、预算与设置**全部保留**。

这条在第 1 步、第 2 步、第 3 步各说一次（文案不同、事实相同）：
覆盖式操作最怕用户以为「全量替换」，所以影响范围要在**每一步**都露出来，
而不是只在最后一步才补充说明。

### 7.3 回滚点：还原前先再存一个

- 导入完成时**自动创建**一个回滚点，toast 明确告知（`导入完成 · 已创建回滚点`）。
- 回滚点列表在「设置 → 数据 → 回滚点」，每条含时间、类型（自动 / 手动）、大小。
- **还原前自动再存一个回滚点**——还原本身也是一次数据变更，
  必须同样可撤回。确认文案要写明这一点（`当前状态会先自动存为新回滚点`）。
- 还原是**全量**的：交易、账户余额与预算一起回到该时点。说明文字要写全，
  否则用户会以为只回滚流水。

### 7.4 导出

CSV 全量导出，格式长期稳定（下游脚本依赖它）。
导出是只读操作，不走向导，一个按钮 + 一次 toast 即可。

## 8. 键盘

PC 端键盘优先是一等公民，不是补充。

| 键 | 动作 |
|---|---|
| <kbd>1</kbd>–<kbd>5</kbd> | 切换五个主导航 |
| <kbd>N</kbd> | 打开记账 |
| <kbd>/</kbd> | 跳到搜索框并聚焦 |
| <kbd>1</kbd>–<kbd>9</kbd> | 记账时选分类 |
| <kbd>⏎</kbd> | 记账时推进阶段 / 保存并再记 |
| <kbd>Esc</kbd> | 关闭弹层 / 退出批量模式 |

**焦点管理**（U7）：

- 打开记账 → 焦点进入弹层的金额输入框。
- 弹层内 <kbd>Tab</kbd> 循环，不跑到弹层外。
- 关闭弹层 → **焦点回到打开它的那个元素**。记账是「随手翻开」的动作，
  关闭后焦点必须回到来处。

## 9. 三态

加载 / 空 / 错误三态在**每个**页面都存在，且表达统一（UX5b）：

| 态 | 表达 |
|---|---|
| 加载 | Skeleton（不用裸文本「加载中...」）；`role="status"` + `aria-busy`，屏幕阅读器读「正在加载数据…」 |
| 空 | 图标 + 标题 + 说明 + 引导动作（区分冷启动与无结果，§3.3） |
| 错误 | `role="alert"` + 说明「数据没取出来」+ 重试按钮 + 错误码 |

错误文案必须说明**数据是否安全**：「本地数据库响应超时。你的数据没有丢失——
这是展示层的问题。」——这一句是信任的载体。

- **页面级三态优先**：组件级 `loading` 可自吞，`error` 必须冒泡到页面级；
  单报表错误只替换报表区域，不整页失败。

## 10. 触屏

- 可点击元素 ≥ **44×44**（U6）。
- 主要动作（记账 FAB）落在拇指可达区：底部导航正中。
- 触屏上 `:hover` 永不触发，因此**不能把唯一入口藏在 hover 里**——
  行内操作按钮在触屏设备上常驻显示。

**44px 的落点**（不是「所有东西都 44px」，而是「容易点错的必须是 44px」）：

| 元素 | 处理 |
|---|---|
| 行内操作（编辑 / 删除） | 移动端**常驻**在行尾，触控目标 ≥ 44×44 |
| 批量复选框 | 移动端常驻在行首，与行内操作对称 |
| 流水行整行 | 行高不必到 44px，但点击区（整行）不得小于 44px |
| 图表 / 表格里的次要数据点 | 不作 44px 要求——它们不是主操作 |

**常驻不等于变挤**：移动端行内操作常驻后，行内留白靠**收紧图标间距**解决，
不靠缩小图标。若行内操作与金额数字产生竞争，优先把操作收到行尾一列，
不把金额缩小——金额是这一行最该被读到的信息。
