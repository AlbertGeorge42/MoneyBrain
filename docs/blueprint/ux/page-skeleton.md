# 页面骨架规范（Page Skeleton）

> 状态：草案（阶段一，仅测量与规范，不改组件代码）
> 与 [design-tokens.md](./design-tokens.md) 的关系：design-tokens 定义颜色、字号、圆角、按钮四档、z 阶梯、动效；本文件在其**之上**定义**页面骨架**——页头、控件行、分区、设置行、侧栏信息块的位置与高度。
> 冲突处理：本文件只约束**位置与槽位**，不重复定义颜色/圆角/动效；数值一律引用 `--mb-*` token，不新增字面量。

---

## 0. 为什么需要这一层

当前各页的局部设计都已成立，但同一结构在不同页面各摆一处，导致「整个应用没有整体设计的感觉」。实测（见 §1）暴露的典型问题：

- 报表的时间选择器在页头**下方**独立控件行（桌面 y92），预算的时间选择器在页头**内部**（y30）——同一控件垂直差 62px，水平锚点一个左一个右。
- 流水控件行高度 38 / 88 / 138 / 162（1440 / 1024 / 768 / 390）四档，报表 44 / 88 / 143.2 三档，预算 44 / 46 / 54 三档，没有统一规则。
- 「不计收支」开关在报表是页面级独立块（h48），在预算是详情弹层行（h70.6），在设置是卡片内行（h44），三种容器三种高度。
- 侧栏页脚 y 坐标在 693–118232 之间跳动（随内容总高移动），长页面上永不可见。

目标：把「页头 / 控件行 / 内容区 / 设置行 / 侧栏块」收敛为四个原语，页面只做组合，不再各自摆放。

## 1. 测量基线

### 1.1 采集方法

- 独立 dev 服务：`npx vite --port 3005 --strictPort`（不复用可能陈旧的 3002）。
- 数据：`VITE_HF_DATA=api`，只读现有账本；浏览器 Edge headless。
- 视口：390×844、768×900、1024×900、1440×900。
- 取数：`document.fonts.ready` 后 `getBoundingClientRect()` + `getComputedStyle()`，每页等待 500ms。
- 坐标：视口坐标；桌面内容容器顶 = 28（`--mb-page-pad`），移动内容容器顶 = 100（shell 头 60 + 上内距 8）。
- 采集时点：2026-11-08。**报表与设置两页当时有未提交改动（reports / settings 并行通道）**，这两列数值以当前工作区为准；流水、预算、总览结构文件干净。

### 1.2 结论摘要（完整对照见 §1.3）

- 桌面页头在 5 页上**完全一致**：y28、h48、标题 20/24 @y40。说明已有隐式共识，缺的是成文。
- 控件行 0 / 1 / 4 档高度不统一；报表与预算时间器的**槽位差 62–64px**。
- 设置行 desktop 44 / mobile 56、label 与控件中心差 0，是现状里**最接近规范**的一族，应直接升格为 `SettingRow`。
- 侧栏页脚没有固定槽位，是本次测量中跳动最大的结构。

## 2. 布局原语

四个原语 + 一个允许关系：`PageShell > (Head, ControlRow?, SectionBlock*)`；`SectionBlock > (SectionTitle, Card*, SettingRow*)`；`SettingRow` 是唯一承载「label 在左、控件在右」的行原语，侧栏信息块复用其 `stack` 变体。

```
PageShell
├─ Head           页头：标题 / 副标题 / 动作
├─ ControlRow?    控件行：时间器 / 分段控件 / 筛选器 / 二级开关（可空）
└─ Content
   ├─ SectionBlock
   │  ├─ SectionTitle
   │  ├─ Card
   │  └─ SettingRow*
   └─ SectionBlock ...
```

### 2.1 `PageShell`

**职责**：定义页面三段（页头 / 控件行 / 内容）的存在与段间距。页面不自己写顶部 padding、不自己排页头。

| 槽位 | 桌面（≥768） | 移动（<768） |
|---|---|---|
| 内容容器左右内距 | 28（`--mb-page-pad`） | 26（`--mb-page-pad-mobile`） |
| 内容容器上内距 | 28 | 8（shell 头高 60 已占位） |
| 内容容器底部留白 | 28 | 116（底部导航 + 安全区） |
| 内容最大宽 | 1120（`--mb-content-max`），超出居中 | 100% |
| Head 高度 | 48（`--mb-s-7`，min-height） | shell 内建 60；内容内可选副行 |
| Head 标题 | 20/24（`--mb-fs-4` × `--mb-lh-tight`） | 28/33.6（`--mb-fs-5`） |
| Head 副标题 | 13（`--mb-fs-1`），与标题基线对齐 | 内容内 16 高 meta 行 |
| Head→ControlRow | 16（`--mb-s-4`） | 16 |
| ControlRow→Content | 16 | 16 |
| Content 段间距 | 16 | 16 |
| 无 ControlRow 时 Head→Content | 16 | 16 |

**Head 槽位规则**

1. 标题固定在左；动作固定在右；副标题与标题同一基线（实测现状 cy 差 0，预算 `mb-bg-page-copy` 的 2.5px 需归零）。
2. 页级动作（新增、设置、导出）只允许出现在 Head 右侧；**禁止**放进 `ControlRow`（现状报表「设置」、流水「显示」在控件行，迁移时上移）。
3. 副标题可选；若页面无副标题，不得用空 `span` 占位。报表补「区间 + 状态」摘要，设置补「本地优先」摘要（见 §4）。
4. 移动端内容页头允许为空：由 shell 头（固定 60）代偿；有副行时（报表 tabs、预算月份器）副行归入 `ControlRow`，不再伪装成页头。

**禁止**

- 页面根节点自写 `padding-top` / `max-width` / `gap`。
- 在 Head 内放时间选择器、筛选器、分段控件（预算现状，迁移时移出）。
- 在 Head 内使用负 margin 把后续块顶上来（预算 `mb-bg-future-entry` 的 `-8px`）。

### 2.2 `ControlRow`

**职责**：页面级控件唯一的容身处，紧跟页头，位置固定。它不负责内容排版。

**允许的子元素白名单**（其余一律禁止）：

| 子元素 | 组件 | 桌面高度 | 移动高度 |
|---|---|---|---|
| 时间选择器 | `TimeRangePicker` / `PeriodBar`（同一套：32 箭头、pad5、gap2） | 44 | 54 |
| 分段控件 | `HfSegmented`（日/周/月/年、收入/支出/转账） | 36（按钮 28） | 52（按钮 44） |
| 筛选器 | 搜索框 / 类型组 / 高级筛选按钮 | 38 | 44–46 |
| 二级开关 | `HfSwitch`（含说明文字） | 44 | 44 |
| 附属说明 | `range-state` / `period-bar-note`（12px） | 21.2 | 16.8 |

**排列规则**

1. 桌面 ≥1024：单行；`align-items: center`；子元素中心线对齐（实测现状 5 个控件 cy 全为 114，保持）。
2. 桌面 768–1023：允许换行为 2 行，行高由内容决定；换行必须在 `ControlRow` 内声明，页面不得各写 `flex-wrap`。
3. 移动 <768：纵向堆叠；控件间距 8（`--mb-s-2`）；每个控件保持自身命中区高度（时间器 54、分段 52、按钮 44）。
4. 上下留白：上 16、下 16；**不允许**用负 margin 与页头贴合。
5. 水平锚点：时间选择器左对齐；页级动作（若历史原因仍在行内）右对齐并单独占尾部槽位；预算月份器的右对齐属于漂移，迁移后左对齐。

**禁止**

- 时间选择器出现在 Head 内（预算现状）。
- 同一行混用「左对齐时间器 + 右对齐动作 + 说明文字」三种锚点（预算现状）。
- 在 `ControlRow` 内放卡片、列表、图表等非控件内容。

### 2.3 `SettingRow`

**职责**：所有「标签/描述 + 控件」行的唯一实现；也用于侧栏信息块的纵向堆叠。

**`inline` 变体（默认）**

| 属性 | 桌面 | 移动 |
|---|---|---|
| 行高 / 最小高 | 44 / 44 | 56 / 56 |
| 左右内距 | 12 | 12 |
| 子级左缩进 | 24 | 70 |
| label | 13px（`--mb-fs-1`） | 13px |
| 描述/元信息 | 12px（`--mb-fs-0`），tertiary | 12px |
| 控件 | 右对齐，高 32（switch 28） | 高 44 |
| 垂直对齐 | label 与控件**中心对齐**（实测 dy=0） | 同 |
| 控件类型 | switch / checkbox / 更多按钮 / 选择器 | 同 |

**`stack` 变体（侧栏信息块）**

| 属性 | 数值 |
|---|---|
| 结构 | label 12 / value 20/1.2 / meta 12，纵向 gap 4 |
| 块高 | 81（三项齐全）；缺项按实际内容，最小 44 |
| 位置 | 固定在侧栏底部槽位，不随页面内容高度移动 |

**规则**

1. 设置列表行只允许 `SettingRow`；`mb-set-row` 迁移后全部由它渲染。
2. `appearance` / `backup` / `display.sort` 这类「label 在上、控件在下」的表单字段**不是** `SettingRow`，归入 `FormField`（label 12 在上、控件 38/44、gap 8），只能出现在 `SectionBlock` 内，不得冒充列表行。
3. 二级开关的三种容器高度必须归一：报表 `scope` 行、预算 `active-row`、设置 `capability-row` 统一按 `SettingRow inline`（桌面 44 / 移动 56）；说明文字允许在 label 下方换行，但行高不随之膨胀。
4. 侧栏 brand / nav 不属于 `SettingRow`（前者是品牌块，后者是导航）；只有页脚信息块走 `stack`。

### 2.4 `SectionBlock`

**职责**：定义「分区标题 → 内容」的间距，和卡片的内距/间距。

| 属性 | 桌面 | 移动 |
|---|---|---|
| 分区标题字号 | 16 / 19.2（`--mb-fs-3` × tight） | 16 / 19.2 |
| 标题→内容 | 12（`--mb-s-3`） | 12 |
| 分区之间 | 16 | 16 |
| 卡片内距 | 20（`--mb-card-pad`） | 16（`--mb-s-4`） |
| 卡片内子块间距 | 12 | 12 |
| 表格卡内距 | 0（表格自带 `--mb-tbl-py`） | 0 |

**规则**

1. 分区标题属于 `SectionBlock`，不得在页面里直接写 `<h2 className="mb-sec-title">`。
2. 卡片只允许两种内距：常规 20/16、表格 0；不再出现 12 的第三种（报表卡历史值已收敛）。
3. 分区之间不使用负 margin；预算 `future` 链接归入首个 `SectionBlock` 的头部行，间距 16。

## 4. 语义不同（保留，不抹平）

以下差异是**有意义的**，写进规范而不是统一：

1. **桌面页头 48/20px vs 移动 shell 头 60/28px**：移动端标题是页面唯一标题，字号更大；桌面端有侧栏品牌，页头可更紧凑。
2. **移动端控件行纵向堆叠**：390 宽度放不下「时间器 + 分段 + 筛选」；堆叠顺序固定为「时间器 → 状态说明 → 分段 → 筛选 → 开关」。
3. **卡片内距 20/16、设置行 44/56**：移动端提高命中区与可读性，保留。
4. **表格卡内距 0**：表格自带单元格内距，不属于卡片密度体系。
5. **副行归属**：报表移动端 tabs、预算移动端月份器位于内容区顶部，属于 `ControlRow` 的移动端首段，不计入页头高度。

## 5. 迁移顺序（一次一页，禁止大爆炸）

前置：先落 `PageShell` / `ControlRow` / `SettingRow` / `SectionBlock` 四个空壳组件与守卫测试，**不改任何页面视觉**（阶段 0，零视觉差异）。

| 顺序 | 页面 | 改动 | 预期视觉变化 | 验收 |
|---|---|---|---|---|
| 0 | 原语落地 | 新增四原语 + 守卫，页面仍用旧 DOM | 0 | 四宽度截图逐像素 diff = 0 |
| 1 | 总览 | 包 `PageShell`；meta 行归位 | 0 | diff = 0 |
| 2 | 流水 | 工具栏包 `ControlRow` | 0（仅 DOM 结构） | diff = 0 |
| 3 | 报表 | 时间器入 `ControlRow`；「设置」上移页头；补副标题 | 设置按钮位移；移动 gap 12→16 | diff 标注后更新基线 |
| 4 | 预算 | 月份器移出页头入 `ControlRow`；future 去负 margin；修 768 标题换行 | 桌面时间器下移 62px；768 标题不再断行 | diff 标注后更新基线 |
| 5 | 设置 | 页头补副标题；`mb-set-row` → `SettingRow`；表单 → `FormField`；覆盖层头 52→56 | 覆盖层头 +4px；行高不变 | diff 标注后更新基线 |
| 6 | 侧栏 | 页脚固定槽位（侧栏改用视口高 + 内部滚动/吸底） | 页脚不再随内容跳动 | 全部页面 foot y 相同 |

**每页「零视觉差异」证明方式**

1. 迁移前在 390/768/1024/1440 各截全页图，存为基线（不进仓库，放临时目录）。
2. 迁移后同机同浏览器同视口重截，用 `pixelmatch` 比对；阈值 0 像素差异为通过。
3. 有意的视觉变化（报表设置按钮、预算时间器、设置覆盖层头）单独列出「坐标前后差值 + 截图」，经确认后更新基线，**不得**把 diff 混进「零差异」批次。
4. 每页提交说明附：diff 图路径、差异像素数、四宽度实测行高/间距值。

## 6. 守卫

### 6.1 结构守卫（DOM 断言，进单测）

对每个页面路由渲染后断言：

1. 恰好一个 `[data-skeleton="page-shell"]`。
2. `[data-skeleton="control-row"]` 数量为 0 或 1；若有，必须是 `page-shell` 的直接子节点，且排在 head 之后、content 之前。
3. 所有 `.mb-set-row` 必须位于 `[data-skeleton="setting-row"]` 内；数量相等。
4. 禁止页面内出现 `mb-page-title` / `mb-rp-page-title` / `mb-set-title` 裸元素（必须由 `PageShell` 渲染）。
5. 禁止 `mb-period`、`mb-rp-timebar`、`mb-tx-toolbar` 出现在 `[data-skeleton="control-row"]` 之外。

### 6.2 Lint 守卫

- 新增 ESLint `no-restricted-syntax`：
  - 页面目录（`features/*/*Page.tsx`）禁止直接写 `className` 含 `mb-page-head` / `mb-rp-page-head` / `mb-bg-page-head` / `mb-set-head`。
  - 禁止 `mb-rp-timebar` / `mb-period` / `mb-tx-toolbar` 出现在 `PageShell` 与 `ControlRow` 之外的文件。
  - 禁止内联 `style={{ marginTop: '-8px' }}` 这类负 margin 修正。
- CSS 守卫：grep 断言 `features/**/*.css` 中不存在 `margin-top: -`。

### 6.3 截图基线

- 4 宽度 × 5 页面 = 20 张基线；CI 或本地 `npm run guard:skeleton` 生成并对比。
- 任一页面新增/删除 `ControlRow` 必须同步更新基线并写进提交说明。
