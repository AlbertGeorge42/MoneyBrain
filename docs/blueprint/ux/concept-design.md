## 2. 模块布局速览

| 模块 | PC 主结构 | 移动主结构 | 视觉表达核心 |
|---|---|---|---|
| 流水 | 工具栏 + 列表（完整表格感） | 搜索 + 分段 + 卡片行 | PC 密度高；移动端一行一卡 |
| 报表 | 指标条 + 整行全宽图 + 两栏并排表（固定行高；合计行底部对齐；短侧静默占位） | 指标卡 + 横滑图 + 分段按钮 | PC 图全宽、表并排；移动端一次一张表 |
| 预算 | 环形进度（156px）+ 分类行 | 环形进度（108px）+ 分类卡 | 同构，仅尺寸与容器不同 |
| 设置 | 单页卡片堆叠（配置中心卡 + 通用卡） | 配置中心入口（开配置弹窗）+ 通用项二级页（带返回箭头） | 同构，仅承载方式不同 |
| 记账 | 居中弹层 600px | 底部抽屉 + 自绘数字键盘 | PC 键盘优先；移动端拇指优先 |

**总览的取舍**（用户第三轮）：账户明细移出总览主区——余额是配置态数据，
总览是读趋势与动向的地方；主区改为**净资产走势图**（信息价值最高：
hero 给时点值、走势给方向；预算进度已有卡片、收支结构归报表页）。
账户收成一行入口（`.acct-entry`，点击进设置），不占主区也不失去入口。

#### 交互逻辑差异

| | PC | 移动 |
|---|---|---|
| 数字输入 | 系统键盘 + <kbd>⏎</kbd> 推进 | **自绘键盘**，金额框只读显示 |
| 分类选择 | 点分类格 / 按 <kbd>1</kbd>–<kbd>9</kbd> | 点分类格（无物理键盘） |
| 提交 | 保存 / 保存并再记（两种按钮） | 保存并再记为主按钮 |
| 账户选择（第十轮 + 第十一轮分级） | **常驻单行横向 chips**（最近使用 + 当前选中，前 5 个）：当前高亮、点击即切换；账户 > 5 时行尾「全部账户 ›」开**固定高度二级抽屉**（搜索 + 按分类分组 + 内部滚动），选完回原位置 | 同一套 chips（两端同构）；转账为「转出 / 转入」两行 chips，各自独立选择 |
| 连续录入 | 保留账户与分类，清金额 | 同 PC，头部显示「已连记 N 笔」 |
| 关闭 | <kbd>Esc</kbd> / ✕ / 点遮罩 / 取消。**有已填内容时发「草稿已丢弃 · 撤销」**（T6：撤销 = 重开并恢复草稿）；空表单关闭不发 | 同一套规则（下拉关闭手势未实现，以 ✕ / 遮罩替代——P1） |

**账户选择的方案对比（第十轮，选 A）**——问题：原「当前账户 pill + 展开式选择器」在展开时把移动端记账抽屉撑高 186px（实测 588→774px、账户行 37→223px），「换账户」变成一次布局跳动。

| | A 常驻横向 chips（**采用**） | B 二级抽屉 |
|---|---|---|
| 高度变化 | **零变化**（切换前后抽屉 588px / 滚动区 296=296 / 账户行 37px 全等） | 零变化（原抽屉不动，新抽屉盖上来） |
| 滚动条 | 不出现（实测全程无） | 不出现 |
| 操作步数 | **1 步**（点账户即切换） | 3 步（点换 → 选 → 回） |
| 单手可达 | chips 在滚动区上部，与分类网格同带 | 二级抽屉贴底、拇指可达，但盖住金额区 |
| 代价 | 账户多时横滑（原型 5 个账户、日常 1–2 屏内） | 多一层弹层栈语义；连记场景下每次换账户都开合 |

选 A 的理由：换账户是「微调」动作，chips 把它压到一步且**只换文字与选中态、布局零变化**；B 用一层抽屉换稳定，代价是每次微调都要开合一次、且遮挡当前输入。转账的「转入账户」原实现与转出共用一个选择器、选中却改转出账户（缺陷），随 chips 一并修复为独立选择。

**账户扩容的分级方案（第十一轮，A + 分级兜底）**——问题：账户 > 5 个后单行 chips 要横滑，选中账户可能滑出可视区。实现 = **chips 只放「最近使用 + 当前选中」前 5 个**（切换仍零布局变化、选中恒可见），行尾「全部账户 ›」打开**固定高度二级抽屉**（搜索 + 按分类分组 + 内部滚动，从记账抽屉上层弹出，选完回原位置）。备选：固定高度下拉（不撑高容器、内部滚动）——未采用，理由见下表。

| | A+分级（chips + 全部账户二级抽屉，**采用**） | 固定高度下拉 |
|---|---|---|
| 20 个账户时高度变化 | **零变化**（实测 5/12/20 个账户时抽屉 588px / 滚动区 296=296 / 账户行 37px / 金额区 y=223 全等） | 零变化（容器固定高） |
| 外层滚动条 | 不出现（实测三档均无） | 不出现 |
| 操作步数 | 常用账户 1 步（chips 直点）；长尾账户 3 步（全部账户 → 搜索/点选 → 回） | 2 步（开下拉 → 点选） |
| 单手可达 | 二级抽屉贴底全宽、列表项 ≥44px，拇指可达；搜索框在抽屉顶部 | 下拉锚在 chips 行、向下展开，可达但宽度受限于行 |
| 长尾账户查找 | **可搜索 + 按分类分组**（20 个账户两级定位） | 纯滚动定位（无分组、搜索需另加） |
| 弹层代价 | 复用 overlay 栈（above-entry 提层盖住记账抽屉），选完自动关 | 需自造下拉壳（又一种载体，违背第十轮载体系收敛） |

采用理由：常用路径保持第十轮的「1 步零变化」；长尾路径用**已统一的抽屉载体**（复用弹层栈语义），且带搜索与分组——下拉方案要引入第三种选择壳，与第十轮「载体系只有平铺/全屏页 + 浮层两类」的收敛方向冲突。
实测：账户 5 / 12 / 20 个时抽屉高度、滚动区、记账区位置三者不变（588 / 296=296 / y=223 全等），只有选择器列表内部滚动（15 个账户 max-height 56vh 内滚）；搜索「测试账户7」15→1 行；选中后 chips 高亮、最近使用更新、选中 chip 恒在可视区；外层记账抽屉零变化。

#### 视觉表达差异与取舍

- **PC 金额 40px 等宽数字**——它是那一屏唯一需要精确输入的东西，必须是焦点。
- **移动端不自绘键盘就用系统键盘**，系统键盘会占掉半屏并遮住分类网格，
  所以「输金额 → 选分类」必须变成上下滑动，3 步节奏就断了。**自绘键盘是移动端保持 3 步的关键**。
- 移动端分类网格从 4×2 降为 3 列——拇指点按面积优先，宁可多滚也不让格子变小。
- 两端都把手续费 / 优惠券 / 日期 / 备注折叠进「更多」，常规路径零干扰。
- **账户 chips 与分类格同密度**（chip 高 ≈ 原 pill 28px，行高 37px 与原账户行相等）——换账户不加高任何一段，记一屏预算不被账户选择吃掉。

> **已知缺口（不在概念稿里修，高保真阶段处理）**：移动端抽屉头目前只有「记一笔 ✕」，
> 缺 UX2 §2.2 要求的「已连记 N 笔」（原型实测）。位置见 §6 Q4。

- 高级筛选：PC 内联面板 / 移动**底部抽屉**（与时间选择同一手势）。

**入口控件口径（唯一，第十九轮）**

- **类型筛选、高级筛选、批量、显示、设置一律是 `<button>`**（chips 或按钮），两端同语义、同标签、同控件类型；布局位置可因双端结构不同，但控件形态不再分叉。
- 标签唯一：`全部 / 支出 / 收入 / 转账 / 退款 / 调整`、`高级筛选`、`批量 ↔ 退出批量`、`显示`、`设置`。不再出现 `⌄ 高级筛选`、`☑ 批量`、`⚙ 显示`、纯图标 `⚙`、文字链或 `<select>` 作为入口。
- 选中 / 未选中不只靠颜色：**选中 = 1px 边框 + 1px 内描边（视觉 2px）+ 字重 600 + 下沉底色**；未选中 = 1px 边框 + 常规字重 + 面板底色。双端同一条规则，`aria-pressed` 同步。
- 触控：移动端入口按钮高 ≥44px；宽度随内容，放不下时**整组换行、不横滚**；报表切换按钮同样 ≥44px。
- 报表页面「设置」也是文字按钮（PC 在时间条右端、移动在页头），打开同一批配置弹窗（见 W6）。

#### 视觉表达差异与取舍

- **PC 是表格、列对齐**：同屏可横向比较「金额 / 账户 / 日期」，这是桌面端的核心能力。

  代价是**垂直密度下降**——但移动端是近看屏幕，少而清楚比多而挤更对。

#### 视觉表达差异与取舍

- **账户颜色按账户性质**（储蓄 / 现金 / 信用 / 投资），交易图标色按收支方向——颜色是语义位，不是装饰位。
- **配置中心收敛入口**：同一批配置弹窗只有「报表工具栏设置 + 设置页配置中心」两个入口，
  其余入口一律删除——入口越多，用户越不确定哪边是权威。
- **载体分置（评审轮拍板）**：同为移动端，设置页入口给全屏二级页（专门配置、要完整纵向空间），
  报表时间条右端「设置」给底部抽屉（边改边看、不离开表格）——载体跟着使用场景走，数据只有一份。
- 分类树在移动端维持两级（一级 + 二级），与 UX1「二级结构不超过两层」一致。
- **排序只留 ⠿ 拖拽占位（T5/第九轮）**：↑↓ 上下箭头已删——一行里排序、编辑、移动、删除四个操作组
  让行密度失控；排序用 ⠿ 占位（真实拖拽落地阶段实现），其余操作收进行尾 ⋯ 菜单，
  五类表格配置同一套行结构，不再一处散落按钮、另一处菜单混杂。
- **删除分类必须转移交易**：删除时选目标分类，交易跟着走；有子分类的分类先处理子分类。
  「删除即静默丢失交易」不允许。账户删除同语义：有交易引用直接禁删并注明笔数。
- **现金流属性编辑入口唯一**：数据是分类的局部字段（W5 决策不变），编辑只在「现金流配置」弹窗
  （行尾 ⋯ → 编辑浮层）；收支分类弹窗的行内以属性小标签 + 笔数徽标降级展示。
- **现金流相关配置**（账户互转的转入账户、手续费）在两端都属于**局部字段**，不在设置里做全局配置。
- **每项皆可调（第九轮）**：设置页不保留任何「只列出不可操作」的行——必需列固定改由表下说明表达，
  偏好卡（启动视图 / 千分位 / 主题占位）整卡删除；一屏看清「设置里到底能改什么」。

#### 时间选择器规范（第十四轮推翻重做 · 本表为唯一权威）

用户反馈「时间选择器还是混乱的，理清规范重新设计一版」→ 不再增量修补，先钉死 8 个维度
再一次性重写实现；本节旧的时间选择器表述全部作废，以下表为准。

| # | 维度 | 规范（钉死） |
|---|---|---|
| 1 | 语义二分 | **时点** = 某一时刻的余额快照（资产负债）；**期间** = 一段时间的发生额（收支明细 / 现金流量 / 投资分析）。语义由报表 tab 决定、不由控件配置；**语义决定面板结构**（时点 = 日历单端点，期间 = 起 / 止两步），不靠标签文字解释 |
| 2 | 粒度三分 | 日 / 月 / 年，四张报表 × 三粒度全支持。**时点**语义下粒度 = 锚点精度：日 = 当日、月 = 该月最后一天、年 = 该年 12-31（`snapPointToGran` 自动锚定）；**期间**语义下粒度 = 聚合桶，决定分桶与 ‹ › 步进 |
| 3 | 选择方式二分 | 预设 / 自定义。预设 7 个：今天、近 7 天、本月、上月、本季、今年、近 12 个月。**预设 × 粒度兼容矩阵**（`PRESET_GRAN_OK`）：今天 / 近 7 天仅日粒度；本月 / 上月 / 本季到月粒度；今年 / 近 12 个月到年粒度。两种场景各一条唯一规则：**面板内**不兼容的预设 = 置灰（不吸附）；**时间条上切粒度后**已生效预设若失效 = 吸附一次到该粒度默认预设并 toast（不置灰——时间条上没有预设控件可置灰） |
| 4 | 控件形态唯一 | **时间条结构固定**：`‹` 左箭头 · 当前值（只读触发器，点开即面板、不调起系统键盘）· 右箭头 `›` · 粒度分段（日/月/年常驻，见维度 9）。**同一套面板**：两端共用渲染函数 `timePanelHtml()` 与同一组 class，元素顺序固定：**预设 → 日历（按粒度裁剪层级）→ 取消 / 应用**。载体差异：PC = 触发器下方浮层（`.period-pop`）；移动 = 底部抽屉。两端尺寸同值（维度 8） |
| 5 | 文案规则唯一 | 时间条**只显示所选值本身**：日 = `YYYY-MM-DD`、月 = `YYYY-MM`、年 = `YYYY`、期间 = `起 ~ 止` 或预设名。禁止语义前缀（「时点 ·」「期间 ·」）、聚合后缀（「按 X 聚合」）、口径 tag；表下不再出现口径 note 或说明句（2026-11-05 文案精简），口径定义只留在 requirements |
| 6 | 状态机 | 草稿制（`S.timeDraft {from,to,end}`）：**打开**（草稿从已生效值初始化）→ **选预设**（即时生效、不经草稿、面板关闭）或 **自定义**（起 → 止两步，选完起自动进止）→ **应用**（写回已生效值）或 **取消**（丢弃草稿，已生效值不动）。**粒度切换不经过面板**（在时间条上即改即生效，见维度 9）；面板开着时切粒度，草稿从（可能已吸附的）新已生效值重新初始化。已生效值 = `S.repTime`（时点锚定日）+ `S.repRange`（期间起止，null = 预设）+ `S.repLabel`（预设名，null = 自定义） |
| 7 | 边界校验 | ① 起 ≤ 止：违反 toast「起需早于或等于止」拒绝，已生效值保持；② 期间跨度 ≥ 一个聚合桶：违反 toast「按 X 粒度的期间需不短于一个 X」拒绝；③ 月 / 年锚点：时点选月取月末、选年取 12-31（规则只在规范表，界面不写字幕）；④ 跨年期间：允许；⑤ 未来日期：允许录入（不禁用） |
| 8 | 两端同类控件清单 | 七件控件两端**同值**（实测）：时间条高 50 / 触发器 44 高（PC min-width 170、移动 flex 自适应——宽度是布局分配，高度与字号 fs-0 同值）/ 粒度分段键 44 高（可视宽 30，伪元素横向扩 7px/侧 → 热区 44×44）/ 箭头可视 32×44（伪元素横向扩 6px/侧 → 热区 44×44）/ 预设 chip 26.6 / 节标题 11px / 网格单元 29。清单 = 时间条、触发器、箭头、分段、chip、节标题、日历网格 |
| 9 | 粒度归属（第十五轮） | **粒度 = 常驻控件，归属时间条；面板只负责取值。** 用户方向：「平时就只切换粒度和左右箭头快速调整，如果需要自定义设置时，再点进去精细化配置」。时间条分段即改即生效（按新粒度重锚定当前值；已生效预设不兼容时按维度 3 吸附一次并 toast——面板内置灰、时间条上吸附，两种场景各走唯一规则不并存）；‹ › 箭头按粒度步进（日 ±1 天 / 月 ±1 月 / 年 ±1 年）即改即生效、不打开面板，时点步进后仍锚月末/年末。**面板内日历只展示「当前粒度及以下」的层级**：年 = 年步进 + 12 格年网格（无月无日）；月 = 年步进 + 12 格月网格（无日）；日 = 年步进 + 月网格 + 日网格；期间语义的起止两步各自满足同一条 |

副图口径：**支出与收入都用环形**，PC 左右并排、两环同尺寸（移动上下单列）。
每侧取一级根分类 Top 6 + 「其余 N 类」，切块与图例行都可下钻。两环中心各带一行
小字 **支出 / 收入** + 该侧合计（左 = 总支出、右 = 总收入），两个金额不写成同一副面孔。

**推翻「≤3 类或首项 >90% 不用环」**（原规则：收入通常 2 类、首项 99.3%，
环会退化成一条弧）：用户明确要求收入与支出**对称**，且退化场景的信息由
**中心合计 + 图例「名称 + 金额 + %」**承担，不需要靠横条长度补足。环仍保留
1.4° 保底切块，99.3% / 0.7% 也画成「完整环 + 极细弧」，不会退化成单弧。

**二级类别环**：点一级切块或一级图例行且该类别有子分类 → 该侧环切换为
**子分类构成**，中心改为「类别名 + 该类别合计」，并出现「‹ 返回一级 + 类别名」
面包屑（Esc 同效）。子分类最多 5 个 + 「其余」，配色走**父色同族明度阶梯**
（父色相固定、浅色由浅到深 / 暗色由深到浅，两端都不取父色本身），不重新分配 10 槽序列色；
**叶子类别（无子分类）不进空环**，点切块/图例行直接打开该类别流水下钻（与表格行行为一致）。二级不再有第三级环。

**保底角的分摊**：<2° 的切块按 1.4° 保底，多出来的角度**不是从最大块扣**，
而是按每块富余（`sweep − 1.4°`）占比分摊，富余为 0 的块不扣。当前数据实测扣除比例：
居住 77.1%（1.670°）、购物 16.7%、餐饮 3.7%、教育 2.1%、娱乐 0.4%；
医疗与「其余」富余为 0，故不扣。总留白 = 块数 × 1°。

**资产构成环（资产负债 tab）**：复用收支两环的同一套环形与图例，不另写一套。
切块口径由资产负债配置的「分组口径」决定——按性质汇总时环按性质切块，按账户时
环按账户切块，**表与环同源**，不存在只改表不改环的情况。按性质时点切块/图例行
先打开该性质的账户抽屉（账户数与合计必须与图例逐字段一致），抽屉里再点账户落流水；
按账户时直接落流水并带账户筛选。空态不画环；**只有 1 类时画 356° 弧 + 中心
「资产 · 仅 1 类」**，不把 360° 满环当成正常构成。信用账户为负债，不进资产构成环。

**PC 现金流桑基（现金流量 tab）**：三层「期初 → 流入 / 流出 → 期末」，
手续费与对账修正各为一条独立 link。口径 = **全账户净额**：期初 + 流入 − 流出 = 期末，
差额容差 ¥0.01；账户间转账是账户间资金移动，不进桑基、也不增减净额。
**不守恒就不画**：失败时展示明确的失败态（开发期直接抛断言），绝不静默画一张错的图。
现金流配置隐藏某个活动分组时，隐藏项**并入「其他（已隐藏 N 组）」并保持守恒**，
`N` 按被隐藏的活动分组数计（流入 / 流出只算一次；账户间转账被隐藏也计入，但它本身不进桑基），
下方流入 / 流出表仍按可见分组重算——图与表的合计可以不同，图上必须标出隐藏组数。

#### 视觉表达差异与取舍

- **PC 不用左右分栏放图**：左右分栏会把趋势图压到半宽，斜率被压扁；
  改成上下堆叠后图拿到整行全宽、表拿到整行全宽，代价是纵向变长——报表是「停下来读」的页面。
- **每张表的合计收在表尾**（`<tfoot>` 合计行）：数值右对齐、用底色与上边框区分合计语义。
  **底部独立的「收入合计 / 支出合计 / 结余」对照行已删除**（用户第三轮）：指标条已给结余、
  表尾已给合计，独立行是第三处冗余。两栏并排的表格统一遵守：① 行高固定（`--mb-tbl-row-h`），
  不因内容多被拉伸；② 两表合计行落在**同一水平线**（唯一对齐锚点），**不做等高拉伸**；
  ③ 行数少的一侧用**静默占位行**补齐，占位区无斑马纹、无边框、无 hover；
  ④ 列宽按语义权重分配（首列名称/分类最宽），超长内容**悬停 tooltip 显示全文 + 点击行进详情**，
  **不做行内展开**（行内展开会重新撑高行，与固定行高冲突）。
  口径说明两栏**共用一条**放表格外（`.tbl-note`），不进任何一栏——左右说明高度不一致会破坏合计对齐。
- **合计口径写进表下说明**：按一级父分类汇总（父级金额已含其子分类），因此折叠子行不改变合计；
  这句话必须跟着表走，否则用户会以为「折叠了合计没跟着变」是 bug。
- **移动端不靠一句话结论**：结论句是模板拼接，信息量与指标条重复且容易过期；
  改由「指标卡 + 表格 + 表尾合计」自己读出来，图退为佐证。
- **移动端图常驻、不做图/表切换**：切到表就等于把图藏起来，而图恰是结论的证据。
- 移动端细分段按钮而非上下两组表：并排读不了，上下堆叠又太长（第二张表要滚很久才看得见）。
- **时间选择器 = 一套组件，语义只差「面板里有无起止两步」**（第十四轮推翻重做）：此前
  时点 / 期间两套控件、PC 并排双 date 输入与移动起止两步并存、语义前缀与聚合后缀反复增删，
  根因是没有先立规范。现在四张报表共用 `timePanelHtml()` 一个渲染函数与同一组 class，
  语义差异被压缩到「自定义」节内有没有起 / 止 pill。
- **粒度外置到时间条（第十五轮维度 9）**：粒度切换与箭头步进是高频轻操作（「平时就只切换
  粒度和左右箭头快速调整」），藏在面板里要多点一次；自定义取值是低频重操作，才值得进面板。
  面板因此只剩「预设 + 日历」，日历按「当前粒度及以下」裁剪层级——年粒度下旧实现仍渲染
  月网格（`cal` 无条件拼接），根因即粒度长期待在面板里、层级裁剪规则缺位；外置后「面板只
  负责取值、取到当前粒度能用的层级为止」一条规则收敛。移动端 349px 时间条单行放得下
  箭头 + 值 + 分段三件（触发器 163 / 箭头 32×2 / 分段 92 / 间隙与内边距 44），最长起止
  文本不溢出，无需「值独占一行 / 分段第二行」的降级方案。
- **预设 × 粒度不兼容：面板内置灰、时间条上吸附（各一条唯一规则，见维度 3）**：面板内
  置灰让「为什么不能用」留在控件本身一眼可见；时间条上切粒度没有预设控件可置灰，失效的
  已生效预设吸附一次到该粒度默认预设并 toast 告知（不静默失败）。
- **时点语义下粒度是锚点精度，不是聚合桶**：按月 = 该月末、按年 = 该年末的余额快照，
  因此时点不存在「跨度 ≥ 一桶」校验；锚定规则只写规范表、界面不写字幕。
- **现金流指标四格等宽**（第六轮口径）：**期末现金总量 + 经营 / 投资 / 筹资净额**——
  「账户间转账」不占格（转账是账户间资金移动、不改变现金总量，仍单列流入 / 流出表）。
  期末现金总量口径 = 现金等价账户余额合计。
- **独立「现金流分类」表已删除**（第三轮）：经营 / 投资 / 筹资 / 未分类作为**一级分组**
  直接进入流入 / 流出表（分组行可折叠、子行是交易，与二级分类折叠同一套交互）——
  分组表本身已给出各类的流入与流出，独立净额表是同一件事的二次汇总。
  转账单列「账户间转账」组，不计入三类净额。
- **投资快照链只显示最近 6 期、无合计行**（第六轮）：每期是独立时点，跨期合计无意义；
  累计口径由指标条「累计收益率」承担。**第九轮起快照链不再单独成表**：投资分析主页面
  只保留一张持仓明细（`持仓 / 市值 / 成本 / 收益 / 收益率`），快照只以净值走势图呈现；
  完整快照仍在设置里维护。
- **现金流在窄屏降级为 Top 5 去向横条**（桑基在 390px 里标签会挤成一团）；
  超过 6 类聚合成「其他」，PC 端桑基遵守同一口径。

### W7 · 调预算与处理超支

#### 视觉表达差异与取舍

- 环形中心是**百分比**，下方是「已用 / 可花」——百分比用于快读，金额用于决策。
- **三类预算各自语义互不混用**：环形与「超支条目」只统计支出类（限额口径）；
  收入类展示「达成率」（低于目标才是告警方向）；转账类只做流量提示——
  三类混在一个百分比里会互相稀释，告警失去含义。
- **已用与总览同源**（B2）：预算页与总览预算卡同一派生函数、锚定当前日期——
  两页数字不一致（如 72% vs 2%）比没有预算页更糟；此前预算已用误随报表所选期间漂移，已修。
- 进度条颜色按占用率分档：< 80% 品牌绿，≥ 80% 琥珀，超支用支出红；
  超支行进度条填满 100%，溢出量用金额与「超支」标记表达，不画溢出段。
- **超支提示常驻在总量卡上**，写明哪个分类超了多少——超支是需要在总量层面被看见的事件。
- **超支必须给三个显式出口**（按实际调整 / 维持限额 / 查看流水），
  不能靠「什么都不做」默认处理；默认会把「没看见 / 看见了接受 / 还没想」压成同一种结果。
- 「维持限额」要回一句明确的话（「维持原限额 —— 本期仍标记为超支，作为已知告警」）。
- **调整只在条目内做**（第十七轮）：不设「调整所有预算条目」的统一入口——
  全局调整表把「改哪一条」和「改多少」拆成两步，且三类预算的语义差异在批量表里
  看不出来。条目详情内的额度输入 + 保存，就地重算该条目的用量与超支/达成/阈值反馈；
  本期已发生的交易不追溯，新额度只改变判定基线。
- **新增只有一个入口，且在页头**（第十八轮）：PC 原先的卡底 CTA 已删除——主操作
  沉在列表末尾要先滚过全部条目才看见（实测 top=975、视口 860）；移到页头与标题/期间同一带后
  恒在首屏，也与移动端页头「＋ 新增」同构。
- 移动端抽屉窄，底部对照条三格挤不下时**只收窄中间格并降一档字号**，不折行。

三步向导（居中弹层）：

```text
┌ 导入数据 ───────── ①选择文件 ─ ②预览与方式 ─ ③建回滚点 ─┐
│                                                        │
│  ① 选择文件                                             │
│  ┌──────────────────────────────────────────────┐      │
│  │   把 ZIP / CSV / JSON 拖到这里（整块可点）       │      │  ← B1：label 包裹，点击即开文件选择器
│  │   或点击选择文件（格式自动识别）                  │      │
│  └──────────────────────────────────────────────┘      │
│  ZIP=完整备份包 · CSV=单表流水 · JSON=结构化单表；        │
│  未选文件时「下一步」禁用，旁边提示「先选择文件」。          │
├────────────────────────────────────────────────────────┤
│  ② 预览与导入方式（仅预览前 5 行）                          │
│  识别到 128 笔：96 笔重复、32 笔新增；                     │
│  [合并] 按日期+金额+分类去重，重复跳过新增追加；            │
│  [覆盖] 整段替换文件声明期间，其余月份/余额/预算/设置保留。   │
├────────────────────────────────────────────────────────┤
│  ③ 建回滚点（清单而非表单）                                 │
│  回滚点   导入前自动备份（无需手动操作）                    │
│  影响范围  合并=追加 32 笔 / 覆盖=2026 年 10 月全部流水     │
├────────────────────────────────────────────────────────┤
│      [取消]      [确认合并导入 / 确认覆盖导入]              │
└────────────────────────────────────────────────────────┘
```

#### 移动（线框）

```text
╔═ 导入数据 ─ ① ─ ② ─ ③ ═╗
║  ① 选择文件                ║
║  ┌────────────────────┐   ║
║  │ 选择文件（系统文件选择器）║   ║  ← label 调系统选择器（触屏无拖放）
║  └────────────────────┘   ║
║  支持 ZIP / CSV / JSON · 合并 / 覆盖两种方式 ║
╟──────────────────────────╢
║  [取消]        [下一步]    ║
╚══════════════════════════╝
```

- 其余两步内容与 PC 相同，只是承载外壳换成抽屉。

#### 交互逻辑差异

| | PC | 移动 |
|---|---|---|
| 向导宿主 | 居中弹层（三步） | 底部抽屉（三步） |
| 选文件 | **拖放区整块可点**（B1：label 包裹 input，点击即开文件选择器；未选文件「下一步」禁用并提示「先选择文件」） | 系统文件选择器（触屏没有拖放） |
| 导入方式 | 第 2 步二选一：合并（去重追加）/ 覆盖（整段替换声明期间） | 同 |
| 导出 | 按钮 + toast（ZIP 备份，走系统另存） | 按钮 + 系统分享面板 |
| 回滚点恢复 | **两步确认**（T3：第一次点变「确认恢复」）；执行前自动创建「还原前」回滚点 | 同 |

#### 视觉表达差异与取舍

- 向导是**三步固定流程**，不是可跳步的自由表单——覆盖式操作最怕用户以为可以随便改。
- **影响范围要在每一步都说一次**（文案不同、事实相同），不能只在最后一步补一句。
- 第 2 步预览表必须标明「仅预览前 5 行」，并给出数字（识别多少笔 / 重复多少 / 新增多少 / 覆盖哪几个月）。
- 底部主动作文案必须带方式字样（`确认合并导入` / `确认覆盖导入`），不能是笼统的「确定」。
- **还原前自动再存一个回滚点**——还原本身也是一次数据变更，必须同样可撤回；两步确认防误触。
- 导出是只读操作，不走向导：一个按钮 + 一次 toast。

### W9 · 移动端单手全程（贯穿性约束）

移动端不是「PC 缩小版」，它有一条贯穿全部模块的**单手约束链**：

```text
┌─────────────────────────────────────────────┐
│  拇指可达区（下半屏）                          │
│  ┌───────────────────────────────────────┐  │
│  │  主操作区：FAB / 保存 / 确认            │  │  ← 落在下半屏
│  │  列表操作区：行内操作在行尾             │  │
│  └───────────────────────────────────────┘  │
│  上半屏：只读区（标题、指标、图表、表格）        │
└─────────────────────────────────────────────┘
```

| 环节 | 规则 | 依据 |
|---|---|---|
| 打开 | FAB 在底栏正中，56px | 拇指自然落点 |
| 输入 | 自绘数字键盘，金额框只读 | 系统键盘会遮住分类网格 |
| 选择 | 分类格放滚动区靠上但可点；行内操作收行尾 | 行尾也是拇指可达带 |
| 提交 | 抽屉底部 / 底栏之上固定 | 不需抬手 |
| 退出 | 下拉关闭抽屉（手势未实现，以 ✕ / 遮罩替代——P1）；<kbd>Esc</kbd> 仅 PC | 底部抽屉的自然手势 |
| 浏览 | 列表滚动 + 分段按钮切换 | 一次只处理一件事 |

**结论**：移动端所有「继续 / 确认 / 保存」类动作必须在下半屏；
上半屏留给不需要手的地方（读数字、读表、看图）。

## 5. 三态与空态（两端统一）

| 态 | PC | 移动 |
|---|---|---|
| 加载 | Skeleton（`role="status"` + `aria-busy`） | 同 |
| 空 · 冷启动 | 图标 + 标题 + 三步引导清单（建账户 → 记第一笔 → 看报表） | 同 |
| 空 · 无结果 | 图标 + 「没有匹配的记录」+ **清空筛选** | 同 |
| 错误 | `role="alert"` + 「数据没取出来」+ 重试 + 错误码 + 数据是否安全 | 同 |

- 三态**表达统一**，但**呈现尺寸**不同：移动端插画更小、说明文字一行内可读。
- 「无结果 ≠ 冷启动」是最常见的空态错误——用户搜了个不存在的词，
  系统却说「账本是空白的」，他会把账本误当成空的。
