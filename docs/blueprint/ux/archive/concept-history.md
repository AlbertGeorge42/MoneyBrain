## 6. 已确认项（Q1–Q5）

### Q1 · 移动端流水行的行内操作放哪？——**已确认（第六轮拍板）**

**结论：行内编辑 / 删除按钮整体移除（两端一致）——点击行进详情，编辑与删除都在详情里做（W4）。**

**理由**：行内操作列（原方案 A 的竖排两图标）实测让移动端标题 100% 截断；
而「改一笔」是低频动作，为它牺牲每一行的可读性不划算。移除后：
- 移动端行只剩 复选框 / 图标 / 文本 / 金额，标题完整显示（实测无截断）
- PC 行 hover 不再出现操作，整行可点进详情
- 批量选择（复选框）保留在行首，W3 不受影响
- W4 的详情面板（编辑 / 删除带撤销）成为唯一编辑入口

原方案记录（背景：UX2 §10「常驻不等于变挤」；实测 6 行标题全部 truncated，可见宽 52–100px）：

| 方案 | 说明 | 代价 |
|---|---|---|
| A（第三轮采用，第六轮推翻） | 行内操作收成行尾一列（竖排两小图标） | 行高 +20px，标题仍受挤 |
| B | 保持单行，收紧图标间距 + 缩到 20px 图标 | 违反「不缩小图标」，且仍截断 |
| C | 行内操作移到长按菜单 | 长按手势不可发现 |
| **D（第六轮拍板）** | **移除行内操作，点击行进详情** | 编辑多一跳；换来行可读性 |

### Q2 · 移动端的 toast 落在哪？——**已确认（第八轮拍板）：A，状态栏下方顶部横幅**

**背景**：原型实测移动端底部一带同时住 4 个东西——底栏（60px）+ FAB（56px）+ 批量条 + toast。

| 场景 | 实测重叠 | 说明 |
|---|---|---|
| 记账抽屉内报错 | toast ∩ 自绘键盘 = 11,522px² | 压住「0」「.」 |
| 批量模式 | 批量条 ∩ FAB = 2,128px² | FAB 被切一半 |
| 普通页 | toast ∩ FAB = 2,016px² | |
| 二级抽屉内 | toast ∩ 抽屉内容 = 4,242px² | 盖住输入框 |

结论：**toast 固定在状态栏下方顶部横幅**（唯一在所有状态下都不与底栏 / FAB / 抽屉 / 批量条冲突的位置）。
原备选记录：B 底部 + 表单错误内联（两套提示位置）/ C 全部顶部横幅（需重做出现位）——均不采用。
「第 N 笔已入账」维持内联在抽屉头部（与「已连记 N 笔」同位置），不走 toast。
**备注（评审轮 P9）**：顶部横幅让「撤销」按钮处于拇指不可达区——撤销的真实使用频次在 UX5b 观察，
若频次高再权衡位置与手势。

### Q3 · 批量模式下的 FAB 怎么处理？——**已确认（第六轮）：维持 A，进入批量模式隐藏 FAB**

原方案记录：A（采用）隐藏 FAB / B FAB 上移让位 / C 批量条改顶部横幅。

### Q4 · 移动端抽屉头的「已连记 N 笔」放在哪、怎么表达？——**已确认（第六轮）：维持现行实现**

抽屉头分两行——上行「记一笔 ✕」，下行左「已连记 N 笔」、右「第 N 笔 · 合计」（右半保留）。
原型内 `qtag` 标注已移除。

### Q5 · 移动端总览的「账户只列 4 个」是否够？——已被第三轮取代

原问题：UX3 §3 定「账户只列前 4」，是否需要「展开全部」。
**第三轮已把账户明细整体移出总览**（主区改净资产走势图，账户收成一行入口），
「列几个 / 展开全部」不再成立；UX3 §3 中「最近流水只列 4 笔」仍沿用。
