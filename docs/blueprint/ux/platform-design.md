# 平台设计：PC 与移动端（UX3）

> 这份文档回答：**为什么两端不一样**。
> 现状是移动端是 PC 界面的响应式缩放，PC 端是移动端界面的放大版。
> 本文给出两端各自的设计规范与差异理由。原型见 [prototype/index.html](prototype/index.html)。

---

## 1. 差异的理由：使用姿势不同

「响应式缩放」之所以是错的，是因为它假设**两端的使用场景相同，只是屏幕大小不同**。
实际不是。

| | PC | 移动 |
|---|---|---|
| 姿势 | 坐着、可能外接键盘、显示器远 | 站着或走着、单手、屏幕近 |
| 会话时长 | 长（几十分钟的复盘、配置） | 短（几十秒的记录与查看） |
| 输入 | 键盘 + 鼠标 | 触屏 + 数字键盘 |
| 主要动作 | **浏览与洞察** | **单手录入 + 快照式浏览** |
| 信息密度 | 高（能一屏承载对比） | 低（窄屏，横向空间稀缺） |
| 导航 | 侧栏（可容纳 5+ 项 + 二级） | 底部栏（拇指可达，最多 5 项） |

由此推导出的结论：**两端不是同一套页面的两种尺寸，是两套各自成立的设计**。

## 2. 导航

### PC

左侧固定侧栏，236px。品牌区 → 主导航 5 项 → 「记一笔」主按钮 → 底部状态（本月收支、连续记账天数）。

主导航项带**快捷键提示**（<kbd>1</kbd>–<kbd>5</kbd>），因为 PC 端键盘是一等公民。

选中态有三层信号：底色变化 + 文字变品牌深绿 + 左侧 3px 竖条。
仅靠底色不够——低对比度屏幕上底色变化识别度不足。

### 移动

底部导航 5 项 + **中央 FAB**（记一笔）。FAB 是圆形、56px、上浮出导航条，
落在拇指自然够到的位置。

> FAB 与导航条的关系不能是「导航的第 3 项」——它是**跨越导航的动作**，
> 所以视觉上必须脱离导航条的节奏（上浮 + 描边），否则用户会以为它是一个 tab。

选中态用**顶部指示条**（20×3px 品牌色）+ 文字变色 + 图标颜色。
不用底色块：底部空间窄，色块会挤压相邻项。

安全区用 `env(safe-area-inset-bottom)`，不写死数值。

## 3. 总览页

### PC：多栏对比

```text
┌─────────────────────────────────────────────┐
│  净资产主卡（最高层级卡片，大数字 + 环比 + 4 分项） │  ← hero 整行（第八轮重排）
├──────────────────────┬──────────────────────┤
│  本月预算（速览条目）    │  账户入口（一行）       │  ← 两栏
├──────────────────────┴──────────────────────┤
│  净资产走势（占位图，整行全宽）                  │
├─────────────────────────────────────────────┤
│  最近流水（整行）                              │
└─────────────────────────────────────────────┘
```

主卡是**最高层级卡片**——浅色用浅底（`surface-raised` + 边框 + 阴影），暗色用比普通卡片高一档的底色 + 1px 高光边；它是这一屏唯一的焦点，其余全是纸面。**不常驻深色反白**（浅色页面里的深色块会破坏主题一致性）。
分项（本月收入 / 本月支出 / 结余率 / 流动资产）在卡内横排，一屏读完。
**账户明细已整体移出总览**（用户第三轮）：余额是配置态数据，
在资产负债（时点快照）里看；总览只留一行账户入口（点击进设置）。

### 移动：快照式浏览

```text
┌─────────────────────────┐
│  净资产（一张卡）           │  ← 缩略版主卡
├───────────┬─────────────┤
│  本月收入   │  本月支出    │  ← 两张并排快照卡
├─────────────────────────┤
│  本月预算（速览）            │
├─────────────────────────┤
│  净资产走势（占位图）         │
├─────────────────────────┤
│  最近（几笔）               │
└─────────────────────────┘
```

关键差别：
- **无账户列表**（第三轮与 PC 同步移出）：总览回答「现在有多少」，
  账户明细去资产负债看。
- 金额缩到 28px（PC 是 40px）——移动端是**近看**屏幕，字号可以更大但数量要少。
- 表格全部降级为卡片行：PC 的「分类 / 金额」两列表格在 390px 宽里不可读，
  移动端改成「分类名 + 金额」一行 + 占比条一行。

## 4. 记账

### PC：居中对话框，键盘优先

600px 宽居中弹层。布局顺序即操作顺序：

```text
类型分段（支出/收入/转账/退款/调整）
─────────────────────────────
¥  [金额输入框]              ← 唯一焦点，40px 等宽数字
─────────────────────────────
分类网格 4×2（每格带 1–9 数字提示）
─────────────────────────────
[账户 chips · 常驻单行（最近使用 + 当前选中）]  全部账户 ›
手续费/优惠券/日期/备注  ▾
─────────────────────────────
[保存]  [保存并再记 ⏎]
```

金额输入 40px 等宽数字——它是这一屏唯一需要精确输入的东西，必须是视觉焦点。

### 移动：底部抽屉 + 数字键盘

抽屉是**三段式**，不是一整块滚动区：

```text
┌─────────────────────────┐
│  ▁▁▁（拖拽条）              │  ← 固定头
│  记一笔              ✕     │
├─────────────────────────┤
│  类型分段                  │
│  ¥ [金额]                │  ← 滚动区（与键盘同屏）
│  分类网格                 │
│  [账户胶囊]               │
│  手续费/优惠券 ▾          │
├─────────────────────────┤
│  ┌───┬───┬───┐            │  ← 固定底
│  │ 7 │ 8 │ 9 │            │  自带数字键盘
│  ├───┼───┼───┤            │  不调起系统键盘
│  │ 4 │ 5 │ 6 │            │  少一次焦点切换
│  ├───┼───┼───┤            │
│  │ 1 │ 2 │ 3 │            │
│  ├───┼───┼───┤            │
│  │ . │ 0 │ ⌫ │            │
│  └───┴───┴───┘            │
│  [保存并再记]              │
└─────────────────────────┘
```

差别与理由：
- **自绘数字键盘**：系统键盘会占据屏幕一半并遮挡分类网格，自绘键盘让
  「金额 + 分类」在一屏内可见——这是移动端能保持 3 步的关键。
- **键盘常驻在固定底**：抽屉高度 = 头部 + 滚动区 + 键盘区。
  滚动区只装「类型 / 金额 / 分类 / 账户 / 更多」，
  键盘与保存按钮钉在底部——滚动时键盘不会消失，否则「输金额 → 选分类」
  这条主路径会被迫上下滑动，与 PC 的三步节奏脱节。
- **金额框是只读显示**：数字由自绘键盘输入，输入框再获得焦点就会调起
  系统键盘，系统键盘会盖住分类网格——这是自绘键盘要解决的核心问题，
  不能留后门。
- 底部抽屉而非居中弹窗：抽屉的底边就是拇指落点，保存按钮直接在拇指下。
- 抽屉底部留 `env(safe-area-inset-bottom)`。

## 5. 报表

两端**骨架一致**（时间条 → 指标 → 图 → 表），但呈现完全不同。

### PC：指标条 + 图在上、表在下

```text
时间条（‹ 值 ▾ › + [日|月|年] 粒度分段常驻）
┌────────────────────────────────────────────────────────┐
│ 本期结余   │ 本期收入 │ 本期支出 │ 储蓄率 │              │  ← 指标条 1+3
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────┐
│  主图（趋势）—— 横跨整行全宽             │
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│  副图（构成）                           │
└────────────────────────────────────────┘
┌──────────────────┬─────────────────────┐
│  收入表（表尾合计行）  │  支出表（表尾合计行）    │  ← 两栏并排（行高固定）
└──────────────────┴─────────────────────┘
```

**为什么是「图在上、表在下」而不是左右分栏**：
左右分栏（1.5:1）把图压到半宽，时间序列的斜率与波动被压扁；
而明细表在窄栏里只有两列，父行 + 二级子行的层级挤在一起读不下去。
改为上下堆叠后：图拿到**整行全宽**（趋势看得清），表拿到**整行全宽**（层级放得开），
代价是纵向滚动变长——但报表是「停下来读」的页面，纵向滚动符合阅读习惯。

**指标为什么是「一条」而不是「一排卡片」**：
4 张等权卡片会互相抢注意力，且逼用户逐张扫。改成**单一容器的指标条**：
容器内用发丝分隔线切成 **1+3 四格**（第一轮定稿；洞察型第五格已随 Q7
「一句话结论移除」删除）——主指标（本期结余）占更宽的一格并用更大字号，
3 格数字（收入 / 支出 / 比率）。

明细表仍保持**两栏并排**（收入表 | 支出表），因为两者的核心动作是**对照**：

| 报表 | 左表 | 右表 |
|---|---|---|
| 收支 | 收入表 | 支出表 |
| 现金流 | 流入表 | 流出表 |
| 资产负债 | 资产表 | 负债与权益 |

> 资产负债的两表是「资产 / 负债与权益」，并排才能直接看出净资产。
> 现金流的两表是「流入 / 流出」，并排才能直接看出净额。
> 收支的两表是「收入 / 支出」，并排才能直接看出结余。

**两栏怎么保证底部对齐**：
两栏并排，但**不做等高拉伸**；统一遵守以下规则（验收见 [interaction-spec §5.3](interaction-spec.md)）：
① 行高固定（`--mb-tbl-row-h`），不因内容多被拉伸；② **合计收进各表表尾**（`<tfoot>`，第三轮定稿），
两表合计行落在**同一水平线**（唯一对齐锚点）；③ 行数少的一侧用**静默占位行**补齐，
占位区无斑马纹、无边框、无 hover；④ 列宽按语义权重（`table-layout:fixed` + `colgroup`），
超长内容悬停/键盘聚焦显示全文 tooltip、点击行进详情，不做行内展开。数值右对齐、用底色与上边框区分合计语义。
卡片底部的跨栏**对照条已删除**（第三轮）——指标条已给结余、表尾已给合计，对照条是第三处冗余。
不设全局「展开全部 / 折叠全部」控件（原型现状：折叠是逐项的阅读动作）。

**二级子项可折叠**：父行左侧有折叠箭头，点击只收起该父项的二级子行，
父行的合计金额始终可见。
折叠状态按「报表:表名:父项」存放，切换报表互不干扰。

### 移动：指标卡 + 明细分段按钮

```text
时间条（同 PC：‹ 值 ▾ › + [日|月|年]）
指标卡（主指标占满行，其余 2×2）
[横滑] 主图 → 副图                                    ← 图常驻，作为佐证
┌────────────────────────────────────────┐
│  [ 收入 | 支出 ]                       │  ← 分段按钮，一次只看一张表
│  餐饮          −312.00    ▾            │
│    └ 公司食堂    −56.00                │
│  购物          −328.60    ▸            │
└────────────────────────────────────────┘
```

差别与理由：
- **不靠一句话结论**（Q7 已删）：结论句是模板拼接，信息量与指标条重复且容易过期；
  改由「指标卡 + 表格 + 表尾合计」自己读出来，图退为佐证。
- **图常驻，不再有「图 / 表」切换**：窄屏切到表就等于把图藏起来，
  而图恰好是证据；代价是页面更长，所以用**分段按钮 压缩表的体量**。
- **指标卡 2 列**，主指标（本期结余）占满整行。
- **明细用分段按钮 而不是上下两组**：PC 的两栏表在窄屏里并排读不了，
  上下堆叠又太长（收入表 + 支出表要滚很久才看得见第二张）。
  分段按钮 把它变成「一次一张」，切换是 O(1) 的。
  三张报表各有自己的分组：收支 = 收入/支出，现金流 = 流入/流出，
  资产负债 = 资产/负债与权益；投资分析只有一张持仓明细，不需要 tab。
- **父行显示合计 + 占比条 + 折叠箭头**，二级子项默认展开（与 PC 一致——
  「表」视图是明确要看明细的场景，展开即所见）。
- 点击箭头收起该父项的子项，其余保持不变。
- 父子行用虚线分隔 + 缩进 26px，层级靠缩进与线型区分，不靠颜色。

### 现金流量在窄屏的降级（承接 E6）

PC 用桑基图展示资金流向。窄屏放不下桑基（节点标签会挤成一团），
移动端改为 **Top 5 去向横条**：

- 保留「钱去哪了」这个认知，牺牲完整流向。
- 超过 6 类自动聚合为「其他」——PC 端桑基也遵守同一规则，两端口径一致。

### 资产负债的点时态

资产负债是**某一时点的快照**，不是一段时期的流水。它与其它报表共用同一条
时间条（含日 / 月 / 年粒度，第十三轮起），但粒度语义不同：**粒度 = 锚点精度**——
按日 = 当日、按月 = 该月最后一天、按年 = 该年 12-31 的余额快照
（`snapPointToGran` 自动锚定），期间报表的粒度才是聚合桶。
锚定规则只写概念稿规范表，界面不写字幕。

## 6. 交互模式差异

| 维度 | PC | 移动 |
|---|---|---|
| 记账载体 | 居中对话框 | 底部抽屉 |
| 数字输入 | 系统键盘 + 回车 | 自绘数字键盘 |
| 行内操作 | **无**（第六轮拍板 Q1：点行进详情，编辑/删除都在详情里） | 同 |
| 批量选择 | 工具栏「批量」 | 「筛选操作区」内「批量」 |
| 行点击 | 批量模式=勾选 / 平时=进详情 | 同 PC（卡片行本身就是入口） |
| 高级筛选 | 工具栏下方**内联面板** | **底部抽屉**（含类型筛选，第十六轮补齐） |
| 报表明细 | 完整表格（两栏并排 + 固定行高 + 合计行底部对齐） | 卡片行 / 分段按钮 一次一张表 |
| 图表对比 | 上下堆叠（图整行全宽） | 横向滑动 |
| 时间选择 | 时间条（箭头+值+粒度分段）+ 浮层面板 | 同一时间条 + 底部抽屉（同一渲染函数） |
| 设置 | 左导航 7 分区 + 右内容（一次一屏） | 列表 → **全屏二级页**（7 个，同组同序同名） |
| 预算编辑 | 右侧面板 | 底部抽屉 |
| 预算总量 | 环形进度（大）+ 按类型分组条目 | 环形进度（150px）+ 分组卡片 |
| 覆盖导入 | 居中弹层（三步向导） | 底部抽屉（三步向导，Q6 拍板维持） |
| 主操作位置 | 侧栏底部 | 底部正中 FAB |
| 浮层宿主 | 右侧面板 / 居中弹层 | 底部抽屉 + 全屏二级页（设置配置中心） |

### 6.1 浮层宿主：一份内容，两处外壳

同一个交互在两端**内容逻辑唯一**，只有承载外壳不同：

| 宿主 | 承载的交互 | 理由 |
|---|---|---|
| PC 右侧面板 | 详情 / 编辑 / 下钻 / 预算 / 账户 / 回滚点 / 配置中心 | 面板不遮挡左侧导航，用户能同时看到自己在哪 |
| PC 居中弹层 | 导入向导 / 批量改分类 / 移动到… / 删除确认 | 这类操作要打断当前上下文，需要一个明确的「你现在在做一件事」的框 |
| 移动底部抽屉 | 详情 / 编辑 / 下钻 / 选值 / 确认 / 报表时间条右端 ⚙ 原地设置 | 底部上滑是移动端唯一可靠的手势；底部就是拇指落点 |
| 移动全屏二级页 | 设置 7 分区（配置中心 4 + 通用 3，评审轮载体分置） | 配置是「进去做完一件事」的任务型页面，占满机身、页头 ‹ 返回 |

移动端不设居中弹层：390px 宽的屏上，居中弹层的高度会被系统输入法和
安全区反复挤压，而底部抽屉可以贴着拇指且能用「下拉关闭」退出。
（原型的批量确认等居中型 modal 仅 PC 呈现，移动端同内容走抽屉壳。）

### 6.2 行的两种语义

流水行同时是**入口**和**选择目标**，所以必须有明确的模式区分：

- 平时点行 → **进详情**（移动端表格降级成卡片行后，行本身就是入口）。
- 批量模式点行 → **勾选**（复选框出现并显隐）。

这个区分不是细节：把两种语义混在一个手势上，用户在批量模式下会
误进详情页，批量操作就无从谈起。

### 6.3 筛选条件的可见性

高级筛选在 PC 是内联面板、在移动端是抽屉，但**生效后的条件必须在
列表上方显式可见**（chip + 单条清除 + 全部清除），不能只给一个数字徽标。
从报表下钻跳到流水时尤其重要——用户需要看到「正在按 餐饮 过滤」这件事本身。

## 7. 触控与可达性（U6、U7 在 R2/R3 验收；UX5b）

- 触控目标 ≥ **44×44**：移动端的图标按钮、chip、筛选项、方向键、分段按钮、
  数字键盘、折叠箭头全部按此尺寸实现。
- **`:hover` 只在 `@media (hover:hover)` 内生效**。触屏上 hover 永不触发，
  因此行内操作按钮在触屏设备上常驻——把唯一入口藏在 hover 里等于功能不存在。
- 焦点可见：`:focus-visible` 统一 2px 品牌色描边 + 2px 偏移。
- 尊重 `prefers-reduced-motion`：命中时关闭所有动画与过渡。

## 8. 断点

单一断点源（原 U2/U3，现为 [dev-guide §2.2](../../dev-guide.md) 的原则）：

| 断点 | 值 | 用途 |
|---|---|---|
| `sm` | 640px | 手机横屏 |
| `md` | 768px | 平板 |
| `lg` | 1024px | 桌面 |
| `xl` | 1280px | 大屏 |

**PC 布局在 < 1024px 时降级为单栏**（侧栏收起、内容单列）；
**移动端形态不做响应式缩放**——它是独立设计，由设备模式切换而非断点触发。
