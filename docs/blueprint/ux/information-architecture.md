# 信息架构（UX1）

> 这份文档回答：**这个产品该怎么组织信息**。
> 它是主导航结构、页面层级、每个页面的职责边界与「为什么它在这一层」的推导依据。
> 新增功能时按 §5 判断它该放在哪；两端导航与设置分区已按本文实现（见 §7）。
> 视觉 token 具体值查 [design-tokens.md](design-tokens.md)，交互细节查 [interaction-spec.md](interaction-spec.md)。

---

## 1. 推导：从「需求累积」到「按用途组织」

现状是每加一个功能多一个页面或一个弹窗：账户、分类、投资、报表、预算、设置各占一处，
报表页里又内嵌配置弹窗。页面数量是需求的**结果**，不是设计的**结论**。

重新推导的起点是产品的实际用途。这个应用的核心是「**金额 + 账户 + 时间**」，
用户来这里的动作只有三类，且优先级明确：

| 动作 | 频率 | 对时间的要求 | 对数据量的要求 |
|---|---|---|---|
| **记一笔** | 高频、连续、成组 | 记当下 | 无 |
| **看现在有多少** | 中频 | 看此刻 | 一屏说完 |
| **看懂钱去哪了** | 低频、但决定信任 | 看一段 | 可对比、可下钻 |

据此，主导航按**用户意图**而非**数据实体**划分。数据实体（账户、分类、投资）
是「看」这一类动作下的不同切面，不是并列的一级目的地。

## 2. 主导航结构

```text
┌─ 总览 ──────────────┐  此刻有多少？钱从哪来、到哪去
│  ├─ 净资产主卡       │  一个数字 + 环比 + 四个分项
│  ├─ 净资产走势占位图  │  账户明细已移出总览（用户第三轮）：余额是配置态数据
│  └─ 最近流水         │  最近几笔，带「全部 →」跳转；账户收成一行入口（进设置）
│
├─ 流水 ──────────────┤  每一笔交易的清单
│  ├─ 搜索框          │  备注 / 账户名 / 分类名 / 金额
│  ├─ 类型筛选         │  全部 / 支出 / 收入 / 转账 / 退款 / 调整（PC 平铺 tab；移动收进筛选抽屉，第十六轮补齐类型项）
│  ├─ 按日分组         │  每天一个小计
│  └─ 批量操作条       │  删除（有确认）为主入口，改分类在「⋯ 更多」里
│
├─ 报表 ──────────────┤  一段时期的钱
│  ├─ 时间条          │  ‹ 所选值 ▾ › + 粒度分段（日/月/年常驻时间条，第十五轮维度 9）；
│  │                  │  语义二分：资产负债 = 时点（锚定日）、其余 = 期间（起止）
│  ├─ 收支明细        │  趋势 + 分类构成 + 分类明细
│  ├─ 现金流量        │  桑基 / Top N + 三类现金流 + 流向明细
│  ├─ 资产负债        │  净资产走势 + 资产结构 + 科目明细（点时态）
│  └─ 投资分析        │  市值趋势 + 持仓分布 + 持仓明细
│
├─ 预算 ──────────────┤  计划 vs 实际（三类预算：支出 = 限额、收入 / 转账 = 计划跟踪，评审轮拍板）
│  ├─ 预算总览环
│  └─ 按类型分组的预算条目（名称 + 类型 + 金额 + 周期 + 分类 + 账户）
│
└─ 设置 ──────────────┤  配置（见 §3：7 分区 = 配置中心 4 + 通用 3）
   ├─ 配置中心         │  账户分类 / 收支分类 / 现金流分类 / 投资资产类型
   └─ 通用            │  列表显示 / 数据与备份 / 回收站
```

**记账不在导航里。** 它是一个跨页面可随时发起的动作：
PC 端是侧栏底部的常驻按钮 + 快捷键 <kbd>N</kbd>，
移动端是底部导航正中的 FAB。
理由：记账是「翻开账本写一笔」，不是「去某个页面办理」。

## 3. 设置的分组原则（承接 E4）

现状是设置页承载全部配置，同时报表页内嵌配置弹窗——同一个配置有两个入口，
用户不知道该改哪个。

规则：**同类配置只有一个权威入口。** 设置页为 **7 分区**（第十二轮定稿）：
配置中心 4 项（账户分类 / 收支分类 / 现金流分类 / 投资资产类型）+ 通用 3 项
（列表显示 / 数据与备份 / 回收站），PC 左导航与移动端列表同组同序同名。

| 分组 | 内容 | 归属理由 |
|---|---|---|
| 账户分类 | 账户分类增删改、账户挂分类（分类带现金等价 / 投资标记） | 账户是「看」类动作的切面，不是独立目的地 |
| 收支分类 | 收支分类树（递归层级）、退款/调整复用普通分类 | 同上 |
| 现金流分类 | 活动归属（经营/投资/筹资/未分配）与资产标记，移动即改归属 | 口径标记的唯一编辑入口 |
| 投资资产类型 | 资产类别、目标比例 | 口径与快照的录入入口 |
| 列表显示 | 流水列显隐 / 密度 | 显示偏好 |
| 数据与备份 | 备份与恢复、导入、回滚点、导出、危险操作 | 生命周期管理 |
| 回收站 | 删除内容的恢复 | 同上 |

**报表页时间条右端「设置」保留展示配置，并新增「账户与分组」「收支分类」两条账本数据入口**
（与设置页配置中心**同源同交互**：同一份 controller、同一套表单与校验，保存立即生效）。
本轮不做按报表 tab 的上下文映射，也不开放现金流分类 / 投资资产类型的报表入口——
「在报表里调」仍不算第二个配置中心。

## 4. 账户的归属：并入总览，不独立成页

账户容易被做成独立页面（「账户管理」），但账户本身没有独立的任务——
用户不会以「打开账户页」为目的而来，他们要么在总览问「我有多少钱」，
要么在设置里改账户定义。

因此：
- **看账户** → 总览页的账户行入口（账户明细第三轮已移出总览，余额在资产负债看）
- **改账户** → 设置 / 账户分类

总览页的账户行点击后进设置，而不是就地展开编辑表单。
这是 E4「同类配置只有一个权威入口」的延续。

## 5. 新功能该放哪：归属判断表

新增功能时，按下表定位，不必再问「要不要新建一个页面」。

| 新功能 | 归属 | 理由 |
|---|---|---|
| 新增账户类型 / 改账户口径 | 设置 / 账户 | 配置类，改的是定义不是数据 |
| 新增统计口径 | 设置 / 对应分组 + 报表内只读 | 定义在设置，呈现按分组 |
| 新增交易字段（如标签） | 记账「更多」折叠区 + 设置 / 分类 | 低频输入不进主路径；定义归设置 |
| 新增筛选维度 | 流水页筛选条 | 属于「找一笔」的动作 |
| 新增报表视图 | 报表页内的时间条下平级标签 | 报表是同源数据的不同切面 |
| 新的业务对象（如储蓄目标） | 先问「它是不是金额+账户+时间」 | 是→进总览/报表；不是→独立一级页 |

**判断原则**：先问「这是**看**、**记**、还是**配**」；
「看」进总览/报表，「记」进记账浮层，「配」进设置。
只有三者都不是时才新建一级页面。

## 6. 层级约束

1. **一级导航恒为 5 项**（总览 / 流水 / 报表 / 预算 / 设置）。
   移动端同样是 5 项 + 中央 FAB，不做数量差异。
2. **二级结构不超过两层**。报表的四个视图是平级标签，不是嵌套菜单。
3. **每个页面有且只有一个主任务**。总览主任务是「回答我现在有多少」，
   流水是「找到并处理某一笔」，报表是「读懂一段时期」。
4. **不设面包屑**。层级只有两层，面包屑只会占掉垂直空间。
