# 信息架构（UX1）

> 这份文档回答：**这个产品该怎么组织信息**。
> 它是主导航结构、页面层级、每个页面的职责边界与「为什么它在这一层」的推导依据。
> 段三（U4–U12）实现时按本文档落地；新增功能时按 §5 判断它该放在哪。

---

## 1. 推导：从「需求累积」到「按用途组织」

现状是每加一个功能多一个页面或一个弹窗：账户、分类、投资、报表、预算、设置各占一处，
报表页里又内嵌配置弹窗。页面数量是需求的**结果**，不是设计的**结论**。

重新推导的起点是产品的实际用途。这个应用的核心是「**金额 + 账户 + 时间**」，
用户来这里的动作只有三类，且优先级明确：

| 动作 | 频率 | 对时间的要求 | 对数据量的要求 |
|---|---|---|---|
| **记一笔** | 高频、连续、成组 | 记当下 | 无 |
| **看现在有多少** | 中频 | 看此刻 | 一屏说完 |
| **看懂钱去哪了** | 低频、但决定信任 | 看一段 | 可对比、可下钻 |

据此，主导航按**用户意图**而非**数据实体**划分。数据实体（账户、分类、投资）
是「看」这一类动作下的不同切面，不是并列的一级目的地。

---

## 2. 主导航结构

```text
┌─ 总览 ──────────────┐  此刻有多少？钱从哪来、到哪去
│  ├─ 净资产主卡       │  一个数字 + 环比 + 四个分项
│  ├─ 账户总览         │  资产快照，按账户列余额（不可编辑，见 §4）
│  └─ 最近流水         │  最近 5 笔，带「全部 →」跳转
│
├─ 流水 ──────────────┤  每一笔交易的清单
│  ├─ 搜索框          │  备注 / 账户名 / 分类名 / 金额
│  ├─ 类型筛选         │  全部 / 支出 / 收入 / 转账 / 退款 / 调整
│  ├─ 按日分组         │  每天一个小计
│  └─ 批量操作条       │  改分类 / 删除（有确认）
│
├─ 报表 ──────────────┤  一段时期的钱
│  ├─ 时间条          │  ‹ 期间标签 ▾ › + 粒度（日/月/年）
│  ├─ 收支            │  趋势 + 分类构成 + 分类明细
│  ├─ 现金流          │  桑基 / Top N + 三类现金流 + 流向明细
│  ├─ 资产负债        │  净资产走势 + 资产结构 + 科目明细（点时态）
│  └─ 投资分析        │  市值趋势 + 持仓分布 + 持仓明细
│
├─ 预算 ──────────────┤  计划 vs 实际（只管支出）
│  ├─ 预算总览环
│  └─ 分类预算行
│
└─ 设置 ──────────────┤  配置（唯一权威入口，见 §3）
   ├─ 账户
   ├─ 分类
   ├─ 投资
   ├─ 数据
   └─ 外观
```

**记账不在导航里。** 它是一个跨页面可随时发起的动作：
PC 端是侧栏底部的常驻按钮 + 快捷键 <kbd>N</kbd>，
移动端是底部导航正中的 FAB。
理由：记账是「翻开账本写一笔」，不是「去某个页面办理」。

## 3. 设置的分组原则（承接 E4）

现状是设置页承载全部配置，同时报表页内嵌配置弹窗——同一个配置有两个入口，
用户不知道该改哪个。

规则：**同类配置只有一个权威入口。**

| 分组 | 内容 | 归属理由 |
|---|---|---|
| 账户 | 账户增删改、账户类型与计入口径 | 账户是「看」类动作的切面，不是独立目的地 |
| 分类 | 收支分类树、二级类别、图标 | 同上 |
| 投资 | 资产类别、净值快照 | 口径与快照的录入入口 |
| 数据 | 备份与恢复、覆盖导入回滚点、导出、危险操作 | 生命周期管理 |
| 外观 | 主题、密度 | 显示偏好 |

**报表页只留跳转链接，不内嵌配置弹窗。** 报表是「看」的页面，
在那里改口径等于让用户在没有上下文的地方做系统级修改。

---

## 4. 账户的归属：并入总览，不独立成页

账户容易被做成独立页面（「账户管理」），但账户本身没有独立的任务——
用户不会以「打开账户页」为目的而来，他们要么在总览问「我有多少钱」，
要么在设置里改账户定义。

因此：
- **看账户** → 总览页的「账户总览」卡片（只读快照）
- **改账户** → 设置 / 账户分组

总览页的账户卡片上的「管理账户 →」跳到设置，而不是就地展开编辑表单。
这是 E4「同类配置只有一个权威入口」的延续。

## 5. 新功能该放哪：归属判断表

段三及以后新增功能时，按下表定位，不必再问「要不要新建一个页面」。

| 新功能 | 归属 | 理由 |
|---|---|---|
| 新增账户类型 / 改账户口径 | 设置 / 账户 | 配置类，改的是定义不是数据 |
| 新增统计口径 | 设置 / 对应分组 + 报表内只读 | 定义在设置，呈现按分组 |
| 新增交易字段（如标签） | 记账「更多」折叠区 + 设置 / 分类 | 低频输入不进主路径；定义归设置 |
| 新增筛选维度 | 流水页筛选条 | 属于「找一笔」的动作 |
| 新增报表视图 | 报表页内的时间条下平级标签 | 报表是同源数据的不同切面 |
| 新的业务对象（如储蓄目标） | 先问「它是不是金额+账户+时间」 | 是→进总览/报表；不是→独立一级页 |

**判断原则**：先问「这是**看**、**记**、还是**配**」；
「看」进总览/报表，「记」进记账浮层，「配」进设置。
只有三者都不是时才新建一级页面。

---

## 6. 层级约束

1. **一级导航恒为 5 项**（总览 / 流水 / 报表 / 预算 / 设置）。
   移动端同样是 5 项 + 中央 FAB，不做数量差异。
2. **二级结构不超过两层**。报表的四个视图是平级标签，不是嵌套菜单。
3. **每个页面有且只有一个主任务**。总览主任务是「回答我现在有多少」，
   流水是「找到并处理某一笔」，报表是「读懂一段时期」。
4. **不设面包屑**。层级只有两层，面包屑只会占掉垂直空间。

## 7. 与现有实现的对应

本文档描述的是**重设计后**的结构。当前实现（`apps/web/src/pages`）的
Dashboard / Transactions / Reports / Budgets / Settings 五个页面与之一一对应，
但语义有偏差：

| 现状 | 与本文档的偏差 |
|---|---|
| 账户管理散落在总览与设置弹窗 | 总览只读、设置唯一可编辑（§4） |
| 报表页内嵌配置弹窗 | 配置迁出到设置（§3） |
| 报表四个视图名为「资产负债表/收入支出表/现金流量表/投资分析表」 | 改为按用途命名：资产负债 / 收支 / 现金流 / 投资分析 |
| 无「投资」设置分组 | 新增（§3） |
