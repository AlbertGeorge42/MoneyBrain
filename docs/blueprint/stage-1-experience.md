# 阶段 1 · 体验、界面与桌面化（M2）

> **目标**：让 MoneyBrain 在 PC 上成为一个**能独立用一整年**的产品——
> 不是"能跑的 Demo"，是装得上、记得快、找得到、信得过、愿意每天打开的东西。
>
> 这一阶段**不增加新的业务功能**。周期交易、标签、多账本、储蓄目标、票据、
> 按范围备份、待付款清单全部推迟（见 [stage-4](stage-4-expansion.md)）。
>
> **为什么先收拾界面、后加功能**：
>
> - 界面层的债**越往后越贵**。现在有 66 个组件文件（其中 58 个 `.tsx`）、15 个 CSS 文件共 1787 行、320 处内联样式
>   （统计于 2026-10-28：`apps/web/src` 下按扩展名计数 + 统计 CSS 行数 + grep `style={{` 出现次数）。
>   拖到移动端做完再统一，等于两个端各改一遍。
> - 新功能可以按需再加；**加了之后还得在统一的地基上写**。地基不干净，加一个功能
>   就要在 320 处内联样式里再添一笔。
> - 界面债与业务债的代价不同——业务债让数字错，界面债让用户**不敢用**。
>   一个数字对但点不动、加载时闪空白、暗色模式看不清的账本，用户还是会弃用。

## 差距清单

### 批次 U · 界面重做（地基 → 重设计 → 落地）

这一批是一条流水线的三段，**按序执行**：

- **段一 · 地基（U0–U3）**：把实现方式改对——命名空间隔离、引用完整性、设备判定单入口。
  这些不产生视觉决策，但它们是重设计的前置：设备判定没有单入口，原型画出来就作废。
- **段二 · 重设计（UX1–UX5b）**：把设计本身重做一版——信息架构、记账交互、跨平台差异、
  视觉语言、线框级概念稿（UX5a）、组件库驱动的可运行高保真页面（UX5b）。
  **这一段不改应用代码**，产出设计决策与原型（例外：U13.1 是 UX5b 的接入前置，只搭主题/Provider，不改页面观感，见段三）。
- **段三 · 落地（U4–U13）**：出口是「能干净地切到原型版本」——只保留机制与能力，
  旧页面的视觉收口一律取消或挂到 UX5b（三档见本段开头）；U13 是组件库迁移
  （AntD → Mantine 8），即「切换新界面」的实现本体。

段一与段三延后档的验收不是"好看"——好看没法自动化验收。拆成三类可验证的目标：

- **正确**：不存在失效变量、幽灵样式、死代码；同一语义只有一处实现。
- **可用**：键盘能到达每一个可操作元素，焦点始终可见；加载/空/错三态齐全且一致。
- **一致**：间距、字号、圆角、阴影、图标、动效全部来自 token，不存在硬编码与第二套来源。

这三类目标共同对应[蓝图入口 §4](../rewrite-blueprint.md) 不变量 12「界面不骗人」；
U7 的焦点可见性与 UX5b 的三态一致是其中可自动化验收的部分。

#### 段一 · 地基（已收口：U0/U1/U1b 完成，U2–U3 降为原则）

##### U2–U3 · 设备判定单入口（降级为原则，不再作为条目）

原型双端是**两套独立结构**，不是响应式断点（见 [concept §8.1](ux/concept-design.md)）。
「三套断点并存」的冲突由结构本身消除；原计划的「16 处媒体查询裸数字 token 化 +
PostCSS 构建期解析」失去对象，**不执行**。

只保留一条机制原则（已写入 [dev-guide](../dev-guide.md) §2.2）：

> **设备判定只有一个入口**：JS 判定与 CSS 表现必须同源。新实现若仍有断点，
> 先立一个设备判定入口（单一常量 + 单一组件），不允许第二套判定
> （`Grid.useBreakpoint()` 与自建 hook 混用、CSS 裸数字各自为政）。

迁移前的现状（留作回溯）：自建 `useIsMobile`（860px）、AntD `Grid.useBreakpoint()`（768px）、
16 处 CSS 媒体查询裸数字（480/680/860/1100）——768–859px 区间 JS 判定与 CSS 表现结论相反。

#### 段二 · 重设计（UX1–UX5b，不改代码）

**为什么要有这一段**：界面是「加功能加出来的」，没有经过整体设计。
66 个组件文件、15 个 CSS 文件、320 处内联样式——每个都是需求驱动的补丁，
没有任何一页是「先设计、后实现」的。段一修完之后，界面**依然只是现在这版界面**：
信息架构、视觉语言、交互模式都还是历史遗留。

- **应用特性没有被设计容纳**。这个应用的核心是「金额 + 账户 + 时间」，
  但界面是按通用 CRUD 做的：列表页、详情页、表单页。
  记账是**高频、连续、有状态**的动作——交互模型应该像记账本，不像管理后台。
- **不同平台没有各自的设计**。桌面端是「浏览 + 偶尔录入」，移动端是「单手 + 频繁录入」——
  信息密度、导航方式、主要动作的位置应是**不同的设计**，不是同一套的响应式缩放。
- **没有原型，UI 改造就变成反复重写**。段三要动 66 个组件；设计方向没定，改完还得再改。

**这一段不改应用代码**，产出设计决策与原型（UX5a 线框；UX5b 的可运行页面是原型，
不进应用构建）；应用内实现由切换后的新实现承接。**唯一例外是 U13.1**（主题骨架接入）：
它只替换主题 / Provider / 图表取色，不改页面观感，是 UX5b 的前置。
因此验收是「文档覆盖度」与「原型可走查」，不是自动化测试。

#### 段三 · 落地（U4–U13）

**这一批的出口是「能干净地切到原型版本」，不是「旧页面视觉收口」。** 前端后续整体
切换到原型设计版本（UX5a 线框 → UX5b 高保真），旧页面的观感在切换后不存在对象。
因此本段按三档处理：

- **取消（U5、U8、U9、U10、U11）**：验收对象是旧页面的观感——死 CSS、三态表达、
  卡片/图标/过渡统一、旧图表暗色调色板、移动端 active 指示。切换后这些对象不存在，
  修它们等于给要拆的房子刷漆。
- **延后 · 并入 Mantine 实现验收（U4、U6、U7）**：约束本身值得保留，但要在**迁移后的
  Mantine 实现**上满足，不返修旧组件（决策 #41）。U7 的键盘可达与焦点可见是不变量 12
  的**能力**（不是观感），不能丢，只是换载体验收。
- **换时机（U12）**：`docs/design-system.md` 仍要写，但不再是「从旧代码总结」，
  而是「UX5b 高保真落成、Mantine 实现就位后的规范」。

### 批次 L · i18n 基础设施（文案目录与本地化边界）

**为什么 i18n 在这里做，而不是等要做第二种语言时**：抽取成本随代码量线性上升。
阶段 1 正好要逐个组件改一遍（U 批次），**顺手把文案抽进目录只多一次改动**；
若先做 UI 重构、之后再来抽 i18n，等于每个组件改两遍。

**但仍然不上重型 i18n 框架**：单语言时框架是纯负担。这里做的是**轻量查表 + 边界固化**，
让「上第二种语言 = 补一份目录 + 换 locale」成立。

| # | 现状 | 目标 | 验收 |
|---|---|---|---|
| L1 | 用户可见文案散落在组件里，无统一目录 | 建单一文案目录 `packages/contracts/src/i18n/`，初始只含 `zh-CN`；配一个轻量查表函数；**所有新增或被修改的用户可见文案必须先进目录**；配一条 lint（如 `no-restricted-syntax`）拦住新增的用户可见裸字符串；key 形状 `feature.page.element[.state]`；查表只支持 `{}` 插值；lint 同时扫 `.tsx` 的 JSX 文本与字符串字面量 | 目录存在且可查；**新增 / 被修改的文案零裸字符串**（存量清零留到阶段 4 · J1，见 L3）；查表函数有测试；lint 对新文件生效；key 命名符合上述形状 |
| L2 | 本地化边界没有钉死 | 展示格式化四个入口：`formatMoney(minor, locale, currency)`、`LocalDate`、`formatTime`、`formatPercent`，一律走 `Intl` 封装，页面不得自拼货币符号或日期格式；错误提示走错误码映射（后端不拼用户文案）；**CSV / 备份 / 同步格式的键名与枚举值不本地化**（它们是机器格式）；分类名、账户名、备注属于用户数据，**不翻译**；文案保持完整句子，不拼「前缀 + 名词 + 后缀」 | 页面层（`features/**`、`pages/**`）无 `toFixed`、无 `¥` 字面量、无 `dayjs().format`（grep 进验收）；错误文案无后端拼接；机器格式键名未被本地化 |
| L3 | 既有散落文案数量大，一次性抽取是永远排不上队的工程 | 已有的散落文案**在被触及时**（改到那个文件、那行时）顺手迁进目录，**不做一次性全量抽取**；本阶段触及的文件内不再有裸字符串 | 本阶段改动过的文件零裸字符串；目录覆盖率随改动递增而非停滞 |

> **触发条件仍在阶段 4**：真的要上第二种语言时，一次性接入语言切换 UI 与 `en-US` 目录。
> 那次工作量应当只有「补翻译 + 接 locale + 清理 L3 尚未触及的存量文案」——
> 前提是 L1/L2/L3 已完成：新增文案从 M2 起就进目录，存量只随触碰递减，
> 所以 J1 面对的是有限的一次性清理，而不是「抽上万字」。

| 15 | 装得起来 | 桌面可一键启动（Tauri），不要求用户开终端 | K8 |
| 16 | 数据能带走 | 导出格式长期稳定，能用标准工具读出全量账目 | 阶段 2 |

第 1–15 条是**「PC 端可用」的门槛**：装不上、启动不了、找不到数据的应用不算产品。
即使移动端与自动同步永远不做，MoneyBrain 依然是一个完整的个人财务工具。

## 本阶段不做

新业务功能（周期交易、标签、多账本、储蓄目标、票据、按范围备份、待付款清单）——
推迟到 [stage-4](stage-4-expansion.md)。同步协议、移动端、自动记账见入口的阶段总览。
