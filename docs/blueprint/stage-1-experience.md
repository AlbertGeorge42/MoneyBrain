# 阶段 1 · 体验、界面与桌面化（M2）

> **目标**：让 MoneyBrain 在 PC 上成为一个**能独立用一整年**的产品——
> 不是"能跑的 Demo"，是装得上、记得快、找得到、信得过、愿意每天打开的东西。
>
> 这一阶段**不增加新的业务功能**。周期交易、标签、多账本、储蓄目标、票据、
> 按范围备份、待付款清单全部推迟（见 [stage-4](stage-4-expansion.md)）。
>
> **为什么先收拾界面、后加功能**：
>
> - 界面层的债**越往后越贵**。现在有 66 个组件文件（其中 58 个 `.tsx`）、15 个 CSS 文件共 1787 行、320 处内联样式
>   （统计于 2026-10-28：`apps/web/src` 下按扩展名计数 + 统计 CSS 行数 + grep `style={{` 出现次数）。
>   拖到移动端做完再统一，等于两个端各改一遍。
> - 新功能可以按需再加；**加了之后还得在统一的地基上写**。地基不干净，加一个功能
>   就要在 320 处内联样式里再添一笔。
> - 界面债与业务债的代价不同——业务债让数字错，界面债让用户**不敢用**。
>   一个数字对但点不动、加载时闪空白、暗色模式看不清的账本，用户还是会弃用。

## 差距清单

### 批次 U · 界面重做（地基 → 重设计 → 落地）

这一批是一条流水线的三段，**按序执行**：

- **段一 · 地基（U0–U3）**：把实现方式改对——命名空间隔离、引用完整性、设备判定单入口。
  这些不产生视觉决策，但它们是重设计的前置：设备判定没有单入口，原型画出来就作废。
- **段二 · 重设计（UX1–UX5b）**：把设计本身重做一版——信息架构、记账交互、跨平台差异、
  视觉语言、线框级概念稿（UX5a）、组件库驱动的可运行高保真页面（UX5b）。
  **这一段不改应用代码**，产出设计决策与原型。
- **段三 · 落地（U4–U12）**：出口是「能干净地切到原型版本」——只保留机制与能力，
  旧页面的视觉收口一律取消或挂到 UX5b（三档见本段开头）。

段一与段三延后档的验收不是"好看"——好看没法自动化验收。拆成三类可验证的目标：

- **正确**：不存在失效变量、幽灵样式、死代码；同一语义只有一处实现。
- **可用**：键盘能到达每一个可操作元素，焦点始终可见；加载/空/错三态齐全且一致。
- **一致**：间距、字号、圆角、阴影、图标、动效全部来自 token，不存在硬编码与第二套来源。

这三类目标共同对应[蓝图入口 §4](../rewrite-blueprint.md) 不变量 12「界面不骗人」；
U7 的焦点可见性与 UX5b 的三态一致是其中可自动化验收的部分。

#### 段一 · 地基（U0–U3）

##### U1 · 变量引用完整性（U0 之后）

| # | 现状 | 目标 | 验收 |
|---|---|---|---|
| U1 | 4 处 CSS 引用了项目未定义、只因 AntD 同名才"恰好能显示"的变量：`picker.css` 的 `--mb-color-bg-container`（2 处）、`--mb-color-border-secondary`（1 处），`settings.css` 的 `--mb-color-text-quaternary`（1 处） | 改为项目自有等价 token（`--mb-color-bg-panel`、`--mb-color-border-subtle`；四级文字色补齐 `--mb-color-text-quaternary`） | 引用即定义；样式文件里不再出现任何"靠 AntD 同名兜底"的变量 |
| U1b | 缺少机制防止此类问题复发——CSS 引用未定义变量**不报错**，浏览器静默回退 | 建立 lint 守卫：脚本扫描全部 CSS/TSX 的 `var(--mb-*)` 引用，与「`variables.css` + `syncCssVars()` 导出清单」比对，未定义即失败；**同时检查死变量**（定义了却无人引用） | 引用未定义变量 → lint 失败；新增未使用变量 → lint 失败（防死变量堆积） |

> 守卫脚本应直接复用项目自己的变量清单（如把 `syncCssVars()` 拆出一个纯函数
> `buildCssVars()` 导出键名），而不是在脚本里另抄一份——否则守卫本身也会漂移。

##### U2–U3 · 设备判定单入口（降级为原则，不再作为条目）

原型双端是**两套独立结构**，不是响应式断点（见 [concept §8.1](ux/concept-design.md)）。
「三套断点并存」的冲突由结构本身消除；原计划的「16 处媒体查询裸数字 token 化 +
PostCSS 构建期解析」失去对象，**不执行**。

只保留一条机制原则（已写入 [dev-guide](../dev-guide.md) §2.2）：

> **设备判定只有一个入口**：JS 判定与 CSS 表现必须同源。新实现若仍有断点，
> 先立一个设备判定入口（单一常量 + 单一组件），不允许第二套判定
> （`Grid.useBreakpoint()` 与自建 hook 混用、CSS 裸数字各自为政）。

迁移前的现状（留作回溯）：自建 `useIsMobile`（860px）、AntD `Grid.useBreakpoint()`（768px）、
16 处 CSS 媒体查询裸数字（480/680/860/1100）——768–859px 区间 JS 判定与 CSS 表现结论相反。

#### 段二 · 重设计（UX1–UX5b，不改代码）

**为什么要有这一段**：界面是「加功能加出来的」，没有经过整体设计。
66 个组件文件、15 个 CSS 文件、320 处内联样式——每个都是需求驱动的补丁，
没有任何一页是「先设计、后实现」的。段一修完之后，界面**依然只是现在这版界面**：
信息架构、视觉语言、交互模式都还是历史遗留。

- **应用特性没有被设计容纳**。这个应用的核心是「金额 + 账户 + 时间」，
  但界面是按通用 CRUD 做的：列表页、详情页、表单页。
  记账是**高频、连续、有状态**的动作——交互模型应该像记账本，不像管理后台。
- **不同平台没有各自的设计**。桌面端是「浏览 + 偶尔录入」，移动端是「单手 + 频繁录入」——
  信息密度、导航方式、主要动作的位置应是**不同的设计**，不是同一套的响应式缩放。
- **没有原型，UI 改造就变成反复重写**。段三要动 66 个组件；设计方向没定，改完还得再改。

**这一段不改应用代码**，产出设计决策与原型（UX5a 线框；UX5b 的可运行页面是原型，
不进应用构建）；应用内实现由切换后的新实现承接。
因此验收是「文档覆盖度」与「原型可走查」，不是自动化测试。

| # | 现状 | 目标 | 验收 |
|---|---|---|---|
| UX5a | UX1–UX4 四份文档之间存在「各说各的」风险：没有一份把**模块布局 + 每类工作流在两端的完整走法**放在一起核对过，落地时才发现移动端行被挤爆、浮层互相压盖 | 产出**线框级概念设计**：按模块给布局骨架，按工作流给 PC / 移动端两套线框，并逐条说明交互逻辑差异、视觉表达差异与取舍；末尾单列待确认项；并在原型里落成**线框级可交互原型**（灰阶、占位块、无 CDN 依赖） | 覆盖记账 / 批量编辑 / 改一笔 / 账户·分类与现金流配置 / 报表与洞察 / 预算 / 导入导出 / 移动端单手流程九类工作流（W1–W9）；每类都有两端线框与差异说明；待确认项逐条可拍板且在原型中按推荐值实现并标注「待确认」；原型可在浏览器打开、两端可切换、主路径可点通 |

> UX1–UX4 已完成（产出物见下方表，完成记录见 [PROGRESS.md](PROGRESS.md)「状态」表，
> 明细以 git 历史为准）。UX5a / UX5b 承接它们的结论，不推翻。

> **UX5 拆成两段的原因**：一段做完「线框级概念 → 确认 → 高保真」比一段到底更稳。
> 直接做高保真时，布局与交互的取舍只能在像素里讨论，用户无法判断对错；
> 而且高保真稿一旦画完，改一次布局的成本远高于改一份线框。
> 两段之间设一道**确认关卡**：UX5a 未确认前不动原型界面。
> UX5a 的确认稿是 UX5b 的输入——UX5b 若发现 UX5a 有问题，回到 UX5a 改，不在高保真里偷偷改。

#### 段三 · 落地（U4–U12）

**这一批的出口是「能干净地切到原型版本」，不是「旧页面视觉收口」。** 前端后续整体
切换到原型设计版本（UX5a 线框 → UX5b 高保真），旧页面的观感在切换后不存在对象。
因此本段按三档处理：

- **取消（U5、U8、U9、U10、U11）**：验收对象是旧页面的观感——死 CSS、三态表达、
  卡片/图标/过渡统一、旧图表暗色调色板、移动端 active 指示。切换后这些对象不存在，
  修它们等于给要拆的房子刷漆。
- **延后 · 并入新实现验收（U4、U6、U7）**：约束本身值得保留，但要在**新实现**上满足，
  不返修旧组件。U7 的键盘可达与焦点可见是不变量 12 的**能力**（不是观感），不能丢，
  只是换载体验收。
- **换时机（U12）**：`docs/design-system.md` 仍要写，但不再是「从旧代码总结」，
  而是「UX5b 高保真落成后的实现规范」。

| # | 现状 | 目标 | 验收 |
|---|---|---|---|

**切换时 token 重规范（口径，不是执行清单）**：

- **保留机制**：单一定义源（结构 token 只在 `variables.css` 一处、颜色只从一个导出出口注入）、
  `--mb-` 前缀与 AntD `--ant-*` 隔离（决策 #32）、U1b 的引用完整性/死变量守卫（决策 #33）、
  token 之外无字面量（半透明走 `color-mix`）、对比度 ≥4.5:1 可脚本断言。
- **重写**：值、语义层与档位命名按 [design-tokens](ux/design-tokens.md) 在 UX5b 定稿。
  现有 58 个 token 里哪些删、哪些改值，属**切换时的执行清单**，不写进蓝图。
- **机制要改一处**：颜色的定义源从「AntD 算法派生」改为「手工声明的设计 token 表」——
  新色值（暖纸面 `#F5F2EA`、墨绿夜账本 `#0F1411`）不是 AntD 能派生的；不改，
  新值无处安放，旧观感会随算法回流到新界面。
- **三处缺口须在 UX5b 前补齐或明确复用**：① 交易类型色缺 `refund` / `adjustment`
  （领域有退款与调整交易，`design-tokens.md` 只定义了 income/expense/transfer）；
  ② 现金流语义缺 `cash` / `non-cash` / `investing`（W5 现金流配置在用）；
  ③ 交互状态色缺 `hover` / `selected` / `disabled`（现有 token 只有静态色，状态差异靠组件内散写）。

**顺序要求**（一条流水线，按段推进）：

1. **U0 → U1 → U1b**（U0、U1 已完成；U1b 立即做）。U0 是命名空间隔离，是 U1 的前置；
   U1b 是防复发机制——不建立它，改完这次的变量，下次又会长出来。
2. **设备判定单入口**随之落地——它是新实现的公共前提，但只是一条原则，
   不再作为条目排期（原媒体查询 token 化方案已取消）。
3. **UX1 → UX2 → UX3 → UX4 → UX5a → 确认 → UX5b**（段二）：先定信息架构，再定核心交互，
   再定平台差异，再定视觉语言，然后出**线框级概念稿**（UX5a），
   **经确认后**再用组件库产出可运行的高保真页面（UX5b，决策 #40）。顺序反了会返工；
   并行边界（UX3 的规范可与 UX4 并行，原型的视觉层必须等 UX4 token 定稿）见段二。
   **确认关卡不可跳过**：UX5a 未确认前不动原型界面——概念阶段就重做界面，
   等于把没拍板的取舍直接固化进高保真，改一次的成本是改线框的数倍。
4. **UX5b 之后 → 切换新界面**：段三只做延后档——U4（无内联字面量）、U6（44px 触控）、
   U7（键盘可达与焦点）在新实现上验收；E1–E4 随新实现验证；E6 随时可做。
5. **U12** 在 UX5b 之后写——此时规范对着已落成的高保真，
   写出来的才是真的规范而不是愿望。

**与其它批次的关系**：

- U 批次**不替代** E 批次。E 是「功能缺失」（没有搜索、没有引导），U 是「界面不对」
  （有搜索但两处实现、有引导但不可聚焦）。E 的能力由 E 批次承接，
  **随新实现一并落地与验收**（见 E 批次表格，E6 除外）。
- U 批次**不产生**新数据模型，不影响同步契约；UX 段同样不产生新实体、不改口径。
- U6 的**真机验收**（44px 触控、安全区）与阶段 3 的 H5 一起做（那时才有真机）；
  U11（移动端 active 指示）已取消——原型已定，新实现自带。
- **阶段 3 的 H 批次依赖 UX3**：手机界面若另起一套设计，H 批次会变成一边写一边设计。
  UX3 先定移动端设计，H 批次照着实现。
- **K8 与界面无关**：K8 是「装得上」的壳，不改界面，可在本阶段任意时点做。

**批次出口**：U 批次**完成 = 前端能干净地切到原型版本**，具体四条：

1. **命名空间隔离**（U0，已完成）：AntD `--ant-*` 与项目 `--mb-*` 零重叠；
2. **引用完整性守卫**（U1、U1b）：引用即定义、无死变量，改完不复发；
3. **设备判定单入口**（原则）：JS 与 CSS 同源，双端独立结构下只有一个判定入口；
4. **token 骨架能接住新值**：单一定义源、前缀隔离、无字面量规则、对比度断言
   可直接装载 UX5b 的新色值与档位。

**不在出口内**：旧页面的视觉收口（已取消）与 token 的具体值 / 语义层（挂 UX5b）。

### 批次 E · 体验功能补齐（PC 侧，并入新实现验收）

**E 是「功能缺失」**——搜索、引导这些能力必须有人承接，所以 E 不并入批次 U。
前端整体切到原型版本后，E1–E4 的能力**随新实现一并落地并验收**（原型已覆盖这些能力），
不再作为「改造旧界面」的条目；E6 与界面无关。

| # | 现状 | 目标 | 验收 | 落地/验收时点 |
|---|---|---|---|---|
| E1 | 冷启动无引导 | 空数据给「建账户 → 记第一笔 → 看报表」清单 | 新库 3 步内看到非零净资产 | 并入新实现（UX5b 后按高保真验收） |
| E2 | 手续费/优惠券常驻表单 | 折叠进「更多」，记住上次账户/分类 | 常规记账 3 步内完成 | 并入新实现（UX5b 后按高保真验收） |
| E3 | 交易列表无关键字搜索、无批量操作 | 关键字搜索 + 批量改分类/删除 | 搜索结果条数与条件一致；批量操作有确认 | 并入新实现（UX5b 后按高保真验收） |
| E4 | 设置页承载全部配置，报表页内嵌配置弹窗 | 设置按账户/分类/投资/数据/外观分组，报表只留跳转链接 | 同类配置只有一个权威入口 | 并入新实现（UX5b 后按高保真验收） |

### 批次 L · i18n 基础设施（文案目录与本地化边界）

**为什么 i18n 在这里做，而不是等要做第二种语言时**：抽取成本随代码量线性上升。
阶段 1 正好要逐个组件改一遍（U 批次），**顺手把文案抽进目录只多一次改动**；
若先做 UI 重构、之后再来抽 i18n，等于每个组件改两遍。

**但仍然不上重型 i18n 框架**：单语言时框架是纯负担。这里做的是**轻量查表 + 边界固化**，
让「上第二种语言 = 补一份目录 + 换 locale」成立。

| # | 现状 | 目标 | 验收 |
|---|---|---|---|
| L1 | 用户可见文案散落在组件里，无统一目录 | 建单一文案目录 `packages/contracts/src/i18n/`，初始只含 `zh-CN`；配一个轻量查表函数；**所有新增或被修改的用户可见文案必须先进目录**；配一条 lint（如 `no-restricted-syntax`）拦住新增的用户可见裸字符串 | 目录存在且可查；**新增 / 被修改的文案零裸字符串**（存量清零留到阶段 4 · J1，见 L3）；查表函数有测试；lint 对新文件生效 |
| L2 | 本地化边界没有钉死 | 金额格式化只有 `formatMoney(minor, locale, currency)` 一个入口（组件里禁止 `¥`、`toFixed(2)`）；日期展示只有 `LocalDate` + locale（存储永远是 `YYYY-MM-DD`）；错误提示走错误码映射（后端不拼用户文案）；**CSV / 备份 / 同步格式的键名与枚举值不本地化**（它们是机器格式）；分类名、账户名、备注属于用户数据，**不翻译**；文案保持完整句子，不拼「前缀 + 名词 + 后缀」 | 全树无 `toFixed(2)` 拼金额、无 `¥` 字面量；错误文案无后端拼接；机器格式键名未被本地化 |
| L3 | 既有散落文案数量大，一次性抽取是永远排不上队的工程 | 已有的散落文案**在被触及时**（改到那个文件、那行时）顺手迁进目录，**不做一次性全量抽取**；本阶段触及的文件内不再有裸字符串 | 本阶段改动过的文件零裸字符串；目录覆盖率随改动递增而非停滞 |

> **触发条件仍在阶段 4**：真的要上第二种语言时，一次性接入语言切换 UI 与 `en-US` 目录。
> 那次工作量应当只有「补翻译 + 接 locale + 清理 L3 尚未触及的存量文案」——
> 前提是 L1/L2/L3 已完成：新增文案从 M2 起就进目录，存量只随触碰递减，
> 所以 J1 面对的是有限的一次性清理，而不是「抽上万字」。

## 「PC 端可用」的验收清单

本阶段的出口条件 = 阶段 0 + 阶段 1 累计。用户能独立用 MoneyBrain PC 版完成一整年的记账，
且中途不需要开发者介入：

| # | 能力 | 验收 | 来源 |
|---|---|---|---|
| 1 | 冷启动可用 | 新库有引导，3 步内看到非零净资产 | E1 |
| 2 | 日常记账够快 | 常规记账 3 步内完成 | E2 |
| 3 | 查得动 | 关键字搜索 + 批量操作 | E3 |
| 4 | 不怕误删 | 单条删除可撤销；批量/覆盖/清空有明确确认与数量 | B2、E3 |
| 5 | 数据可找回 | 覆盖导入有回滚点；备份能恢复（`db:drill` 通过） | B1、B3 |
| 6 | 报表可信 | 四张报表数字自洽，对账条差额为 0 | C1–C3 |
| 7 | 配置有入口 | 同类配置只有一个权威入口 | E4 |
| 8 | 大数据不卡 | 桑基图取 Top N | E6 |
| 9 | 界面可信 | 引用即定义、无死变量；设备判定单入口 | U1、U1b、原则 |
| 10 | 键盘可用 | 纯键盘走通主流程，焦点始终可见（新实现验收） | U7 |
| 11 | 三态一致 | 加载/空/错三态齐全且一致（原型已定，新实现自带） | UX5b |
| 12 | 视觉一致 | 按高保真稿实现；暗色对比度达标 | UX5b |

| 14 | 文案可查表 | 新增/修改文案零裸字符串（存量清零在 J1）；金额与日期只有一个格式化入口 | L1–L3 |

即使移动端与自动同步永远不做，MoneyBrain 依然是一个完整的个人财务工具。
